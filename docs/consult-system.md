# 咨询系统架构

## 总览

```text
来访者上下文 ──┐
               ├─> 决策引擎 ─> 根到叶路径 ─> 成文模板 + AI ─> 咨询稿
咨询树（唯一事实源）┘                              │
                                                   └─> 成交/失败/好评/退出反馈
                                                         └─> 更新节点奖励与惩罚
```

系统分为四层：

1. **决策层**：每个节点是一句咨询师要说的话。系统根据学生特点、历史学生回答、节点奖励和惩罚，选择下一句要说的话。
2. **框架层**：模板规定段落顺序、段落意图、语气和长度，不参与选路。
3. **索引层**：把每条“根 → 叶”路径预先编成稳定索引，供页面和后续 Agent 检索，不必重新遍历整棵树。
4. **成文层**：把路径、上下文、路径索引和模板交给 AI，先规划章节，再逐章成文。

## 路径规模与长稿

咨询树负责“咨询逻辑骨架”，不负责直接存放 2—4 万字正文。默认树只保留基础示例节点；实际咨询路线以管理员导入的成交对话为准。节点只保存咨询师要说的话，不把几千字塞进单个节点，否则节点选择、历史回答和索引都会失去可维护性。为了避免大树上打开页面卡顿，咨询路径页默认全部收起，只显示根节点，用户需要时再逐层展开或使用“全部展开”。

长稿使用以下管线：

```text
目标篇幅（2 / 3 / 4 万字）
  → AI 规划 6—12 章写作大纲
  → 逐章生成（每章约 2500—4500 字）
  → 保存每章状态与正文
  → 全部成功后拼接完整咨询稿
```

生成过程是后台任务。页面轮询 `GET /api/admin/consult/runs/:id` 查看进度；章节状态为 `pending`、`running`、`ready`、`failed`。任何一章失败都会明确显示失败章节和原因，保留已完成章节，并可调用 `POST /api/admin/consult/runs/:id/retry` 从失败处重试。系统不使用兜底模板，也不把失败稿伪装成成功结果。

## 数据模型

- `ConsultNode`：`id`、`text`、`type`、`children`、`weight`、`reward`、`penalty`、`selectedCount`、`metadata`。`text` 是咨询师要说的话，`metadata.answerHistory` 保存学生在这句话之后的历史回答。
- `ConsultTree`：单根多叉树，保存在 `settings.consult_tree`。
- `ConsultTemplate`：段落数组、整体语气、成文目标，保存在 `settings.consult_templates`。
- `consult_runs`：每次生成的上下文、路径、候选分数、成文结果和反馈，便于回溯。
- `consult_run_sections`：长稿的章节规划、正文、目标字数和逐章状态。

默认树和默认模板是只读基线。自定义模板从基线复制后编辑，不会改动默认模板。编辑已有自定义模板并保存时，系统会先询问是“保存为新副本”还是“覆盖当前”，避免误改唯一版本。

## 深树组织

一问一答会自然形成很长的链。系统按“深链”而不是“固定四层”组织：

- 后端支持最多 2000 层、10000 个节点、单节点 200 个子节点，遍历和校验都改为迭代实现，不再依赖递归深度。
- 决策路径最多 2000 步；超长路径写入 AI 提示时会保留开头、结尾并抽取中间段，避免提示词失控。
- 列表视图限制视觉缩进宽度，同时显示“第 N 轮”，并提供搜索定位、上一句、下一句和“只看当前路径”。
- 思维导图视图用可拖动、可缩放的画布展示可见节点。节点点击查看，点 `+ / −` 展开或收起；长链横向延伸，不再被缩进挤出屏幕。
- 导入支持整段多轮对话：一行一句，咨询师写“咨询师：”，学生写“学生：”，空行分隔不同对话；也兼容用 `→` 串联的一段对话。

## 决策公式

```text
score(node) = weight
            + alpha * reward
            - beta * penalty
            + gamma * contextMatch
```

- 默认参数：`alpha=1`、`beta=0.5`、`gamma=2`、`epsilon=0.05`。
- 每次非探索选择取 `argmax(score)`。
- `epsilon` 提供探索率，避免高分路径长期垄断。
- `contextMatch` 会综合本次关键词、问卷情况和该节点积累的历史学生回答。
- 每次生成的候选分数和最终路径都写入运行记录，可在工作台展开查看。

## 反馈回流

| 结果 | 更新 |
| --- | --- |
| 成交 | 路径上全部节点 `reward += 1` |
| 未成交 | 路径上全部节点 `penalty += 1` |
| 用户好评 | 最后一个节点 `reward += 0.5` |
| 中途退出 | 所选断点节点 `penalty += 0.5` |

历史过重时，可在决策参数中把整棵树的奖励和惩罚分衰减到 90%。

## 路径索引

每条完整叶路径生成一个稳定索引 ID：

```text
id = "pth_" + FNV-1a(根到叶节点 ID 序列)
```

索引字段全部由树与历史运行记录计算，不提供人工填写成交率或学生特点的入口：

- `id`：稳定路径索引 ID，可用于 Agent 日志、运行记录和人工回查。
- `nodeIds` / `pathText`：完整路径及每一步咨询师话术。
- `features`：路径特点。来自路径节点的标签，并统计这些标签在历史学生中命中的次数和占比。
- `studentFeatures`：学生特点。来自历史运行上下文中的关键词和问卷文本匹配，统计该特点沿此路径出现的次数与占比。
- `runCount`：经过这条精确路径的历史生成次数。
- `won` / `lost` / `abandoned` / `liked`：成交、未成交、中途退出、好评数量。
- `decidedCount = won + lost + abandoned`：只统计有明确成交判断的样本；好评不混入成交率。
- `conversionRate = won / decidedCount`：原始成交率，无样本时为 `null`。
- `conversionLowerBound`：95% Wilson 置信下界，避免 1 次成交造成“100% 成交率”的误判。
- `lastUsedAt`：最近一次经过该路径的时间。

历史运行必须与完整 `nodeIds` 精确一致才会计入该索引。修改路径后，旧路径不会错误地并入新路径的成交率。

### Agent 检索接口

```http
GET /api/admin/consult/indexes
POST /api/admin/consult/indexes/query
```

查询示例：

```json
{
  "context": {
    "tags": ["求职", "城市"],
    "profile": "大三，汉语言专业，想留在杭州做运营，但还没有实习"
  },
  "limit": 10
}
```

排序顺序：

1. 学生特点匹配覆盖率；
2. 路径特点覆盖率；
3. 成交率 Wilson 置信下界；
4. 已决策样本量；
5. 稳定索引 ID（保证结果可复现）。

Agent 先取 Top N 路径，再结合实际对话在候选路径附近做局部决策，不需要遍历整棵树。索引只缩小候选空间和提供历史效果依据，不能替代逐句回应。

## 模板变量

段落名称、段落指令和整体语气支持：

- `{{path}}`：完整路径文本。
- `{{path_section_2}}` 或 `{{path_2}}`：第 2 个路径节点。
- `{{context}}`：来访者补充信息、标签、情况和对话记录。
- `{{user_name}}`：称呼，未填写时显示“来访者”。

## 端到端示例

一条优秀成交对话：

```text
咨询师：还不确定毕业以后做什么也没关系。你现在更想继续读书，还是先工作看看？ → 学生：我想先工作，但不知道做什么 → 咨询师：想直接工作的话，我们先从你能接受的岗位和城市开始缩小范围。
```

1. 在“咨询路径 → 导入成交对话”粘贴对话。咨询师的话合并成节点，学生的回答挂到前一句咨询师节点下。
2. 工作台填写关键词和用户情况后，决策引擎结合节点奖励、关键词匹配和历史学生回答选出下一句。
3. AI 先按目标篇幅规划章节，再逐章生成；每章都携带完整大纲、已完成章节摘要、决策路径、问卷情况和高相关路径索引。
4. 点击任意节点可以查看这句话之后积累的历史回答；记录“成交”后，路径上全部节点奖励加 1，下次选择时更容易被选中。

## 管理入口

- `/admin/consult`：咨询工作台，生成、回看、记录反馈。
- `/admin/consult/tree`：咨询师话术路径、历史回答、成交对话导入、参数与衰减。
- `/admin/consult/indexes`：完整路径索引、学生特点查询、成交率与置信下界。
- `/admin/consult/templates`：成文模板列表和段落编辑器。

接口统一位于 `/api/admin/consult`，沿用现有管理员登录态。
