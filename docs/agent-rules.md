# 后续 Agent 工作规则

这些规则来自用户明确要求，优先级高于一般工程偏好。

## 产品与交互

- 使用者不是技术从业者。界面必须简单、直接、少解释、好点击。
- 不要为了“信息完整”堆标题、小标题、说明段和重复按钮。
- 重要动作要显眼且居中；常用操作不要藏在拥挤角落。
- 列表、画布、工具栏要紧凑，并允许拖动调整或隐藏，避免挤占主要内容。
- 日期选择优先使用可涂色、可连续选择、可全选的交互，不用原始日期输入框堆叠。
- 日期很多时也要保持布局稳定，不能把表格或页面撑坏。

## AI 与数据

- 不要用低质量兜底模板伪装 AI 生成成功。
- AI 失败必须显示真实原因，并允许重试；已完成部分要保留。
- 报告和咨询稿中的指标必须由数据客观计算，不能提供人工填写成交率、学生特点等“主观指标”入口。
- 路径索引需要稳定 ID、可回溯路径、历史样本和置信区间。
- 树节点是“咨询师要说的话”，不要把整篇长文塞进单个节点。
- 当前可信来源是用户导入的成交咨询稿（`zxg/` 下的七月、9.18 等）；不得再编写或补回系统自拟的开场、默认路线或示例话术。
- 阶段标题下面的多段话术是同级兄弟节点，不要擅自串成单链。
- 导入成交咨询稿应丰富现有树，但绝不能清空、重置或覆盖用户已导入的路线。
- 默认模板和默认设置只读；自定义模板只能复制后修改。
- 编辑已有模板保存前，必须提醒“保存为新副本 / 覆盖当前 / 取消”。

## 咨询树

- 默认收起整棵树，仅在用户操作时逐层展开，避免大树导致页面卡顿。
- 支持深树，不要假设只有四层。
- 列表视图避免用无上限缩进；思维导图要支持拖动、缩放、全屏和工具栏隐藏。
- 双击节点打开/关闭编辑区；禁止浏览器右键菜单和右键拖动平移。
- 不要让画布默认自动展开大量节点。

## 认证与安全

- 生产环境必须要求账号密码和 `AUTH_SECRET`，绝不能开放免密登录。
- 本地免密只能绑定显式 `NODE_ENV=development`，不能靠 `NODE_ENV` 缺失来判断本地环境。
- 不要修改 `requireAdmin()` 绕过令牌和数据库会话校验。
- 不要把真实管理员密码、API Key 或联系方式密钥写入代码或文档。

## 数据操作

- 修改或清理数据库前先备份；备份必须考虑 SQLite WAL。
- 不要直接重置 `consult_tree`、`consult_runs` 或用户导入的数据。
- 咨询森林保存在 `settings.consult_forest`；旧 `settings.consult_tree` 只作为迁移兼容，不应再写回。
- 表结构变更要兼容已有数据库，启动迁移必须可重复执行。
- 不要提交 `.env`、`data/`、`web/dist/`。

## 运行与验证

- 不要随意杀掉用户已经启动的 dev server；端口占用时先说明并征得同意。
- 后端改动后执行 `npm run typecheck`。
- 前端改动后执行 `npm run typecheck && npm run build`。
- 没有自动化测试时，至少完成类型检查、构建和关键页面手工走查。
- 服务器更新入口是 `bash update.sh`（脚本自己拉取、校验、构建、重启）；生产服务由 systemd / PM2 / Docker 重启，不要用开发脚本替代。

## 文档维护

- 改动涉及架构、认证、数据模型、部署流程或已确认需求时，同步更新 `docs/`。
- 用户的新要求如果推翻旧实现，要在 `development-history.md` 记录“何时、改了什么、为什么”，避免后续 Agent 又把旧逻辑加回来。
