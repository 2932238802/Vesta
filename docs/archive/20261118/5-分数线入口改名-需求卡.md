# 分数线入口改名：把“分数线”显示名改为“升学分数线查询”

## CR-003 分数线入口改名（分数线 › 升学分数线查询）

- **类型**：文案变更
- **问题与价值**：后台导航里的“分数线”三个字只说明了数据是什么，没有说明这个入口是给人用的查询工具。改成“升学分数线查询”后，运营和咨询师一眼能看出这是“查升学分数线”的地方，减少点进去才发现不对的试探。
- **目标用户与场景**：运营 / 咨询师；在后台侧栏找“升学分数线”入口时，按名称即可定位。
- **成功指标**：
  - 后台任意页面侧栏中，该入口显示为“升学分数线查询”，不再显示单独的“分数线”。
  - 页面标题、浏览器标签标题与入口名称一致。
  - 路由、接口、数据、权限完全不变（`/admin/score-lines` 仍可直达）。
- **现状盘点（只读调研，2026-11-18）**：

| # | 位置 | 当前文案 | 是否用户可见 |
| --- | --- | --- | --- |
| 1 | `web/src/views/admin/AdminLayout.vue:95` | 分组标题「分数线」 | 是（侧栏一级分组） |
| 2 | `web/src/views/admin/AdminLayout.vue:109` | 入口链接「分数线」 | 是（侧栏二级入口） |
| 3 | `web/src/router.ts:91` | `分数线 · 管理后台` | 是（浏览器标签） |
| 4 | `web/src/views/admin/ScoreLines.vue:5` | 页面标题「分数线」 | 是（页面大标题） |

- 其余“分数线”多为正文说明（如“有多条同类分数线，系统不会自动混在一起画”），描述的是数据本身，**不在本次范围内**。
- 补充（G3 评审 P3 修正）：复核弹窗的页签“分数线”（`score-lines/ReviewView.vue`）与折线图 `aria-label` 中的“分数线趋势”（`score-lines/ChartCard.vue`）也是用户可见控件，但**明确不在本次改名范围**；本次只改“栏目入口名”，不改页面内的数据维度名称。
- 无测试断言依赖这四处文案；`check:docs` / `check:size` / `check:version` 不受影响。

- **范围（推荐方案 A）**：
  - 侧栏入口链接（#2）改为「升学分数线查询」。
  - 页面标题（#4）改为「升学分数线查询」，`eyebrow`（“内部查询”）与副标题保持不变。
  - 浏览器标签标题（#3）改为「升学分数线查询 · 管理后台」。
  - 一级分组标题（#1）保留「分数线」作为分组名；分组内只有一个入口，两个层级都写全名会重复。
- **非目标**：
  - 不改路由路径、接口、数据表、权限。
  - 不改页面副标题、`eyebrow`、正文里的“分数线”表述。
  - 不改其他栏目名称，不做导航结构重排。
- **NFR**：

| 项 | 判定 | 目标 / 理由 |
| --- | --- | --- |
| 性能 | 不适用 | 纯文案。 |
| 安全 | 不适用 | 无接口与鉴权变更。 |
| 隐私与数据保留 | 不适用 | 无数据处理。 |
| 兼容性 | 适用 | 纯前端显示文案；旧链接、接口、书签不受影响。 |
| 可观测性 | 不适用 | 无新增日志。 |
| 成本 | 不适用 | 无新增依赖或基础设施。 |

- **约束与依赖**：
  - 遵循文档优先：先更新本文与开发文档，再改代码。
  - 不新增文件；改动集中在 3 个既有文件。
- **风险与未知**：
  - 低。若用户或运营的肌肉记忆依赖“分数线”三个字，短期会有一次不适应；分组标题保留「分数线」可缓解。
  - 待确认：是否需要同时改一级分组标题（见选项 B/C）。

- **选项**：
  - A（推荐）：入口 + 页面标题 + 浏览器标题改为「升学分数线查询」，分组标题保留「分数线」。
  - B：只改侧栏入口链接，页面标题与浏览器标题保持「分数线」。改动最小，但入口与页面标题不一致。
  - C：分组标题、入口、页面标题、浏览器标题全部改为「升学分数线查询」。最彻底，但侧栏会出现两级同名。
  - D：不做。

- **推荐**：A。理由：用户指向的是“入口的名字”，但入口点进去后标题仍写“分数线”会显得没改完；分组标题保留可以维持侧栏的层级辨识度。
- **关联需求/任务**：R-003；任务在开发文档中编号 T-013 起。
- **状态**：已确认（G0，2026-11-18 用户选择方案 A；G1 已确认）。开发文档见 `6-分数线入口改名-开发文档.md`。
