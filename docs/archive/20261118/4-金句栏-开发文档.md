## 1. 需求 R-002 金句栏（P1，v1）

- **来源**：CR-002（2026-11-18，G0 用户选择“做，完整范围”）。
- **背景**：咨询师需要在通话中按主题快速找到两三句金句。收藏栏按“收藏类型”组织，金句只是其中一类，没有主题维度；140 条金句混在卡片流里无法快速定位。本次把金句拆成独立页面和独立数据表，按主题分类浏览。
- **描述**：系统应在后台“咨询”导航中提供“金句栏”，位于“咨询树”与“收藏栏”之间。页面左侧为分类栏，右侧为金句列表；支持按分类筛选、关键字搜索、单条复制、置顶、新增、编辑、删除；支持分类新增、改名、上下调序，分类下仍有金句时不可删除。首批 11 类 140 条金句在服务启动时写入一次，之后全部人工维护。
- **成功指标**：
  - 进入页面到复制一条金句 ≤ 3 次操作（选分类 → 找条目 → 复制）。
  - 140 条金句首屏一次加载；切换分类与搜索不触发额外请求。
  - 首次部署后，分类数 11、金句数 140，且重启不会重复写入。
  - 可观察场景：打开“自卑、内耗与在意评价”看到 14 条；点“随机三条”得到 3 条；一次复制全部成功。
- **验收标准**：

  - `AC-002-1` 打开 `/admin/consult/quotes`：侧栏“咨询”组顺序为 写咨询稿 → 咨询树 → 金句栏 → 收藏栏；金句栏高亮；页面标题“金句栏”；收藏栏入口仍存在且可进入。
  - `AC-002-2` 分类栏显示“全部金句”“置顶”和 11 个分类；每个分类右侧条数等于该分类金句数；点击分类后列表只显示该类金句，分类项高亮；切回“全部金句”恢复 140 条。
  - `AC-002-3` 在搜索框输入金句正文中的词、编号（如 `124c`）或分类名：列表即时过滤为匹配项，并显示结果条数；清空搜索恢复当前分类全部条目；无结果时显示空状态，不报错。
  - `AC-002-4` 点击任意金句卡片“复制”：剪贴板内容与该条正文完全一致（不含编号、分类、出处）；按钮短暂显示“已复制”；连续复制不同条目均正确。
  - `AC-002-5` 点击“☆”置顶：该条变为“★”，并移动到列表顶部；“置顶”分类只显示置顶条目且计数正确；再次点击取消置顶，条目回到原顺序。
  - `AC-002-6` 新增金句：选择分类、填写正文后保存，新条目出现在对应分类末尾，总数 +1，页面计数同步；正文为空时保存被拒绝并提示。编辑金句：修改正文、分类、出处、置顶后保存，列表立即反映。删除金句：二次确认后从列表与数据库移除，总数 -1。
  - `AC-002-7` 分类管理：新增分类后出现在分类栏末尾；改名后分类栏与卡片上的分类名同步变化；上移/下移后顺序立即变化且刷新页面后保持；分类下仍有金句时“删除”不可用（或返回 409 并提示），空分类可删除；分类名为空或重复时被拒绝。
  - `AC-002-8` 首批种子：全新数据库启动后 `consult_quote_categories` 有 11 行、`consult_quotes` 有 140 行，分类名与条数与原稿一致；`settings.consult_quotes_seed_applied = 1`；再次启动不新增行；手动删除一条种子金句后重启，不会自动补回。
  - `AC-002-9` 收藏栏不受影响：`/admin/consult/collections` 页面、接口与 `consult_collections` 数据保持原样；金句栏的金句不出现在收藏栏，收藏栏的金句也不会进入金句栏。
  - `AC-002-10` 异常与鉴权：接口在未登录时返回 401；分类不存在、分类 ID 非法、正文超长时返回 400 并给出可读错误；请求失败时页面显示错误与重试入口，不白屏。

## 3. 关键设计

### 3.1 信息架构

- 路由：`/admin/consult/quotes`，名称 `admin-consult-quotes`，页面标题 `金句栏 · 管理后台`。
- 导航顺序：写咨询稿 → 咨询树 → **金句栏** → 收藏栏（见 `AdminLayout.vue`）。
- 页面布局：左分类栏（全部 / 置顶 / 各分类 / 管理分类）+ 右侧搜索与金句列表；窄屏（≤1000px）分类栏收为横向标签条。
- 金句卡片：编号徽章（种子条目才有）、分类名、正文、复制按钮；悬停显示置顶、编辑、删除；长正文折叠 4 行，可展开。
- 顶部动作：随机三条、新增金句。

### 3.2 数据模型

```sql
CREATE TABLE IF NOT EXISTS consult_quote_categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_consult_quote_categories_name
  ON consult_quote_categories(name);
CREATE INDEX IF NOT EXISTS idx_consult_quote_categories_order
  ON consult_quote_categories(sort_order, id);

CREATE TABLE IF NOT EXISTS consult_quotes (
  id TEXT PRIMARY KEY,
  category_id TEXT NOT NULL,
  no TEXT NOT NULL DEFAULT '',
  text TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT '',
  pinned INTEGER NOT NULL DEFAULT 0,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_consult_quotes_category
  ON consult_quotes(category_id, pinned DESC, sort_order, created_at);
```

- `no` 仅用于种子条目展示原稿编号；新增金句留空。
- `sort_order` 只在同一分类内保证稳定顺序；本次不提供手工排序。
- 不启用数据库外键；分类存在性、删除限制在接口层校验。

### 3.3 接口契约

统一前缀 `/api/admin/consult`，沿用管理员登录态。

| 方法 | 路径 | 作用 | 成功响应 |
| --- | --- | --- | --- |
| `GET` | `/quotes` | 读取全部分类与金句 | `{ categories, quotes }` |
| `POST` | `/quotes` | 新增金句 | `{ item }` |
| `PATCH` | `/quotes/:id` | 编辑正文 / 分类 / 出处 / 置顶 | `{ item }` |
| `DELETE` | `/quotes/:id` | 删除金句 | `{ ok: true }` |
| `POST` | `/quote-categories` | 新增分类 | `{ category }` |
| `PATCH` | `/quote-categories/:id` | 分类改名 | `{ category }` |
| `PUT` | `/quote-categories/order` | 全量重排 | `{ categories }` |
| `DELETE` | `/quote-categories/:id` | 删除空分类 | `{ ok: true }` |

响应对象：

```ts
interface ConsultQuoteCategory { id: string; name: string; sortOrder: number; count: number }
interface ConsultQuote {
  id: string; categoryId: string; no: string; text: string;
  source: string; pinned: boolean; sortOrder: number;
  createdAt: string; updatedAt: string
}
```

校验与错误：

- 正文 `trim` 后 1–10000 字，否则 `400`；出处 ≤200 字。
- 分类名 `trim` 后 1–30 字；重名 `409`；改名同样校验。
- `categoryId` 必须存在，否则 `400`。
- `PUT /quote-categories/order` 的 `ids` 必须恰好是现有全部分类的一个排列，否则 `400`；单事务写入。
- 删除非空分类 `409`，响应含该分类金句数。
- 未登录 `401`；不存在 `404`。
- 日志只记录 `id` / `categoryId`，不记录正文。

### 3.4 种子与启动迁移

- 数据文件：`server/src/data/consult-quotes-seed.json`，结构：

  ```json
  {
    "version": 1,
    "categories": [{ "id": "qc_01", "name": "拖延、行动与执行力", "sortOrder": 1 }],
    "quotes": [{ "id": "q_001", "categoryId": "qc_01", "no": "15", "text": "…" }]
  }
  ```

- 来源：`咨询金句-分类版(1).docx`，11 类 140 条；分类顺序按原稿，条内顺序按原稿编号。ID 使用稳定值，便于 `INSERT OR IGNORE` 幂等重试。
- `migrations.ts` 新增 `seedConsultQuotes()`，在 `runMigrations()` 末尾调用：

  ```ts
  if (getSetting('consult_quotes_seed_applied') === '1') return
  // BEGIN → 逐条 INSERT OR IGNORE 分类与金句 → COMMIT
  // 成功后 setSetting('consult_quotes_seed_applied', '1')
  // 失败 ROLLBACK 并 log.error，不写标记，下次启动重试
  ```

- 不新增一次性脚本，不改 `update.sh`；`update.sh` 重启服务即触发迁移。`--mode=none` 不重启时脚本本身会失败退出，不会出现“以为更新了”的假成功。
- 若需要在生产重新导入种子：人工删除 `settings` 中的 `consult_quotes_seed_applied` 并重启；不提供界面入口（见 A-005）。**重导只补回缺失的条目，不会刷新已改名或已编辑的既有条目**；要修正已有条目需手工处理或另立需求。

### 3.5 前端结构

为满足“新文件 ≤400 行”：

- `web/src/views/admin/ConsultQuotes.vue`：页面骨架、数据加载、搜索与筛选状态。
- `web/src/views/admin/quotes/QuoteCard.vue`：单条展示、复制、置顶、编辑/删除入口、展开。
- `web/src/views/admin/quotes/QuoteFormModal.vue`：新增/编辑表单。
- `web/src/views/admin/quotes/QuoteCategoryModal.vue`：分类管理（新增、改名、上下移、删除限制）。
- `web/src/views/admin/quotes/useQuoteShelf.ts`：接口调用、本地状态、排序与计数派生。
- 共享类型 `shared/src/consult-quote.ts`；请求方法加入 `web/src/api/consult.ts`，类型加入 `web/src/api/types.ts`。

交互口径：

- 列表排序：置顶优先；其次 `sortOrder`；最后 `createdAt`。
- 复制使用 `navigator.clipboard`，失败时回退 `textarea + execCommand`；复制内容只含正文。
- 随机三条从当前筛选结果中抽取；不足 3 条时返回全部；弹窗支持“换一批”“复制这三条”。
- 删除金句、删除分类均二次确认；分类非空时删除入口置灰并提示“分类下还有 N 条金句”。
- 空状态：无金句、分类为空、搜索无结果分别给出不同文案。

### 3.6 与收藏栏的边界

- 不改 `consult_collections` 表、接口与页面；收藏栏的“金句”类型继续存在，但与金句栏数据互不相通。
- 收藏栏后续下线另立需求；本次不预留迁移逻辑。
