# 学员名单分组简化：移除日期分组、默认分组并入“全部”

> 维护者：Doc Agent / Dev Agent ｜ 日期：2026-11-18 ｜ 状态：已实施（产品版本 v1.90，待提交）
> 来源：`docs/archive/20261118/1-学员名单分组简化-需求卡.md`（CR-001）

## 1. 需求 R-001 学员名单分组简化（P0，v1）

- **来源**：CR-001（2026-11-18 用户确认，G0 选择“做，完整范围”）
- **背景**：当前名单同时有期次（日期）栏、分组栏、状态栏。咨询师认为分组仍不好用：默认分组与“全部”语义重叠，日期栏增加筛选负担。用户确认把默认分组职能交给“全部”，并删除日期分组。
- **描述**：系统应在学员名单页提供“全部 + 用户自建分组”的单一分组维度，不再提供期次/日期筛选；新学员默认出现在“全部”；默认分组在界面隐藏但保留内部自动归组能力；归档学员可通过“全部”加回。
- **成功指标**：
  - 打开 `/admin/submissions` 时，页面顶部无期次/日期栏；分组栏无“分组”标签、无“默认分组”chip；“全部”默认选中。
  - 新建邀请后，学员出现在“全部”，不需要手工加入分组。
  - 现有用户分组、成员关系、归档数据数量不变。
  - 状态栏（含“全部”）行为不变。
- **验收标准**：
  - `AC-001-1` 打开名单页，数据加载完成后：顶部没有期次/日期栏；分组栏第一个是“全部”且选中；没有“分组”文字标签；没有“默认分组”chip；用户自建分组按原顺序显示。
  - `AC-001-2` 新建一条邀请并打开名单“全部”：该学员出现在“全部”列表；不出现在归档区；不需要手工加入分组。
  - `AC-001-3` 旧链接带 `week` / `group` / `dates` 参数打开名单：页面不按日期或旧分组参数过滤，不报错；`GET /api/admin/roster` 响应不再包含 `weeks` / `currentWeek`；名单请求与 `export.csv` 都不再携带 `week`，导出不再按周过滤。
  - `AC-001-4` 已有分组 A、B 及其成员：打开页面后 A、B 名称、计数、成员关系保持不变；切换 A/B 时列表结果与改动前一致。
  - `AC-001-5` 默认分组 `is_default=1`：分组栏与管理弹窗都不显示默认分组；后端仍保留该组和成员关系，用于新邀请自动归组与归档判定。
  - `AC-001-6` 归档区存在学员：点“加入分组…”时出现“全部”与用户自建分组；选“全部”后学员回到“全部”，不再出现在归档区。
  - `AC-001-7` 状态栏：仍保留“全部 / 未填写 / 已提交未领取 / 待联系 / 已联系 / 已约时间 / 已完成”；切换任一项的过滤结果与改动前一致。
  - `AC-001-8` 创建分组时输入“全部”或“默认分组”：接口返回 `400`（或 `409`）并提示该名称为保留名；空名称仍 `400`；分组上限 50 个不变。
  - `AC-001-9` 只有默认分组、没有用户分组：分组栏只显示“全部”；“新建分组”仍可用；管理弹窗显示空状态，不报错。
  - `AC-001-10` 删除最后一个用户分组：组内成员若仍在默认分组，不进入归档；只有不在任何有效分组的成员才进入归档；学员与答卷不被删除。
- **NFR 影响**：

| 性能 | 适用 | 名单只按 `q` / `category` / `groupId` 过滤；不再计算期次；首屏请求次数不增加。 |

## 3. 关键设计

- **默认组不删除**：`GET /api/admin/roster` 继续返回 `groups`，默认组仍带 `default: true`；前端派生 `visibleGroups = groups.filter(g => !g.default)` 供分组栏与管理弹窗使用。原始 `groups` 保留在状态里，用于取默认组 id（归档加回）和分组切换，不能把默认组从 `state.groups` 直接删掉。
- **“全部”= `groupId` 空串**：不新增虚拟分组记录；新学员仍自动写入隐藏默认组，因此会出现在 `roster` 与“全部”列表里。
- **归档加回**：选“全部”时，用 `groups.find(g => g.default).id` 调 `POST /roster/groups/:groupId/members`；不新增“全部”假 id。
- **旧 URL**：`week` / `group` / `dates` 一律忽略；不因未知参数报错。`week` 不再传给 `GET /roster` 或 `export.csv`。
- **保留组名**：`POST /roster/groups` 拒绝创建名为“全部”或“默认分组”的组，避免与虚拟“全部”/隐藏默认组重名；已有重名数据按 A-001 处理。
- **不改数据**：无表结构变更、无迁移；`roster_groups` / `roster_group_members` / 默认组 / 归档数据保持原样。

## 8. 评审返工（2026-11-18，产品版本 v1.90）

- **评审 P1**：旧链接 `?groupId=<默认组 id>` 会被后端接受为合法筛选，前端因默认组被 `visibleGroups` 隐藏而没有任何 chip 选中；工具栏仍显示“移出本组”，可把学员移出隐藏默认组并误归档。
- **修复**：
  - 新增 `server/src/routes/admin/roster-group-id.ts#selectRosterGroupId()`：只接受非默认的有效组 id；默认组 id、非法 id 一律返回空串（按“全部”处理）。
