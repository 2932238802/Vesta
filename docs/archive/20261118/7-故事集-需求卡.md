# 故事集：咨询栏目下独立的“分类 + 故事”速查页

> 维护者：Doc Agent ｜ 最近更新：2026-11-18 ｜ 状态：已确认（G0）
> 关联文档：`docs/archive/20261118/8-故事集-开发文档.md`（R-005 / AC / T）

## CR-005 故事集（咨询 › 故事集）

- **类型**：新功能
- **问题与价值**：咨询师在通话里常需要讲一个具体的例子或案例来回应学生，现在这些内容散落在聊天记录和个人笔记里，调用时找不到。金句栏解决的是“短句”，故事需要的是“有情节、有长度、可按主题找”的独立空间。
- **目标用户与场景**：咨询师；通话中根据学生当下的话题（拖延、迷茫、家庭、就业…）打开对应分类，找到一篇故事，复制到对话里或照着讲。
- **成功指标**：
  - 从进入故事集到复制一篇故事，不超过 3 次操作（选分类 → 找条目 → 复制）。
  - 新增一篇故事到列表可见，不超过 30 秒，且刷新后仍在。
  - 可观察场景：新建“家庭沟通”分类，添加一篇带标题的故事，切到该分类能看到它；复制后剪贴板内容与页面正文一致；再次打开页面数据仍在。
- **现状**：仓库内无任何“故事”相关代码或数据；微信缓存中也没有故事类 docx。本次从零新增，不做种子导入。

- **范围（用户已确认部分）**：
  - 咨询导航新增“故事集”，位于“金句栏”与“收藏栏”之间，独立页面 `/admin/consult/stories`。
  - 结构沿用金句栏：左侧分类，右侧故事列表；分类与故事都支持增删改查。
  - 独立数据表，不复用 `consult_quotes` / `consult_collections`。
- **建议字段**：标题（必填）、正文（必填）、分类（必填）、出处 / 适用场景（选填）、置顶。
- **建议能力**（待 G0 确认）：
  - 分类：新增、改名、上下调序；分类下仍有故事时不可删除。
  - 故事：新增、编辑、删除、置顶、复制、按分类筛选、关键字搜索（标题 / 正文 / 分类名）。
  - 卡片：标题 + 正文折叠 4 行；“查看全文”打开弹窗（不做独立详情路由）。
- **非目标**：
  - 不做 Word 导入、不做启动种子（Q1 已确认“先做空页面”）。
  - 不做 AI 生成 / 推荐、不接入咨询稿生成、不做使用统计。
  - 不做拖拽排序、批量导入导出、多图 / 富文本。
  - 不改金句栏、收藏栏的页面与数据。
- **NFR**：

| 项 | 判定 | 目标 / 理由 |
| --- | --- | --- |
| 性能 | 适用 | 一次性读取全部分类与故事；筛选在浏览器完成。首期数据量为人工录入的数十到数百篇。 |
| 安全 | 适用 | 沿用管理员会话与 `requireAdmin()`；正文按纯文本渲染，不使用 `v-html`；服务端校验长度与分类归属。 |
| 隐私与数据保留 | 适用 | 故事可能涉及真实学员经历，需人工自行脱敏；日志只记录 id 与分类，不记录正文；删除为硬删除并二次确认。 |
| 兼容性 | 适用 | 纯新增表、接口、路由；不改现有接口与页面。 |
| 可观测性 | 适用 | 新增 `consult.story_*` / `consult.story_category_*` 结构化日志，失败带 `reqId`；不记录正文。 |
| 成本 | 不适用 | 无外部调用、无新增基础设施。 |

- **约束与依赖**：
  - 遵循金句栏的既有实现模式（`server/src/routes/consult/quotes.ts`、`web/src/views/admin/quotes/*`），接口契约与错误码保持一致。
  - 新文件不超过 400 行；不向已有的巨型文件加功能。
  - 无数据迁移；建表走 `server/src/db/schema.ts` 的幂等建表。
- **风险与未知**：
  - 故事正文比金句长，单条可能上千字；列表接口一次全量返回在数百篇内可接受，超过需改分页（记为首期观察项）。
  - 故事含真实案例时存在隐私风险，需在表单内提示脱敏（不强制）。
  - 与金句栏结构相似，存在复制粘贴两套实现的维护成本；本次不抽取通用组件，避免为第二个实例过早抽象。

- **选项**：
  - A（推荐，已选）：按上述建议范围做完整 CRUD，先空页面人工维护。
  - B：只做“浏览 + 复制 + 新增”，编辑/删除/分类管理后置。
  - C：先不建页面，等故事素材整理好再一起做。
  - D：不做。
