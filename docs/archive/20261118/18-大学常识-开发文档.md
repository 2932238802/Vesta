## 1. 需求 R-010 大学常识（P1，v1）

- **来源**：CR-010（2026-11-19，G0 已确认）。
- **背景**：咨询中经常遇到入党、奖助学金、转专业等大学常识问题，信息散落且容易记错。需要按话题快速查到一份说明。
- **描述**：后台“咨询”组新增“大学常识”，位于“有效的提问”与“咨询树”之间。左侧话题栏（搜索、列表、拖拽排序），右侧 Wiki 阅读区（面包屑、标题、更新时间、Markdown 正文）；管理员可新建、编辑、删除话题，鼠标拖动调整顺序；默认按创建时间排序。
- **成功指标**：
  - 进入页面到打开话题 ≤ 2 次操作。
  - 新建/编辑后刷新仍在，计数一致。
  - 拖动两个话题后刷新，顺序保持。
- **验收标准**：

  - `AC-010-1` 咨询组顺序 写咨询稿 → 金句栏 → 故事集 → 有效的提问 → 大学常识 → 咨询树；路由 `/admin/consult/basics`；标题“大学常识 · 管理后台”；分组高亮。
  - `AC-010-2` 话题栏显示全部话题与数量；关键词按标题过滤并显示结果数；无匹配空状态；清空恢复。
  - `AC-010-3` 点击话题右侧显示面包屑「大学常识 / 标题」、标题、更新时间、正文；默认打开第一个；深链 `/admin/consult/basics/:id` 可打开。
  - `AC-010-4` Markdown 渲染（标题、加粗、列表、链接、代码）；`<script>`、`<img onerror>` 以文本显示；`javascript:` 链接不可点击；页面 `v-html` 仅来自 `renderMarkdown`。
  - `AC-010-5` 新建/编辑：标题与正文必填；保存后出现在列表末尾并自动选中，计数 +1；编辑立即反映；删除二次确认后移除、计数 -1。
  - `AC-010-6` 鼠标按住话题可拖动排序，有视觉反馈；松手后立即生效并持久化，刷新保持；默认按创建时间（新话题在末尾）。
  - `AC-010-7` 搜索过滤时禁用拖动，并给出提示（避免顺序歧义）。
  - `AC-010-8` 390px：话题栏全宽；点话题切到阅读视图，“返回话题列表”可用；无横向溢出。
  - `AC-010-9` 与金句栏、故事集、有效的提问、咨询树、知识库组互不影响。
  - `AC-010-10` 401/400/404；排序 ids 非法 400；页面错误态与重试。

## 3. 关键设计

### 3.1 信息架构

- 路由：`/admin/consult/basics`（默认打开第一个话题）与 `/admin/consult/basics/:id`。
- 导航：咨询组 写咨询稿 → 金句栏 → 故事集 → 有效的提问 → **大学常识** → 咨询树；`activeGroup` 归咨询。
- 布局：左侧 300px 话题栏（搜索 + 列表），右侧阅读区；≤1000px 话题栏全宽、点话题进入阅读视图并显示“返回话题列表”。

### 3.2 数据模型

```sql
CREATE TABLE IF NOT EXISTS consult_topics (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_consult_topics_order
  ON consult_topics(sort_order, created_at, id);
```

- `sort_order` 初始化为当前最大值 +1（即创建时间顺序）；拖动后整体重写。
- 无外键、无分类。

### 3.3 接口契约

| 方法 | 路径 | 作用 | 成功响应 |
| --- | --- | --- | --- |
| `GET` | `/topics` | 话题摘要列表（不含正文） | `{ topics }` |
| `GET` | `/topics/:id` | 单篇正文 | `{ topic }` |
| `POST` | `/topics` | 新建话题 | `{ topic }` |
| `PATCH` | `/topics/:id` | 编辑标题 / 正文 | `{ topic }` |
| `DELETE` | `/topics/:id` | 删除话题 | `{ ok: true }` |
| `PUT` | `/topics/order` | 全量重排 | `{ topics }` |

校验：

- 标题 `trim` 后 1–120 字；正文 `trim` 后 1–50000 字；否则 400。
- 不存在 404；排序 `ids` 必须恰好是现有全部话题的完整排列，否则 400；未登录 401。
- 日志只记录 `id` 与 `count`，不记录标题与正文。

### 3.4 前端结构（新文件 ≤400 行）

- `ConsultBasics.vue`：页面骨架、路由参数、加载与错误态。
- `basics/TopicRail.vue`：搜索、列表、拖拽排序、新建入口。
- `basics/TopicView.vue`：面包屑、标题、更新时间、Markdown 正文、编辑/删除、移动端返回。
- `basics/TopicEditorModal.vue`：标题、正文、Markdown 预览。
- `basics/useBasics.ts`：取数、选中、搜索、拖动状态与保存顺序。
- `consultBasics.css`：全部选择器以 `.basics-page` 前缀限定。

拖拽实现：

- 使用 Pointer Events（`pointerdown` → `pointermove` → `pointerup`），按住 4px 后进入拖动态；列表项按位移重排，松手调用 `PUT /topics/order`。
- 搜索框非空时禁用拖动，列表上方提示“清空搜索后可调整顺序”。
- 保存失败时回滚到拖动前顺序并提示。

### 3.5 与其他模块边界

- 不引用金句/故事/提问数据；无交叉。
- 移动端阅读视图只切换显示，不新增路由（仍为 `/:id`）。
