# CR-001 学员名单分组简化：移除日期分组、默认分组并入“全部”

> 维护者：Doc Agent ｜ 日期：2026-11-18 ｜ 状态：已确认（G0 / G1，选择“做，完整范围”）
> 文档位置：`docs/archive/20261118/1-学员名单分组简化-需求卡.md`

## 1. 需求卡

- **类型**：变更
- **问题与价值**：当前学员名单同时有“期次（日期）栏”“分组栏”“状态栏”，咨询师反馈分组仍不好用；默认分组与“全部”语义重叠，日期分组增加了筛选负担。目标是把名单收敛成“全部 + 用户自建分组”，日期维度不再出现在页面上。
- **目标用户与场景**：后台咨询师在“学员名单”中查看、筛选、分组、归档学员；新学员创建后默认出现在“全部”。
- **成功指标**：
  - 打开 `/admin/submissions`：页面顶部不再出现期次/日期栏（0 个日期控件）。
  - 分组栏不再出现“分组”文字标签和“默认分组”chip；只剩“全部”+用户自建分组；默认选中“全部”。
  - 新建邀请后，学员出现在“全部”，不需要额外加入分组。
  - 用户已有分组全部保留，分组数量、成员关系、归档数据不丢失。
  - 状态栏保持现状（含“全部”与各状态）。
- **范围**：
  1. **删除日期分组（UI + API）**：移除 `RosterCycleBar`、`week` 查询参数、`weeks` / `currentWeek` 响应、`AdminRosterWeek` 类型、期次空状态与“在全部期次里搜”入口。
  2. **分组栏简化**：删除“分组”文字标签；删除“默认分组”chip；保留“全部”+用户自建分组；“全部”默认选中；`groupId` 默认空串。
  3. **默认分组隐藏**：分组栏与“管理分组”弹窗不显示默认分组；底层保留 `roster_groups.is_default` 与新邀请自动归组，保证新学员出现在“全部”且不进入归档。
  4. **归档加回**：归档学员的“加入分组…”目标列表用“全部”承担默认分组职能；选择“全部”时写入隐藏的默认分组，学员回到“全部”。
  5. **保留用户分组**：现有 `roster_groups` / `roster_group_members` 数据与成员关系原样保留，不做数据迁移。
- **非目标**：
  - 不删除默认分组的数据库记录，不改 `is_default` 语义，不改归档定义（没有有效分组 = 归档）。
  - 不改状态分类栏（`ROSTER_TABS`）及其“全部”。
  - 不改多对多分组语义、不加新的分组层级或权限。
  - 不改名/迁移用户已有分组；不清理归档数据。
- **NFR**：

| 项 | 判定 | 目标 / 理由 |
| --- | --- | --- |
| 性能 | 适用 | 移除 `week` 过滤后，名单查询只按分组与搜索过滤；不新增额外请求；默认首屏请求次数不增加。 |
| 安全 | 不适用 | 不改变认证、授权、输入边界；分组接口仍走 `requireAdmin()`。 |
| 隐私与数据保留 | 不适用 | 不新增收集字段；不改变保留期与删除策略。 |
| 兼容性 | 适用 | 旧 URL 的 `week` / `group` / `dates` 参数应被忽略而不报错；`weeks` / `currentWeek` 从管理接口移除，当前仅 web 客户端使用，需同步类型。 |
| 可观测性 | 适用 | 保留现有 `roster.group_*` 日志；删除期次筛选后不新增日志；分组创建/删除/成员变更日志不变。 |
| 成本 | 不适用 | 不新增基础设施或外部调用。 |

- **约束与依赖**：
  - 依赖 v1.88 的分组表与默认组迁移（`server/src/db/roster-groups.ts`、`server/src/routes/admin/roster-groups.ts`）。
  - 前端组件：`RosterCycleBar.vue`（删除）、`RosterGroupBar.vue`、`RosterGroupDialog.vue`、`RosterArchive.vue`、`RosterTable.vue`、`Submissions.vue`、`useRoster.ts`、`useRosterGroups.ts`。
  - 后端：`server/src/routes/admin/roster.ts`、`shared/src/cycle.ts`（不再被名单使用，但可能被其他模块使用，不能删）、`web/src/api/types.ts`。
  - 验收与回归：`npm run verify`，名单分组/归档/加回手工走查。
- **风险与未知**：
  1. **名称冲突**：当前接口允许创建名为“全部”或“默认分组”的用户分组；与虚拟“全部”/隐藏默认组同屏会出现重名。建议保留名为“全部”“默认分组”的组名，并在生产库排查是否已有同名有效组。
  2. **归档入口变少**：默认分组隐藏后，用户无法从“全部”把学员移出默认组，新学员基本不会进入归档；“归档”主要服务历史未分组数据。需确认这是预期。
  3. **接口破坏性**：移除 `weeks` / `currentWeek` 会改变管理接口响应；当前只发现 web 客户端使用，需同步类型与页面。
  4. **旧链接**：带 `week` / `group` / `dates` 的旧 URL 需要优雅降级；本期建议忽略未知参数并清理地址栏。
- **选项**：
  - **A. 做（完整范围）**：一次完成 UI + API 删除日期分组、分组栏简化、默认组隐藏、归档加回“全部”。代价：前后端同时改，需回归名单/分组/归档；风险中等。
  - **B. 拆小（第一刀）**：本轮只改前端（删日期栏、隐藏默认组、默认选“全部”），`week` / `weeks` / `currentWeek` 接口字段保留到下轮清理。代价：留下死字段，但上线风险更小。
  - **C. 先 spike**：用临时 `DATA_DIR` 验证“默认组隐藏 + 新邀请自动归组 + 归档加回全部”的行为，时间盒半天，产出结论后再排任务。
  - **D. 缓办**：等咨询师确认“归档是否还需要入口”“重名分组怎么处理”后再做。
  - **E. 不做**：保留当前期次栏、默认分组 chip 与全部语义。
- **推荐**：A（完整范围）。理由：用户已明确 UI+API 全删，且默认组语义可由“全部”承接；主要风险集中在重名与归档入口，可在实现前用一条只读 SQL 排查生产分组名。
- **关联需求/任务**：R-001 / T-001 ~ T-005（见 `2-学员名单分组简化-开发文档.md`）
- **状态**：已确认（G0）；待 G1 确认后进入开发

## 2. 已确认口径（2026-11-18）

- 期次/日期栏：**整栏删除**，前端 + 后端 `week` 过滤一起删。
- 分组栏：删除“分组”文字标签；保留“全部”；删除“默认分组”chip；默认选中“全部”。
- 默认分组：底层保留 `is_default` 与自动归组，界面隐藏；新学员默认出现在“全部”。
- “全部”范围：所有有效分组里的学员；归档学员仍在下方单独列出。
- 管理弹窗：隐藏默认分组。
- 归档加回：以“全部”为目标，实际写入隐藏默认分组。
- 状态栏：保留现状（含“全部”）。

> 说明：用户最初第 1 点写“删掉全部、保留默认分组”，后续澄清为“删掉默认分组、默认选全部”；本卡以后续澄清为准。
