## CR-006 知识库重组（分数线组改名、收藏栏移出、金句栏迁移、专业知识汇总）

- **类型**：栏目调整 + 新功能
- **背景**：后台侧栏把“金句、分数线、专业知识”分放在不同栏目，咨询师在通话中要在几个入口之间来回找。把与“查资料”相关的内容收进一个“知识库 && 数据库”栏目，按“专业 → 知识点”组织专业知识，能让查找路径变成一次点击进入、按专业定位。
- **目标用户与场景**：咨询师 / 运营；通话中按学生所读专业（如护理）打开对应条目，找到“专科和本科的就业对比”“为什么大批年轻护士提桶跑路”这类可直接讲的内容。
- **现状盘点（只读调研，2026-11-18）**：

| 项 | 现状 |
| --- | --- |
| 侧栏分组 | 问卷 / 咨询 / 分数线 / 设置 |
| 咨询组 | 写咨询稿、咨询树、金句栏、故事集、收藏栏 |
| 分数线组 | 升学分数线查询（`/admin/score-lines`，v1.92 改名） |
| 金句栏 | `/admin/consult/quotes`，独立表 `consult_quote_categories` / `consult_quotes` |
| 收藏栏 | `/admin/consult/collections` 与详情页；页面、接口、`consult_collections` 表均存在 |
| Markdown | `web/src/markdown.ts` 已有轻量渲染（标题、列表、链接、图片等，先转义再拼接），收藏栏在用 |
| 逐句树 | `settings.consult_forest` 保留 |

- **范围（用户的四条指令）**：
  1. 侧栏“分数线”大栏改名为“知识库 && 数据库”（名称待确认）。
  2. 咨询组移除“收藏栏”。
  3. 金句栏从咨询组移动到“知识库 && 数据库”组，位于分数线入口之下。
  4. 新组内新增“专业知识汇总”，位于金句栏之下：Wiki 结构，专业 → 若干知识点，每个知识点默认是一篇小文章。

- **建议结构**：
  - 侧栏：问卷 / 咨询 / **知识库 && 数据库** / 设置。
    - 知识库 && 数据库：升学分数线查询 → 金句栏 → 专业知识汇总。
    - 咨询：写咨询稿 → 咨询树 → 故事集（收藏栏入口移除）。
  - 路由：金句栏保持 `/admin/consult/quotes`（只改导航分组，旧书签可用）；分数线保持 `/admin/score-lines`；专业知识汇总新增 `/admin/knowledge`（专业列表）与 `/admin/knowledge/:majorId`（专业首页）/ 文章阅读态。
  - 数据：`knowledge_majors`（id、name、sort_order、created_at、updated_at）；`knowledge_articles`（id、major_id、title、body、sort_order、created_at、updated_at）。不启用外键，接口层校验。
  - 页面：左侧专业栏（护理、计算机…）+ 右侧专业首页（知识点列表）→ 点击知识点进入 Wiki 阅读视图（面包屑：专业知识汇总 / 护理 / 标题），可返回。管理员可新增/编辑/删除专业与知识点，专业支持上下调序。
  - 正文：建议支持现有轻量 Markdown（标题、列表、链接、粗体、图片），阅读态渲染。
- **非目标**：
  - 不改金句栏、分数线页面的内部功能与数据。
  - 不删除收藏栏的数据、接口与页面（仅移除入口，除非用户明确要求下线）。
  - 不做全文检索索引、版本历史、协作编辑、权限分级；首期只有管理员编辑。
  - 不做 AI 生成、自动分类、外链抓取。
  - 不做多级目录（专业下再分组）；只做“专业 → 知识点”两级。
- **NFR**：

| 项 | 判定 | 目标 / 理由 |
| --- | --- | --- |
| 性能 | 适用 | 专业与知识点列表一次读取；文章正文按需读取或随列表返回（取决于规模，设计时定）。 |
| 安全 | 适用 | 沿用 `requireAdmin()`；Markdown 渲染必须先转义、只允许 http(s) 链接，避免 `v-html` 注入。 |
| 隐私与数据保留 | 适用 | 知识内容可能引用真实案例，表单提示脱敏；日志不记录正文。 |
| 兼容性 | 适用 | 金句栏、分数线路由不变；收藏栏仅移除入口，旧链接仍可直达。 |
| 可观测性 | 适用 | 新增 `knowledge.major_*` / `knowledge.article_*` 日志，失败带 `reqId`。 |
| 成本 | 不适用 | 无外部调用。 |

- **风险与未知**：
  - 收藏栏“移除”若被理解为删除功能，会涉及用户数据；必须确认是“隐藏入口”还是“下线功能”。
  - 专业知识内容量大时，一次返回全部正文会拖慢首屏；首期按人工维护量级设计，后续按需加分页。
  - 侧栏分组名含 `&&` 或 `&` 属字符选择，需与用户确认字面量。
  - 知识库组内三个入口的语义差异（分数线 / 金句 / 专业知识）需要在页面标题或副标题里说清，否则仍会混淆。

| A-020 | 内容来源 | 空页面人工维护（用户已选） | 空页面人工维护 |
| A-021 | 知识点是否需要标签/分类 | 需要 / 不需要 | 不需要，首期两级结构 |

- **选项**：
  - A（推荐）：按上述建议做完整重组 + 专业知识汇总 Wiki（空页面人工维护）。
  - B：先只做栏目重组（改名、移收藏栏、移金句栏），专业知识汇总下一轮。
  - C：先只做专业知识汇总，栏目重组后置。
  - D：不做。
