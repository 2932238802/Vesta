# 学员名单：咨询状态与手工优先级 · 开发文档

> 版本：v1.1（2026-11-17）　状态：**已实施并提交（产品版本 v1.86）**
> 一句话：在学员名单里加入「是否咨询」勾选与「咨询结果」四选一，勾选行排前并整行高亮；把原来的自动 A/B/C 优先级删掉，改成咨询师手工填写，并且不向答题者展示任何档位。
> 范围：管理端学员名单、名单相关接口与导出、答卷详情/首页最近答卷的连带展示、公开报告脱敏。**本轮只落盘开发文档，不改代码、不改版本号。**

## 一、需求与已确认口径

| # | 已确认结论 | 说明 |
| --- | --- | --- |
| 1 | 在「学员」和「阶段」之间增加 **是否咨询** 复选框 | 管理员可勾选/取消；每行一个，不是批量选择框 |
| 2 | 默认排序：**已勾选在前，未勾选在后** | 两组内部继续保持原来的「最新在前」顺序 |
| 3 | 勾选后 **整行颜色高亮** | 与批量选择的高亮可叠加，但不能互相覆盖到看不见 |
| 4 | 在「阶段」和「优先级」之间增加 **咨询结果** 下拉框 | 四个选项：`已成交`、`跟进`、`快成了`、`维护中`；可留空 |
| 5 | **优先级改为咨询师手工填写** | 不再按问卷自动算 A/B/C；名单、详情、首页都不再显示自动档位 |
| 6 | **答题者看不到优先级/档位** | 公开报告页面和 `/api/report/:slug` 返回的 JSON 都不能出现 A/B/C 或对应档位文案 |
| 7 | 历史自动 A/B/C **不回填**成人工优先级 | 避免把机器判断伪装成咨询师判断；历史值留在库里但不再展示 |

### 1.1 口径澄清

- **阶段**是系统按答卷/领取/联系状态推导的流程阶段（`pending / opened / expired / unclaimed / new / contacted / scheduled / done`），本次不改。
- **是否咨询**是咨询师手动维护的独立布尔值，不自动改变阶段；勾选「是否咨询」不会把阶段改成「已联系」。
- **咨询结果**是咨询完成后的结果分类，和阶段、优先级都是独立字段。未勾选「是否咨询」时下拉框禁用；取消勾选会清空咨询结果（见 5.2）。
- **优先级**是自由短文本，最多 20 字，可空；不预设「高/中/低」或 A/B/C。这样咨询师可以按自己的习惯写「高」「本周重点」「先放一放」等。
- 用户原句「已成交  跟进，快成了  维护中 这四个」按四个选项处理：`已成交` / `跟进` / `快成了` / `维护中`，中间的逗号是分隔，不是选项文案的一部分。


「优先级/分数」列当前直接读 `AdminRosterRow.tier`：

- legacy 模式：同一列还显示 `submissions.total`。
- 列名由 `rosterScoreLabel()` 动态决定（`web/src/views/admin/submissions/rosterMeta.ts`）。

### 2.2 数据与接口

- `GET /api/admin/roster`（`server/src/routes/admin/roster.ts#rosterRouter`）从 `invites LEFT JOIN submissions` 取数，排序为 `COALESCE(s.created_at, i.created_at) DESC LIMIT 1000`，每行返回 `tier`、`total`、`stage` 等字段。
- 表结构：`invites`（`server/src/db/schema.ts`）目前没有咨询状态/结果/手工优先级字段；`submissions` 有 `tier`、`total`、`contact_status`。
- 修改单行状态的现有入口是 `PATCH /api/admin/submissions/:id`，只能改 `contactStatus`、`adminNotes`、`overrides`；未提交的邀请没有 submission，改不了。
- 首页最近答卷（`server/src/routes/admin/overview.ts`）和答卷详情（`server/src/routes/admin/submissions.ts`）都返回 `tier`，前端分别显示「X 档」。

### 2.3 自动优先级从哪里来

- 提交时：`server/src/routes/public.ts` 在 `doc` 模式下调用 `docPriority(survey, answers)`，写入 `submissions.tier`。
- 报告构建时：`shared/src/doc.ts#buildDocReportWithAi` 再调用一次 `docPriority()`，但把 `tierLabel`、`tierLine` 置空，所以 doc 报告页面本来就不显示档位。
- legacy `ai` 报告仍可能通过 `shared/src/report.ts#buildReport` 的 hero 块带出 `tierLabel`；AI 失败时的 `buildFallback()` 对 doc 模式也会走 `buildReport()`，存在把档位文案带出来的路径。

## 三、目标交互

### 3.1 表格结构

```text
[全选] 学员 | 是否咨询 | 阶段 | 咨询结果 | 优先级 | 领取/联系 | 时间 | 操作
```

- 「是否咨询」列宽约 74px，表头居中，单元格放一个原生 checkbox。
- 「咨询结果」列宽约 96px，使用和「联系状态」一致的原生 `select` 样式。
- 「优先级」列宽约 96px，使用原生文本输入框，`maxlength=20`，失焦或回车保存。
- 窄屏继续横向滚动，`roster-table` 的 `min-width` 从 720px 提到约 920px。

### 3.2 行为规则

| 场景 | 表现 |
| --- | --- |
| 勾选「是否咨询」 | 立即勾上；PATCH 成功后重新拉名单，该行排到未勾选行前面，整行高亮 |
| 取消勾选，且已有咨询结果 | 先弹确认：「取消后咨询结果会清空，确定吗？」取消则恢复勾选 |
| 取消勾选，且没有咨询结果 | 直接 PATCH；成功后行回到未勾选分组 |
| 未勾选时看咨询结果 | 下拉框禁用，显示空值；不能选择 |
| 勾选后选咨询结果 | 下拉框可用；选择后立即 PATCH，失败则恢复原值并提示 |
| 修改优先级 | 失焦或回车时保存；前后空格去掉，超过 20 字截断；空值表示清空 |
| 保存中 | 只禁用当前行的相关控件，避免连点；其他行不受影响 |
| 保存失败 | 用服务端数据恢复该行（重新 `load()` 或恢复原值），toast 显示错误 |
| 点击行打开详情 | 点击 checkbox / select / input 不触发行跳转；沿用 `openRow()` 对 `input, select, textarea, label, button` 的忽略逻辑 |
| 批量选择 | 仍由第一列的 checkbox 负责；与「是否咨询」互不影响 |
| 搜索 / 期次 / 状态 tab | 过滤后仍按「勾选在前」排序；计数逻辑不变，不新增 tab |
| 未提交的邀请 | 也可以勾选咨询、填结果和优先级；这些字段挂在邀请上，不要求先有答卷 |

### 3.3 高亮样式

在 `web/src/views/admin/submissions/shared.css` 增加：

```css
.submissions-page .roster-table tbody tr.consulted td {
  background: color-mix(in srgb, var(--accent) 7%, transparent);
}
.submissions-page .roster-table tbody tr.consulted.picked td {
  background: color-mix(in srgb, var(--accent) 13%, transparent);

```

- `picked` 是批量选择态，`consulted` 是咨询标记态；两者叠加时用更深的底色，不能只剩其中一种。
- 不改变 hover 行为；hover 仍由现有表格样式负责。
- 勾选行的底色要覆盖整行（包括第一列选择框单元格），不是只染姓名单元格。

### 3.4 文案

- 表头：`是否咨询`、`咨询结果`、`优先级`。
- 咨询结果选项：`未选择`（空值）、`已成交`、`跟进`、`快成了`、`维护中`。
- 优先级输入框占位符：`填写`；为空时也可以显示 `—`，但不要显示 A/B/C。
- 保存成功 toast：`已标记咨询`、`已取消咨询`、`咨询结果已更新`、`优先级已更新`。

## 四、数据模型

### 4.1 字段放在 `invites`

新增三列到 `invites`，不放到 `submissions`：

| 列 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `consulted` | `INTEGER NOT NULL` | `0` | 0/1，是否已咨询 |
| `consult_result` | `TEXT NOT NULL` | `''` | `'' / won / following / almost / maintaining` |
| `priority` | `TEXT NOT NULL` | `''` | 咨询师手工优先级，≤20 字 |

理由：

1. 名单一行对应一条邀请；未提交的邀请也要能勾选咨询、填优先级。
2. 删除答卷后邀请还在，咨询信息不应跟着答卷消失；重新填写也不丢。
3. 同一学员如果换新链接，新邀请是独立记录，符合「一条链接一条跟进记录」的现有口径。

### 4.2 迁移

在 `server/src/db/migrations.ts#ensureInviteColumns` 里把当前只处理 `group_id` 的逻辑改成 additions 列表，保持幂等：

```sql
ALTER TABLE invites ADD COLUMN consulted INTEGER NOT NULL DEFAULT 0;
ALTER TABLE invites ADD COLUMN consult_result TEXT NOT NULL DEFAULT '';
ALTER TABLE invites ADD COLUMN priority TEXT NOT NULL DEFAULT '';
```

实现时继续用 `PRAGMA table_info(invites)` 判断列是否存在，存在就跳过；不要新建迁移版本表，也不要写一次性脚本。

### 4.3 历史数据

- 不把 `submissions.tier` 的 A/B/C 回填到 `invites.priority`。
- `submissions.tier` 列保留，历史值不动；新 doc 答卷写入空串（见第七节）。
- 旧的自动档位不再出现在任何管理端展示或公开报告中；需要追溯时只能查库或看历史报告原文。

### 4.4 索引

不新增索引。名单最多 1000 行，`consulted` 只有 0/1 两个值，索引收益低；排序在内存/临时表完成即可。若以后名单上限放大，再评估 `(consulted, created_at)` 组合索引。

## 五、接口契约

### 5.1 `GET /api/admin/roster`

查询语句增加三列：

```sql
SELECT i.id AS invite_id, ..., i.consulted, i.consult_result, i.priority,
       s.id AS submission_id, ...
FROM invites i
LEFT JOIN submissions s ON s.invite_id = i.id
ORDER BY i.consulted DESC, COALESCE(s.created_at, i.created_at) DESC, i.id
LIMIT 1000
```

返回的每行新增：

```json
{
  "consulted": true,
  "consultResult": "following",
  "priority": "高"
}
```

- `consulted` 转成布尔值，不把 0/1 直接给前端。
- `consultResult` 为空串表示未选择；非法历史值按空串处理。
- `priority` 为空串表示未填写。
- `tier` 从响应中删除；`total` 保留，供 legacy 行在优先级下面显示总分。
- `counts`、`weeks`、`currentWeek` 不变；不新增「已咨询」tab。

### 5.2 `PATCH /api/admin/roster/:inviteId`

新增路由，挂在 `rosterRouter` 上，位于 `requireAdmin()` 之后。

请求体（至少一个字段）：

```json
{ "consulted": true }
{ "consultResult": "won" }
{ "priority": "本周重点" }
```

校验与语义：

| 字段 | 规则 |
| --- | --- |
| `consulted` | 必须是 boolean；否则 `400 咨询状态格式不对` |
| `consultResult` | 必须是 `'' / won / following / almost / maintaining`；否则 `400 咨询结果不在允许范围` |
| `priority` | 必须是 string，否则 `400 优先级格式不对`；`trim()` 后截断到 20 字；空串表示清空 |
| 记录不存在 | `404 记录不存在` |
| 一个字段都没有 | `400 没有需要更新的内容` |

联动规则：

- 生效后的 `consulted` 为 `false` 时，服务端强制把 `consult_result` 写成 `''`，即使请求里带了非空结果。
- 生效后的 `consulted` 为 `true` 时，`consultResult` 不传就保持原值。
- 不自动修改 `invites.status`、`submitted_at`、`submissions.contact_status`。

响应：

```json
{ "ok": true }
```

写库后记一条结构化日志 `roster.consult_updated`，字段包含 `reqId`、`inviteId`、本次实际变更的字段名、`res.locals.admin`；不要记录优先级原文以外的个人信息。

### 5.3 导出 CSV

`GET /api/admin/submissions/export.csv` 的查询已经 JOIN `invites`，增加 `i.consulted, i.consult_result, i.priority`。

表头调整：

```text
姓名, 备注, 渠道, 提交时间, 总分, 优先级, 是否咨询, 咨询结果, 微信号, 时间段, 联系状态, 优先方向, 半年目标, 目标城市与岗位, 报告路径, 管理员备注
```

- 「档位」列删除，换成手工「优先级」。
- 「是否咨询」输出 `是` / `否`；「咨询结果」输出中文标签，空值留空。
- `总分` 口径不变：doc 模式留空，legacy 输出 `submissions.total`。
- 列顺序变化会影响按列号解析的旧脚本；CSV 没有版本号，按表头读取的脚本不受影响。

### 5.4 首页最近答卷

`server/src/routes/admin/overview.ts` 的 recent 查询增加 `i.priority`，响应把 `tier` 换成 `priority`。`web/src/views/admin/Dashboard.vue` 只在 `row.priority` 非空时显示 chip，不再显示「X 档」。

### 5.6 咨询导入

## 七、公开报告脱敏

目标：答题者在页面上、保存的图片/PDF 里、接口 JSON 里都看不到自动 A/B/C 或档位文案。

### 7.1 停止计算新的自动优先级

- `server/src/routes/public.ts`：doc 模式提交时不再调用 `docPriority()`，`scores` 写成 `{ total: 0, tier: '', dimensions: [], detail: {} }`。
- `shared/src/doc.ts`：`buildDocReportWithAi()` 的 hero 块不再调用 `docPriority()`，`tier` 写空串。
- 删除 `shared/src/doc.ts#docPriority` 及其两处 import。
- `shared/src/types.ts` 的 `ScoreResult.tier` 与 hero 块 `tier` 类型从 `Tier` 放宽为 `Tier | ''`；否则 doc 提交写空串会触发类型错误。

### 7.2 服务端统一脱敏

> 实施偏差（2026-11-17）：`server/src/routes/public.ts` 正好卡在 611 行基线（`check:size` 只减不增），
> 不能再往里加函数。helper 放到独立模块 `server/src/report-privacy.ts`，`public.ts` 只 import，
> 行为与本文档一致。

新增一个只在公开路由使用的 helper：

```ts
export function hidePriorityForStudent(payload: ReportPayload): ReportPayload {
  return {
    ...payload,
    blocks: payload.blocks.map((block) =>
      block.type === 'hero'
        ? { ...block, tier: '', tierLabel: '', tierLine: '' }
        : block
    )
  }
}
```

对 `GET /api/report/:slug` 的所有返回路径应用：

- `storedPayload`（已生成、已落库的报告）；
- `buildFallback()`（AI 未配置 / 失败时的基础版）；
- 任何 `preview=1` 提前返回的 payload。

这样即使历史报告里存了 `tier: 'A'` 或模板渲染出了 `tierLabel`，公开响应也会被清空。legacy `ai` 模式同样脱敏；公开页只保留总分（`total`），不保留档位。

### 7.3 前端

`HeroBlock.vue` 不需要改逻辑：`tierLabel` 为空时本来就不渲染档位 chip；`tierLine` 为空时不渲染档位说明。脱敏后即使有人查看 JSON，也看不到 A/B/C。

## 十、边界与待确认

| 项 | 当前决定 | 说明 |
| --- | --- | --- |
| 优先级格式 | 自由短文本，≤20 字 | 需求没给固定档位；若实际要「高/中/低」或 1–5 分，只换前端控件与校验，`priority TEXT` 不变 |
| 咨询结果为空 | 允许 | 勾选咨询后可以先不选结果；导出时空值留空 |
| 是否咨询与阶段 | 完全独立 | 不自动改 `contact_status`；如果产品希望勾选后自动变「已联系」，需要另开需求 |
| legacy `ai` 模式 | 公开报告也脱敏档位 | 只保留总分；如果旧报告必须保留档位说明，需要产品明确例外 |
| 历史 A/B/C | 不回填 | 名单里显示空优先级，咨询师自行补 |
| 多管理员并发 | 后写覆盖 | 不加版本号/乐观锁；现有联系状态也是这个模型 |
| 咨询信息是否进审计 | 记结构化日志，不建历史表 | 需要「谁在什么时候改了什么」的完整审计时再加表 |
| 详情页编辑 | 只读展示 | 编辑入口统一在名单；避免两套保存路径 |
| 自定义报告模板里的 `{{tier}}` / `{{tierLabel}}` | 默认模板只在 hero 使用 | 公开脱敏覆盖 hero；如果后台自定义模板把档位占位符写进正文，需要同步清理模板或禁用这两个占位符 |
| CSV 列顺序 | 改变 | 按表头读取的脚本不受影响；按列号硬编码的脚本需要同步 |
