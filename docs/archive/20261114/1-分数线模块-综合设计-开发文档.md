> 版本：v3.3（2026-11-14）　状态：**Phase 1 已实施（产品版本 v1.77，待提交）**

## 〇、设计结论（先看）

1. **只给咨询师/运营用**：管理后台内部工具，不做学生端，不接入 AI 报告。
2. **学员信息手填**：不依赖答卷；省份以手填为准。后续如果要「从学员带入」再加，不影响表结构。
3. **口径分四层**：
   - **主线**：考研国家线（A/B 区、学科门类、学硕/专硕）、专升本省控线（省份、科类、批次）；
   - **院校线**：某校某年总分 / 单科；
   - **专业线**：某校某专业某年总分 / 各科目单科；
   - **招生计划**：专业、计划数、学费、考试科目。
4. **覆盖全国院校**：建全国院校主表 + 别名 + 招生专业表；查询可按院校搜索，覆盖状态明确区分「已收录 / 未发布 / 不招生 / 抓取失败」。
5. **每个学校不一样、各科目都要**：分数线按「学校 + 专业 + 科目」存，`subject_code` + `full_score` 必填；总分也是一个科目（`total`）。
6. **服务端自动抓取**：定时任务 + 数据源注册表 + 原始快照 + 解析器版本 + 校验/复核；抓不到就明确失败，运营可导入兜底。
7. **分阶段上线**：先做全 31 省主线（国家线/省控线）+ 查询/图表；再逐级扩到全部院校的校线/专业线；不为了「全」把页面做成不可用。

## 一、需求、口径与验收

### 1.1 使用者与场景

- 使用者：咨询师（在野）和运营；在电话/微信沟通中快速查「这个省、这个学校、这个专业，往年要多少分」。
- 不面向学生：没有公开页；不需要登录学生账号。
- 不写报告：AI 报告仍按 `shared/src/doc-skill.ts` 的约束，不把这里的数字自动写进正文。

### 1.2 输入

页面手填，全部可改：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 考试类型 | 是 | 专升本 / 考研 |
| 年份 | 是 | 查哪一年；折线图默认展示该范围全部年份 |
| 省份 | 专升本必填；考研主线必填，院校线可由院校带出 | 以手填为准 |
| 地区 / 市 | 否 | 专升本地市（可空）；考研 A/B 区由省份自动映射 |
| 院校 | 否 | 全国院校搜索；不选就只看主线 |
| 专业 | 否 | 选院校后搜该校专业；用于专业线/计划/学费 |
| 批次 / 科类 | 否 | 专升本普通类/建档立卡/退役士兵；考研学硕/专硕、学科门类 |
| 学习方式 | 否 | 考研全日制/非全日制（有数据才显示） |

### 1.3 输出

1. **主线卡**：该省该年国家线/省控线，总分 + 各单科；永远显示，不被院校线替代。
2. **院校线/专业线**：选院校/专业后显示；总分 + 各科目单科；**校线和专业线都在**，没有就明确「未收录」。
3. **折线图**：同一科目跨年份；**主线、校线、专业线三条都可同图对比**（同一科目同一量纲）；最低分用单独标记，不连线。
4. **数据表**：科目 × 年份；主线、院校线分开展示。
5. **招生计划**：专业、计划数、学费、考试科目、备注。
6. **来源与时间**：来源名称、链接、发布时间、抓取时间、覆盖状态。

### 1.4 口径定义（必须写清，避免各人理解不同）

| 术语 | 定义 |
| --- | --- |
| 主线 | 考研国家线（教育部/研招网）与专升本省控线（各省考试院）。主线不分学校，只按省/区、科类、批次 |
| 院校线 | 学校自己划的复试线/投档线；可以是校线，也可以按专业 |
| 专业线 | 某校某专业（或院系）单独划线；与校线同时保留，图上都画 |
| 单科线 | 每个科目要求的最低分；考研常见政治/英语一/英语二/数学一/数学二/专业课一/专业课二；专升本按各省科目 |
| 总分线 | 所有科目合计的最低分，作为 `subject_code='total'` 的一个指标 |
| 最低分 | 录取/复试/投档产生的最低分，单独打 `is_minimum=1` 标志；图上用空心标记，不并入分数线 |
| 招生计划 | 某校某专业某年计划招多少人、学费多少、考哪些科目 |
| 覆盖状态 | `covered` 已收录 / `partial` 部分年份或部分科目 / `no_data` 官方未发布或未抓到 / `not_offered` 该校该年不招 / `failed` 抓取或解析失败 |

### 1.5 验收标准

| # | 验收 |
| --- | --- |
| AC1 | 手填「浙江 + 专升本 + 2025」：先显示省控线（总分 + 各科目单科），再显示可查询院校 |
| AC2 | 手填「浙江 + 考研 + 2025 + 某校 + 某专业」：显示国家线（A/B 区）+ 校线 + 专业线（总分/各科单科）；没有则明确空状态 |
| AC3 | 每所学校可搜索到；搜索支持校名、别名、城市；未收录的学校也能被选中并提示 |
| AC4 | 折线图与数据表数字一致；缺年份断线；主线、校线、专业线同科目可对比；最低分标记不连线 |
| AC5 | 专升本院校列表含校名、城市、办学性质、招生专业、计划数、学费；主线不丢 |
| AC6 | 「刷新/抓取」能触发服务端任务；运行中有状态；失败显示真实原因；完成后自动重查 |
| AC7 | 覆盖页能看出每个省/学校的抓取状态、最后成功时间、失败原因 |
| AC8 | 全部接口要求管理员令牌；前端不直接访问外部网站 |
| AC9 | 每个数字可追溯到来源链接和抓取时间；抓取失败的旧数据不被坏数据覆盖 |
| AC10 | 390px 下筛选、图表、表格、院校列表可用，无页面级横向溢出 |
| AC11 | 不把未核验的分数线写进 AI 报告 |

### 3.3 规模估算

全国普通高校约 3,000 所（本科 + 高职，具体以教育部名单为准）。按 10 年 × 每校 20 个专业 × 每专业 10 个科目估算，最坏约 300 万条指标；实际远小于这个数。SQLite 能存，但必须：

- 按 `school_id + year` 走索引，查询不扫全表；
- 抓取分批写入，单批 ≤500 条指标；
- 备份/恢复关注数据库体积，超过阈值时做归档（10 年外冷数据）。

## 四、覆盖模型：怎么做到「遍及所有国内学校」

### 4.1 四层数据

```text
L1 主线：国家线 / 省控线（1 条，按省/区 + 科类 + 批次）
L2 院校线：某校某年（总分 + 单科）
L3 专业线：某校某专业某年（总分 + 单科）
L4 招生计划：某校某专业某年（计划数 + 学费 + 考试科目）
```

查询时 L1 永远显示；L2/L3/L4 选院校/专业后显示。专业线存在时优先展示专业线，校线不删，作为对照。

### 4.2 全国院校主表

- 从教育部公布的全国普通高校名单导入（`scripts/seed-schools.ts`），字段：校名、学校标识码、省份、城市、层次（本科/专科）、办学性质（公办/民办/中外合作/独立学院）、官网、研究生院/招生网。
- 别名表：简称、旧名、合并更名（如「XX 学院」→「XX 大学」），用于搜索和抓取文本匹配。
- 标签：985 / 211 / 双一流 / 自划线 / 强基等，用 JSON 数组，别为每个标签加列。
- 院校搜索按「校名 / 别名 / 城市」匹配；3,000 条以内 `LIKE` 足够，必要时加 FTS。

### 4.3 覆盖状态

**不要用一个 `has_data` 布尔值糊弄**。每所学校 × 考试 × 年份应有明确状态：

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| `covered` | 该年有主线 + 院校/专业线，或至少院校线 | 正常展示 |
| `partial` | 有部分专业/科目，或只有校线没有专业线 | 展示已有，标注缺什么 |
| `pending` | 抓到了但还没复核（或只有待复核数据） | 只显示「待复核」卡片/徽标，不显示任何数字 |
| `no_data` | 官方还没发布，或已发布但没抓到 | 空状态 + 来源 + 去抓取 |
| `not_offered` | 该校该年不招这个考试/专业 | 明确写「不招生」，不显示空图表 |
| `failed` | 抓取/解析失败 | 显示失败原因 + 重试 |

覆盖状态放 `school_coverage` 表（见 5.6），按学校/考试/年份更新；查询时直接读，不在页面里猜。

### 4.4 数据来源分层

| 层 | 来源 | 抓取频率 | 备注 |
| --- | --- | --- | --- |
| T0 主线 | 教育部 / 研招网 / 31 省考试院 | 每天/每周 | 数量少、最重要，优先保证 |
| T1 重点校 | 34 所自划线 + 双一流高校研究生院 | 每周 | 校线/专业线 |
| T2 全部本科 | 全国本科院校研究生院/招生网 | 每两周/每月 | 覆盖主目标 |
| T3 专科/专升本 | 各省考试院 + 招生院校 | 每月 | 计划、学费、专业 |
| T4 兜底 | 运营导入 JSON/Excel | 随时 | 抓不到/PDF 图片时 |

**「遍及所有学校」的现实边界**：不是每所学校都公开分数线，也不是每所都招同一个考试。系统保证「每所学校都能被搜到、每个数据缺口都有状态和来源」，不承诺「每所学校每个专业都有数字」。这比假装全覆盖更可信。

## 五、数据模型

### 5.1 总览

```text
schools 1─N school_aliases
schools 1─N school_programs（招生专业 / 计划 / 学费 / 考试科目）
schools 1─N scoreline_batches（主线 / 院校线 / 专业线）
scoreline_batches 1─N scoreline_metrics（总分 / 各科单科）
scoreline_sources（抓取源注册表）
crawl_runs 1─N crawl_documents（原始快照）
school_coverage（每校每年覆盖状态）
```

v1.0 的 `score_line_sets` / `score_line_entries` 保留为 legacy，不删、不改名。

### 5.2 `schools`

```sql
CREATE TABLE IF NOT EXISTS schools (
  id            TEXT PRIMARY KEY,              -- sch_...
  code          TEXT NOT NULL DEFAULT '',      -- 教育部学校标识码/招生代码
  name          TEXT NOT NULL,
  province      TEXT NOT NULL DEFAULT '',
  city          TEXT NOT NULL DEFAULT '',
  level         TEXT NOT NULL DEFAULT '',      -- 本科 / 专科 / 其他
  nature        TEXT NOT NULL DEFAULT '',      -- 公办 / 民办 / 中外合作 / 独立学院
  tags          TEXT NOT NULL DEFAULT '[]',    -- JSON：985/211/双一流/自划线
  official_url  TEXT NOT NULL DEFAULT '',
  graduate_url  TEXT NOT NULL DEFAULT '',
  admissions_url TEXT NOT NULL DEFAULT '',
  status        TEXT NOT NULL DEFAULT 'active',-- active / merged / closed
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_schools_name_province ON schools(name, province);
CREATE INDEX IF NOT EXISTS idx_schools_province ON schools(province, level);

CREATE TABLE IF NOT EXISTS school_aliases (
  id        TEXT PRIMARY KEY,
  school_id TEXT NOT NULL,
  alias     TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_school_alias ON school_aliases(alias);
CREATE INDEX IF NOT EXISTS idx_school_alias_school ON school_aliases(school_id);
```

### 5.3 `school_programs`（招生专业 / 计划 / 学费）

```sql
CREATE TABLE IF NOT EXISTS school_programs (
  id            TEXT PRIMARY KEY,              -- prg_...
  school_id     TEXT NOT NULL,
  year          INTEGER NOT NULL,
  exam          TEXT NOT NULL,                 -- upgrade / postgrad
  province      TEXT NOT NULL DEFAULT '',      -- 招生省份
  major_code    TEXT NOT NULL DEFAULT '',
  major_name    TEXT NOT NULL,
  degree_type   TEXT NOT NULL DEFAULT '',      -- 学硕 / 专硕 / 空
  study_mode    TEXT NOT NULL DEFAULT '',      -- 全日制 / 非全日制 / 空
  plan_count    INTEGER,                       -- 计划数，未知为 NULL
  tuition       TEXT NOT NULL DEFAULT '',      -- 学费原文，可能「5000 元/年」或「5000–6000」
  exam_subjects TEXT NOT NULL DEFAULT '[]',    -- JSON：[{code,name,fullScore}]
  note          TEXT NOT NULL DEFAULT '',
  source_url    TEXT NOT NULL DEFAULT '',
  review_status TEXT NOT NULL DEFAULT 'pending', -- pending / approved / rejected
  updated_at    TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_school_programs_key
  ON school_programs(school_id, year, exam, province, major_code, degree_type, study_mode);
CREATE INDEX IF NOT EXISTS idx_school_programs_school
  ON school_programs(school_id, year DESC, exam);
```

### 5.4 `scoreline_batches`

```sql
CREATE TABLE IF NOT EXISTS scoreline_batches (
  id            TEXT PRIMARY KEY,              -- slb_...
  scope         TEXT NOT NULL,                 -- national / provincial / school / program
  exam          TEXT NOT NULL,                 -- upgrade / postgrad
  year          INTEGER NOT NULL,
  province      TEXT NOT NULL DEFAULT '',
  region        TEXT NOT NULL DEFAULT '',      -- 考研 A区/B区；专升本 地市（可空）
  school_id     TEXT NOT NULL DEFAULT '',
  program_id    TEXT NOT NULL DEFAULT '',
  category      TEXT NOT NULL DEFAULT '',      -- 普通类/建档立卡；学硕/专硕
  track         TEXT NOT NULL DEFAULT '',      -- 学科门类/专业大类/科类
  title         TEXT NOT NULL DEFAULT '',
  source_name   TEXT NOT NULL DEFAULT '',
```

### 5.8 写入规则

- 每个批次一个事务：upsert batch → 删旧 metrics → 插新 metrics。
- 唯一键冲突 = 覆盖；同一数据重复抓取不产生重复行。
- `checksum` 由「scope/exam/year/省/校/专业/科目值」规范化后计算，不含抓取时间。
- 抓取写入默认 `review_status='pending'`；只有复核通过（`approved`）才进入查询。人工导入默认 approved。
- `confidence < 0.8` 或同比变化 >30% 仍为 pending，并在复核页标红。
- 不删除历史年份；不 `DROP` 旧表。

## 六、查询逻辑

### 6.1 主线

- 考研：按「年份 + 省份 → A/B 区 + 学科门类 + 学硕/专硕」查 `scope='national'`。
- 专升本：按「年份 + 省份 + 科类/批次」查 `scope='provincial'`。
- 没有主线数据时，院校线也不能冒充主线；页面显示「主线未收录」。
- 同一省/年有多条主线（普通类/建档立卡、学硕/专硕、不同学科门类）且用户没选时，返回 `requires: ['category']` / `['track']`，页面提示补选，不把多条线混画。

### 6.2 院校线 / 专业线

选择院校后：

1. 有 `program_id`：**同时查** `scope='program'` 和 `scope='school'`，两者都返回；专业线不替代校线。
2. 没有 `program_id`：查 `scope='school'`；如果该校只有专业线，提示「请选择专业」。
3. 同一科目跨年份聚合；主线、校线、专业线三条都保留，图上都画，可勾选隐藏。
4. 最低分（`is_minimum=1`）单独返回，不混进分数线。

### 6.3 省份 → A/B 区

考研国家线分区固定，写在 `shared/src/score-line-region.ts`：

- A 区：北京、天津、河北、山西、辽宁、吉林、黑龙江、上海、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东、重庆、四川、陕西。
- B 区：内蒙古、广西、海南、贵州、云南、西藏、甘肃、青海、宁夏、新疆。

省份手填/选择后自动映射；映射只用于主线，不改变院校线。

## 七、服务端自动抓取（核心）

### 7.1 总体流水线

```text
定时调度 / 手动触发
  → 取 source（按 tier、next_run、启用状态）
  → 发现链接（索引页 → 年份/公告 → 附件）
  → 抓取（HTTP，限速/超时/重试）
  → 存原始快照（data/crawl/…，算 checksum）
  → 解析（html-table / xlsx / pdf-text / json）
  → 归一化（学校别名、专业名、科目名、省份/城市）
  → 校验（分值范围、年份、重复、同比异常）
  → 写库（事务、upsert、覆盖状态）
  → 发布 / 待复核
  → 记录 run + 日志 + 覆盖状态
```

### 7.2 调度

- **抓取单位 = 省份**：同一时间只跑一个省（该省的专升本 T0 省控线 + 该省 T1/T2/T3 学校），不并行多个省。这样单进程、SQLite、单服务器都扛得住，也避免一次性压垮多个站点。
- **全国单元**：考研国家线、34 所自划线汇总不按省重复抓，单独一个 `province='全国'` 队列单元，每天一次。
- 31 个省级地区组成轮转队列：按 `last_run_at` 最久 + 优先级排序，一次取一个省；一个省跑完再取下一个。
- 省内的 T0 主线每天一次；T1 自划线/双一流每周；T2 本科院校每两周；T3 专科/专升本每月。到期的省进队列，未到期不重复跑。
- 队列里已有同省任务时，不重复入队；页面「立即抓取本省」把该省插到队首（`priority=1`），但仍等当前省跑完。
- 并发：全局 1 个抓取任务；省内同一域名 1 请求/2 秒；失败退避（1h → 6h → 24h），连续 5 次失败自动禁用 source 并在覆盖页标红。
- 随机抖动 ±10%，避开整点；夜间 01:00–06:00 优先。
- 环境变量 `SCORELINE_CRAWL=off` 可关闭；`SCORELINE_CRAWL_PROVINCE_MINUTES` 控制每省最长运行时间（默认 30 分钟，超时截断并记 partial）。

### 7.3 数据源注册

- `scripts/seed-schools.ts`：导入教育部全国高校名单 → `schools` / `school_aliases`。
- `scripts/seed-sources.ts`：写入 T0（覆盖全部 31 个省级地区 + 研招网）和 T1 源；T2/T3 按「学校官网 + 已知栏目」生成候选，抓不到再标 `needs_seed`。
- 每所学校至少一条 source（研究生院/招生网/考试院对应页）；没有 URL 的学校标 `needs_seed`，运营可在覆盖页补。
- source 的 `url` 只允许服务端配置/管理员补充，**不接受普通用户传入 URL**（防 SSRF）。

#### 7.3.1 每所学校怎么找入口

1. `schools` 里先存官网；抓官网首页，匹配含「研究生院 / 研究生招生 / 招生就业 / 专升本 / 招生信息网」的链接。
2. 进栏目页，按年份和标题筛「分数线 / 复试基本分数线 / 复试线 / 招生计划 / 招生简章 / 专业目录」。
3. 附件优先 `.xlsx` / `.pdf` / `.html`；没有附件就解析正文表格。
4. 找不到入口 → `needs_seed`，覆盖页显示「缺数据源」，运营补 URL 后立即生效。
5. 研招网 / 省考试院作为交叉来源；学校官网与考试院不一致时，以学校官网原文为准并标 warning。

### 7.3.2 全国院校名单：没有现成文件时的获取与导入

当前没有现成名单文件；教育部官网对脚本访问返回 403，所以**不写自动抓取**，按下面的 SOP 做一次性导入 + 季度更新：

1. **下载**：浏览器打开教育部官网 → 政府信息公开 → 全国高等学校名单 → 最新年度，下载 `.xlsx` 或 `.pdf`；PDF 先转成表格，不 OCR。
2. **落盘**：放到 `data/imports/schools-YYYYMMDD.xlsx`（`data/` 已忽略，不入库）。
3. **导入**：`npx tsx scripts/import-schools.ts data/imports/schools-2025.xlsx`，先 `--dry-run` 看统计，再正式写。
4. **校验**：
   - 学校总数与名单一致（全国普通高校约 3,000 所）；
   - 31 个省级地区都有学校；
   - `学校标识码` 唯一，重名学校用「名称 + 省份」判重；
   - 与现有 `schools` 对比：新增 / 更名 / 合并 / 停办，输出 diff。
5. **字段映射**：
   - 学校名称 → `name`，学校标识码 → `code`；
   - 所在地 → `province` / `city`（拆「省 / 市」）；
   - 办学层次 → `level`（本科 / 专科）；
   - 主管部门、备注 → `note`；
   - `nature`（公办/民办）教育部名单通常没有：先用空串，页面显示「未标注」，后续从阳光高考/学校官网补，不阻塞查询；
   - 985/211/双一流/自划线 → `tags`，用单独名单种子，不从校名猜。
6. **更新**：每季度重跑一次；覆盖页显示 `needs_school_sync`，新增学校先入库再抓分数线。

导入脚本要求：`--dry-run` 只统计不写；重复导入按 `(name, province)` / `code` upsert；不删除旧学校，停办/合并只改 `status`。

### 7.4 解析器

| parser_id | 输入 | 依赖 | 用途 |
| --- | --- | --- | --- |
| `html-table@1` | HTML | `cheerio` | 考试院/学校公告里的表格 |
| `xlsx@1` | Excel | `xlsx`（SheetJS） | 招生计划、专业线附件 |
| `pdf-text@1` | PDF 文本层 | `pdfjs-dist` | 多数分数线 PDF |
| `json@1` | JSON | 无 | 合作方/自建数据 |
| `manual@1` | 人工导入 | 无 | 兜底 |

- 解析器按 `parser_id@version` 注册；升级解析器不覆盖旧版本，便于回放。
- 解析结果先转成统一 `RawBatch`，再进入归一化。
- PDF 无文本层（扫描件）→ `failed`，错误写「该 PDF 无文本层，需人工导入」；**不做 OCR**（避免重依赖和误识别）。
- 每个解析器必须有 fixture 测试：`server/src/score-lines/parsers/__fixtures__/`，不联网。

### 7.5 归一化

| 项 | 规则 |
| --- | --- |
| 学校名 | 精确匹配 `schools.name` → 别名表 → 去括号/后缀再匹配；仍不中 → `pending` 人工确认 |
| 专业名 | 去空格/全半角/括号方向；匹配 `school_programs.major_name`；不中则保留原文 + pending |
| 省份/城市 | 标准省名 + 城市；不中保留原文并 warning |
| 科目名 | 政治/英语一/英语二/数学一/数学二/专业课一/专业课二/总分 → 固定 code；其他按 `exam_subjects` |
| 分数 | 去「分」、全角数字、`—`/`/`；非数字 → 解析失败，不写 0 |
| 满分 | 从公告/专业目录取；取不到写 NULL，不猜 |

### 7.6 校验与复核

- 分值：`0 ≤ value ≤ full_score`（full_score 已知时）；总分不强制等于各科之和（有些省有政策分）。
- 最低分：`is_minimum=1` 必须有 `minimum_type`（admit/retest/transfer/other），否则拒绝写入；页面显示具体类型，不写裸「最低分」。
- 年份：公告年份与抓取年份不一致 → warning。
- 同比：同一学校/专业/科目比上一年变化 >30% → `pending`。
- 重复：唯一键冲突按新数据覆盖，但保留旧快照；连续两次抓取值不同且无来源变更 → pending。
- 置信度：解析器给 0–1；表格结构完整 0.9，PDF 文本 0.7，人工 1.0。
- 复核页：按学校/年份筛 pending；分数线批次和招生计划都走复核。可「通过 / 修正后通过 / 拒绝」；通过后 `review_status='approved'`，查询/专业选择器可见。
- 发布策略：**所有抓取默认 pending**，不自动对外；T0 主线也要复核（可批量通过），T2/T3 逐批抽检。复核页支持按省/学校/年份批量通过。
- 查询接口只读 `approved`；覆盖页和复核页显示 `pending` 数量与明细。

### 7.7 抓取合规

- 只抓公开页面/公开附件；不登录、不绕验证码、不抓非公开接口。
- 遵守 `robots.txt`；单域名 1 请求/2 秒；请求带明确 UA 和用途说明。
- 不把抓到的全文对外提供，只展示分数/计划等事实数据，并给出原文链接。
- 若网站条款禁止转载，只存快照供内部核对，页面不展示大段原文。

### 7.8 日志与监控

| 事件 | 字段 |
| --- | --- |
| `scoreline.crawl_started` | `runId`, `sourceId`, `tier`, `province`, `schoolId` |
| `scoreline.fetch` | `runId`, `url` 域名, `status`, `ms`, `bytes` |
| `scoreline.parse_failed` | `runId`, `parserId`, `reason` |
| `scoreline.batch_saved` | `runId`, `scope`, `year`, `schoolId`, `metrics` |
| `scoreline.coverage` | `schoolId`, `year`, `status` |
| `scoreline.crawl_finished` | `runId`, `status`, `discovered/fetched/parsed/saved/failed`, `ms` |

覆盖页显示：最后成功时间、连续失败次数、失败原因、需人工补 URL 的学校数。

## 八、接口设计

所有接口在 `requireAdmin()` 之后，前缀 `/api/admin/score-lines`。

### 8.1 院校搜索

`GET /api/admin/score-lines/schools?q=&province=&level=&exam=&year=&limit=20`

```json
{
  "schools": [
    { "id": "sch_...", "name": "示例大学", "province": "浙江", "city": "杭州", "level": "本科", "nature": "公办", "tags": ["双一流"], "planCount": 30, "coverage": { "status": "covered", "missing": [] } }
  ]
}
```

- `q` 匹配校名/别名/城市；默认 20 条，最多 50。
- 空 `q` 返回该省学校列表（按名称）；用于下拉初始项。
- 传 `exam + year` 时联查 `school_coverage` 和当年 `plan_count`，用于「专升本可查询院校列表」。

### 8.2 专业搜索

`GET /api/admin/score-lines/programs?schoolId=&year=&exam=&q=`

```json
{ "programs": [{ "id": "prg_...", "majorName": "计算机科学与技术", "degreeType": "学硕", "studyMode": "全日制", "planCount": 30, "tuition": "8000 元/年" }] }
```

- 只返回 `review_status='approved'` 的专业；pending 只出现在复核页。

### 8.3 查询

`GET /api/admin/score-lines/query?exam=&year=&province=&region=&schoolId=&programId=&category=&track=`

- 返回 6.4 的结构。
- 主线永远返回（有数据时）；校线/专业线可空。
- 只读 `review_status='approved'`；待复核数据不进查询。
- `requires` 非空时 `main` / `schoolLine` / `programLine` 为空，页面只显示补选提示。
- `coverage` 必返回，解释缺什么；另返回 `pendingCount`，页面可提示「有 N 条待复核」。
- `Cache-Control: no-store`。

### 8.4 覆盖看板

`GET /api/admin/score-lines/coverage?exam=&province=&status=&page=`

```json
{
  "summary": { "covered": 120, "partial": 80, "no_data": 900, "not_offered": 300, "failed": 12 },
  "items": [
    { "schoolId": "sch_...", "name": "示例大学", "province": "浙江", "year": 2025, "status": "partial", "missing": ["program_line"], "lastRunId": "cr_...", "lastError": "" }
  ]
}
```

### 8.5 触发抓取

`POST /api/admin/score-lines/crawl`

```json
{ "province": "浙江", "years": [2025, 2024], "force": false }
```

`province` 允许 `全国`（考研国家线/自划线汇总）。

- **一次只抓一个省**：同一时间只允许一个 `running`；其他省按队列排队。
- 页面「立即抓取本省」= 该省 `priority=1` 插到队首，但仍等当前省跑完。
- 同省已有 queued/running → 返回已有 `runId` 和 `position`，不重复入队。
- 返回 `{ runId, status: "queued", province, position }`；页面轮询 `GET /crawl/runs/:id`。
- 无 source → 409 `NO_SOURCE` + 「补数据源」链接。
- 限流：每管理员 60 秒 5 次；全局单任务。

`GET /api/admin/score-lines/crawl/queue` 返回排队中的省：

```json
{ "running": { "runId": "cr_...", "province": "江苏" }, "queue": [{ "runId": "...", "province": "浙江", "position": 1 }] }
```

`GET /api/admin/score-lines/crawl/runs/:id` 返回 run 统计和逐文档结果。

### 8.6 人工导入（兜底）

`POST /api/admin/score-lines/import`，支持 `dryRun`：

```json
{
  "dryRun": true,
  "batches": [
    {
      "scope": "program",
      "exam": "postgrad",
      "year": 2025,
      "schoolId": "sch_...",
      "programId": "prg_...",
      "category": "学硕",
      "track": "工学",
      "title": "2025 示例大学计算机学硕复试线",
      "sourceName": "示例大学研究生院",
      "sourceUrl": "https://example.com/line",
      "metrics": [
        { "subjectCode": "total", "subjectName": "总分", "fullScore": 500, "value": 320 },
        { "subjectCode": "politics", "subjectName": "政治", "fullScore": 100, "value": 50 },
        { "subjectCode": "english1", "subjectName": "英语一", "fullScore": 100, "value": 50 },
        { "subjectCode": "total", "subjectName": "总分", "fullScore": 500, "value": 312, "isMinimum": 1, "minimumType": "admit", "note": "录取最低分" }
      ]
    }
  ]
}
```

- 与抓取写同一套校验；导入默认 `review_status='approved'`（人工负责）。`isMinimum` 缺省为 0；同一科目可同时有分数线和最低分两条。
- 院校/专业不存在时先建或拒绝（建议拒绝，提示先补主表）。
- 请求体 ≤4MB，批次 ≤200。

### 8.7 复核

`GET /api/admin/score-lines/review?kind=batch|program&province=&schoolId=&year=&page=`

```json
{
  "total": 12,
  "items": [
    { "kind": "batch", "id": "slb_...", "province": "浙江", "schoolName": "示例大学", "year": 2025, "title": "…", "confidence": 0.7, "createdAt": "…" },
    { "kind": "program", "id": "prg_...", "province": "浙江", "schoolName": "示例大学", "year": 2025, "majorName": "计算机科学与技术", "planCount": 30, "tuition": "8000 元/年" }
  ]
}
```

`POST /api/admin/score-lines/review`

```json
{ "kind": "batch", "id": "slb_...", "action": "approve|reject", "note": "" }
```

- 只允许 pending；通过后查询/专业选择器可见。
- 支持批量：`{ "kind": "batch", "ids": ["..."], "action": "approve" }`，一次最多 100 条。
- 复核招生计划/学费用 `kind='program'`，与分数线分开。

## 十、权限、安全、性能

### 10.1 权限

- 全部接口 `requireAdmin()`；不新增公开路由。
- 抓取/导入/复核只允许管理员。
- 不记录学生个人信息；查询参数只含考试/地区/学校/专业。

### 10.2 安全

- **禁止 SSRF**：抓取 URL 只来自 `scoreline_sources`（服务端种子/管理员补充），不接受普通请求传入 URL；抓取前校验协议 `http/https`、禁止内网 IP/端口。
- 导入 JSON 严格校验字段、长度、数组上限；拒绝未知字段。
- 抓取内容不执行脚本、不渲染 HTML；解析只取文本/表格。
- 请求体 ≤4MB；抓取并发/限速/超时；错误不暴露路径/SQL。
- 原始快照只存服务器 `data/crawl/`，不通过静态目录对外暴露。

### 10.3 性能

- 查询按 `(school_id, year, exam)` / `(scope, exam, province, year)` 索引；一次查询最多 10 年（常量 `SCORELINE_HISTORY_YEARS = 10`）。
- 覆盖看板分页（50/页），不在前端全量拉 3,000 校。
- 抓取写库批量事务，单批 ≤500 条指标。
- 数据库体积监控：`schools` ~3k、`programs` ~30 万、`metrics` ~300 万时，备份会变大；10 年外数据可归档，`update.sh` 备份耗时需观察。
- 不缓存查询结果（避免旧数据）；页面每次查询打服务端。

用例覆盖：

### 14.2 解析器 fixture

- 每个 parser 至少 3 个样本：正常、缺列、格式变化。
- 样本放 `server/src/score-lines/parsers/__fixtures__/`，**测试不联网**。
- 解析失败必须报具体原因，不返回空数组冒充成功。

### 14.3 接口（临时 `DATA_DIR`）

1. 起服务，`/api/admin/dev-login` 拿 token。
2. 不带 token：全部 401。
3. 学校搜索：按校名/别名/城市；空 q 返回该省列表。
4. 查询：主线 + 校线 + 专业线 + 最低分 + coverage；无数据时明确空状态。
5. 导入 dry-run 不写库；正式导入后查询可见。
6. 抓取：用本地 fixture HTTP 服务模拟源，跑通 发现→抓取→解析→写库→覆盖状态；不访问真实站点。
7. 并发抓取同 source → `alreadyRunning`。
8. 复核：pending 批次 approve 后可见，reject 后不可见。
9. 分页/权限/限流。

### 14.4 页面走查

1. 空表单 → 只查主线（专升本缺省提示）。
2. 选「浙江 + 专升本 + 2025」→ 省控线 + 院校列表（计划/学费）。
3. 选「考研 + 浙江 + 某校 + 某专业」→ 国家线 + 校线 + 专业线 + 各科；切换科目看图，三条线可分别隐藏。
4. 院校无数据 → 覆盖状态文案，不显示 0。
5. 「立即抓取本省」→ 队列位置 → 当前省进度 → 自动重查；另一省在跑时按钮只入队，不并发。
6. 覆盖看板：筛选、分页、重试、补源。
7. 复核队列：pending 批次/专业可见；通过后查询出现，拒绝后消失；批量通过可用。
7. 390px：筛选/图表/表格/院校列表可用。
8. 控制台无报错、无 `NaN`/`undefined`。

### 14.5 规模/迁移

- 造 3,000 校 + 10 万指标，查询 P95 <300ms；覆盖看板分页正常。
- 用 v1.76 临时库跑迁移，考研/专升本数据可查，`cet` 等跳过且旧表仍在。

## 十六、风险与待确认

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | 全国学校太多，抓取永远追不完 | 分 T0–T3；先保证 31 省主线，再按 T1→T2→T3 铺；覆盖看板列缺口 |
| 2 | 学校官网结构各异、经常改版 | 每校/每省独立 source + parser；fixture 回归；失败标红 |
| 3 | 大量 PDF/扫描件 | 文本层 PDF 用 `pdfjs-dist`；扫描件标 failed，人工导入；不 OCR |
| 4 | 学校更名/合并/别名 | 别名表 + 人工复核；匹配不中进 pending |
| 5 | 专业名不一致 | 专业 code + 原文双存；匹配不中保留原文 |
| 6 | 各科目满分不同 | `full_score` 逐条存；未知 NULL，不猜 |
| 7 | 同比突变/脏数据 | 置信度 + 30% 异常阈值 + 复核队列 |
| 8 | 抓取被封/限流 | 限速、退避、夜间、失败自动禁用 + 告警；不绕验证码 |
| 9 | 数据库/备份变大 | 索引、分页、10 年外归档；监控 `vesta.db` 体积 |
| 10 | 页面文件超 400 行 | 按 9.3 拆；`check:size` 拦截 |
| 11 | v1 旧数据迁移错 | 只迁 postgrad/upgrade；备份；标记可重跑；旧表不删 |
| 12 | 「主线」被院校线覆盖 | 主线单独卡/单独表，永远展示；院校线为空不顶替 |
| 13 | 院校名单每年变化 | 每季度人工下载最新名单重跑导入；diff 出新增/更名/合并/停办，不删旧校，只改 `status` |
| 14 | 教育部名单没有「公办/民办」 | `nature` 允许空，页面显示「未标注」；后续从阳光高考/学校官网补，不阻塞 |
| 15 | 三种最低分同点重叠 | 不同空心形状 + 文字标签；tooltip 列全；表格分三行 |

### 待确认

无阻塞表结构的问题。唯一运营事项：上线前定「谁下载哪一年的教育部名单、什么时候导入」，写进实施排期。
