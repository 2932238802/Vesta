## 0. 结论先行

**问题不在「抓不到」这一层，而在「抓到了之后怎么判定、怎么落库、怎么把失败讲出来」这四步。**

按五环节归类，今天确认的问题集中在：

| 环节 | 核心问题 | 严重度 |
| --- | --- | --- |
| 取页 | 引导页跟随后的 document 元数据仍记首跳；种子每次启动覆盖管理员补的 `entry_url / verified` | P1 / P2 |
| 解码 | **未发现今日新增缺陷**；12 份快照 charset 抽检仍成立 | — |
| 选链 | `linkItems >= 3` 的旧启发式仍优先于显式失败，解析失败页被记成 `index` | P0 |
| 解析 | PDF / Excel / JSON 失败没有机读码；国家线来源指回专题页、`published_at` 为空 | P1 |
| 落库 | 维度字典用子串匹配，标题里的「普通高校」「教育考试院」被误标成 `普通类 / 教育`；覆盖状态 `failed / not_offered` 从未写入；失败运行不刷新覆盖表；维度 note 被异常注记覆盖；导入先校验后归一化，别名等价批次静默覆盖 | P0 / P1 |

**最高优先级三件事**：

1. **P0-1 维度误标**：`普通高校 → 普通类`、`教育考试院 → 教育`，直接改变唯一键，重复抓取会产生两套数据。
2. **P0-2 覆盖看板失败状态链路**：`failed / not_offered` 永不出现，失败运行也不刷新 `last_error`，文档承诺的「失败原因 + 下一步」看不到。
3. **P0-3 解析失败被 `index` 吞掉**：`unsupported_table` 只要页面导航链接 ≥3 条就被清成索引页，run / source 还会被判 `success`。

修复顺序建议：**P0-1 → P0-3 → P0-2 → P1**。P0-1 和 P0-3 都是「新逻辑绕过了旧判定」，先补回归用例再改，避免再次出现「修好一个、漏掉一条路径」。

## 2. 现状链路与判定点

```text
取页 fetchResource / 引导页 1 跳
  → 解码 decodeHtml（Content-Type + meta）
    → 选链 candidateLinks / discover 队列 / 列表页取最新年
      → 解析 parsers（html-table / html-category / xlsx / pdf / json / yz-topic / national-line）
        → 归一化 normalizeParsedBatch / normalizeBatchDimensions
          → 校验 validateImportPayload / anomalyIssues
            → 落库 batch-store（唯一键含 category/track）+ crawl_documents
              → 覆盖 coverage / 查询 query → 页面
```

查询 / 覆盖展示按「落库」的下游处理，不另立第六环节；解码环节本次未发现新增缺陷（12 份快照 charset 抽检仍成立），问题集中在取页元数据、选链判定、解析失败码与落库归一化。

关键判定点：

| 判定点 | 当前位置 | 当前行为 |
| --- | --- | --- |
| 引导页是否跟第二跳 | `server/src/score-lines/crawl.ts:259-310` | 跟 1 跳；但 document 元数据仍用首跳响应 |
| 页面是不是索引页 | `crawl.ts:296-298` | `result.index === true` **或** `linkItems >= 3` |
| 解析失败是否计数 | `crawl.ts:314` | 只写 details，不增加 `stats.failed` |
| 维度从哪来 | `normalize.ts:192-206` | `raw.category || inferCategory(title)`；`inferFrom()` 用 `text.includes()` |
| 批次唯一键 | `server/src/db/schema.ts:296-297` | `(scope, exam, year, province, region, school_id, program_id, category, track)` |
| 覆盖状态 | `coverage.ts:80-87` | 只写 `covered / partial / pending / no_data` |
| 覆盖失败原因 | `coverage.ts:16-24` | 只读 `crawl_runs.message`，且只在有批次 saved 时刷新 |

## 3. 问题清单（按严重度）

> 严重度定义：**P0** 会产生错误数据或让核心承诺失效，下一版本必须修；**P1** 影响排障 / 复核 / 数据可解释性，建议同轮修；**P2** 工程债 / 边界风险，可排下一轮；**P3** 清理项。

### P0-1 维度推断用子串匹配，标题里的普通词被写成 category / track

- **根因环节**：落库（归一化）；解析结果本身没有维度，靠标题补，属于落库前的二次推断。
- **证据**：
  - `shared/src/score-line-dimension.ts:31`：`普通类` 的别名包含 `普通`；`:60`：`教育` 本身就是专升本 track 值。
  - `server/src/score-lines/normalize.ts:51-61`：`inferFrom()` 用 `text.includes(key)`，取最长命中。
  - 实测：`inferCategory('…2026年浙江省普通高校专升本招生各类别最低控制分数线通告','upgrade')` → `普通类`；同标题 `inferTrack` → `教育`。
  - 文档口径：第 7 篇 §4.5 与第 9 篇附录都写浙江 `category` 应留空（`7-…md:196-197`、`9-…md:1271`）。
- **触发**：任何标题含「普通高校」「教育考试院」的专升本批次，且 `raw.category` / `raw.track` 为空。
- **影响**：
  - 唯一键包含 `category/track`（`schema.ts:296-297`），重新抓取会写入与旧数据不同键的新批次，复核后同省同年同科类出现两套数据；
  - `buildLine()` / `buildSeries()` 会把同一年同科目合并成重复点（`query.ts:84-139`）；
  - 旧库迁移 `migrateScoreLineV1()` 也用同一套推断（`migrations.ts:615-616`），历史标题会被误标。
- **现状与文档冲突**：v1.82 文档写「认不出返回空、不猜」，实际是在猜。

### P0-2 覆盖看板的 `failed / not_offered` 永不出现，失败运行也不刷新 `last_error`

- **根因环节**：落库（覆盖状态计算）+ 取页/解析（失败运行没有回写）。
- **证据**：
  - `coverage.ts:80-87` 只生成 `covered / partial / pending / no_data`；`shared/src/score-line.ts:38-45` 却暴露 `failed`、`not_offered` 标签，前端筛选和统计都包含它们。
  - `crawl.ts:213-217` 只在有批次 `saved` 时调用 `refreshCoverage / refreshProvinceCoverage`；全失败（`saved=0`）时不刷新。
  - `coverage.ts:16-24` 的 `lastRun()` 只取 `crawl_runs.message`，不取 `status`；失败运行没有批次时，`school_coverage.last_error` 保持空值或旧值。
  - `docs/README.md:286/290` 明确写「失败原因写进覆盖看板」「抓不到时覆盖看板标 `failed`」。
- **触发**：任何省份一次抓取全部失败；任何学校该年没有任何 approved 数据。
- **影响**：运营看到的是 `no_data` + 空失败原因，无法区分「该省没发布」「入口没核验」「解析器不适配」「站点拦截」；「抓取失败」筛选永远是空。

### P0-3 `index` 优先级仍会吞掉解析失败，且解析失败不计入失败数

- **根因环节**：选链（索引页判定）+ 解析（失败计数）。
- **证据**：
  - `crawl.ts:296-298`：`isIndex = result.index === true || (result.linkItems?.length ?? 0) >= 3`，随后 `error = result.batches.length || isIndex ? '' : codedError(result)`。
  - `html-table@1` / `html-category@1` 解析失败时会同时返回候选链接（`parsers/html.ts:58-70`、`parsers/category-table.ts:248-262`）；只要导航链接 ≥3 条，`unsupported_table` 就被清成 `index`。
  - `crawl.ts:314` 只把失败码塞进 `details`，`stats.failed` 只统计网络异常和写库失败（`:194`、`:200`、`:317`）；9 页解析失败 + 1 条保存成功时，run 仍判 `success`（`:435`、`:446`）。
  - 第 9 篇 §10.3 第 4 项已明确这项「仍未做」，但 `99a2d67` 只给 `yz-topic` 加了显式 `index`，没有改旧启发式的优先级。
- **触发**：任何「有表格但形状不认」且页面导航链接较多的公告页。
- **影响**：失败码 / 失败页数 / 覆盖提示全部丢失；排障只能看 `shape`，不能按码给下一步。

### P1-4 维度认不出的 note 会被异常注记整段覆盖

- **根因环节**：落库。
- **证据**：`normalize.ts:204-222` 把「批次 / 学位类型认不出：X」写进 `note`，并把 `confidence` 降到 0.7；`crawl.ts:206-208` 随后执行 `if (anomalies.length) normalized.batch.note = anomalies.join('；')`；`validate.ts:9-11` 对 `<0.8` 必生成「解析置信度偏低」。
- **影响**：复核员只看到置信度，看不到原始维度值和认不出的原因，无法修正。

### P1-5 只有 pending 主线时查询返回 `no_data`；考研国家线 pending 永远不计入

- **根因环节**：落库 / 查询。
- **证据**：`query.ts:268-283` 无院校时 `status: hasMain ? 'covered' : 'no_data'`，完全忽略同对象的 `pendingCount`；`pendingBatchCount({ province: schoolProvince })` 只按省过滤，而国家线落库 `province=''`。
- **影响**：页面把「已抓到、待复核」误报成「主线未收录」；v1.82 新抓的 28 条国家线 pending 在查询侧不可见。

### P1-6 人工导入先校验、后归一化，别名等价批次静默互相覆盖

- **根因环节**：落库。
- **证据**：`routes/admin/score-lines-import.ts:76-87` 先 `validateImportPayload(body)`，再把 `normalizeImportBatch` + `normalizeBatchDimensions` 映射；`shared/src/score-line.ts:428-443` 只做单批次校验，没有跨批次唯一键检查；`batch-store.ts:108-152` 按唯一键覆盖。
- **触发**：同一逻辑批次分别写 `category = 学术学位 / 学硕` 或 `track = 文史类 / 文史`。
- **实测**：两条都能通过校验，`normalizeDimension` 都落到 `学硕`；dryRun 报 2 条，实际只留 1 条。
- **影响**：导入结果与 dryRun 不一致，且不报错。

### P1-7 国家线 `category=''` 与导入模板 `category='学硕'` 混用，查询不提示歧义

- **根因环节**：解析 / 落库。
- **证据**：`parsers/national-line.ts:131/145` 写 `category: ''`；`web/src/views/admin/score-lines/ImportDialog.vue:45` 的示例写 `category: '学硕'`；`query.ts:75-82` 的 `ambiguity()` 用 `.filter(Boolean)` 丢掉空串。
- **影响**：先抓取（空）再按模板导入（学硕）时，`requires` 不会提示补选，`buildLine()` 把两批指标合并到同一年，可能生成重复点。

### P1-8 国家线批次丢失公告页来源，`published_at` 为空

- **根因环节**：解析 / 落库。
- **证据**：`crawl.ts:163-173` 的 `contextFor()` 固定 `sourceUrl: source.url`，`processPage()` 每页复用同一个 `context`；`national-line.ts:135/149` 直接 `sourceUrl: context.sourceUrl`，且不写 `publishedAt`。
- **影响**：28 条国家线的 `source_url` 全部指回 `lnfsx.shtml` 专题页，PDF 兜底更无法定位到具体文件；不满足第 1 篇 AC9「每个数字可追溯到来源链接和抓取时间」。

### P1-9 引导页跟随后，document 元数据仍记首跳

- **根因环节**：取页 / 落库。
- **证据**：`crawl.ts:259-310`：第二跳响应放在局部 `second`，后续 `saveSnapshot(content, fetched.contentType, finalUrl)`、`httpStatus: fetched.httpStatus`、`contentType: fetched.contentType` 仍用第一跳。
- **影响**：首跳 HTML、第二跳 PDF/Excel 时，快照扩展名、content_type、http_status 全部对不上，排障会误判。

### P1-10 PDF / Excel / JSON 解析失败没有机读码

- **根因环节**：解析。
- **证据**：`parsers/pdf.ts:31-40`、`xlsx.ts:29-32`、`json.ts:45-50` 失败时只返回 `issues`，不返回 `failure`；`crawl.ts:176-179` 的 `codedError()` 只能写中文句子或 `parse: …`。
- **影响**：v1.82 的 Content-Type 分派把更多页面送进这些解析器，失败后没有 `no_text_layer / unsupported_table / decode` 等码，覆盖页无法按码给下一步。

### P2-11 来源种子每次启动覆盖管理员补的 `entry_url / verified`

- **根因环节**：取页 / 配置。
- **证据**：`sources.ts:196-230` 的 `ON CONFLICT(id) DO UPDATE` 每次重写 `url / entry_url / parser_id / verified`，只保留 `enabled` 和 last_run；`migrations.ts:543` 每次启动调用。
- **影响**：通过 `POST /score-lines/sources` 改的入口会在下次重启被改回；第 1 篇 §7.3.1「运营补 URL 后立即生效」实际只能靠改代码常量。

### P2-12 人工导入的维度归一化不降置信度、不记 issue

- **根因环节**：落库。
- **证据**：`normalize.ts:118-125` 的 `normalizeBatchDimensions()` 把 `issues` 传空数组，也不调整 `confidence`；导入路径直接用它。
- **影响**：与抓取路径「认不出 → 0.7 + note」不一致；人工导入的未知维度仍以 confidence=1 进入待复核队列。

### P2-13 只有索引页的 run / source 仍被判 `failed`

- **根因环节**：解析 / 落库。
- **证据**：`crawl.ts:435/446` 的 `status = saved > 0 ? … : 'failed'`；索引页不增加 `saved`（也不增加 `failed`）。
- **影响**：`crawl_documents.parse_status='index'` 的修复只在 document 层生效，run / source 层仍显示失败，和 `99a2d67` 的提交说明不一致。

### P2-14 覆盖页的失败码翻译对多数 run 失效

- **根因环节**：落库 / 展示。
- **证据**：`crawl.ts:314` 把每条写成 `${url}：${error}`，`run.message` 以 URL 开头；`shared/src/score-line.ts:286-294` 的 `crawlFailureHint()` 是行首锚定。
- **影响**：只有被 `unshift` 到首位的 `needs_seed` 能翻译，其余失败码原样展示。

### P2-15 覆盖刷新按每条批次调用，存在写放大

- **根因环节**：落库。
- **证据**：`crawl.ts:213-217` 对每条保存的批次调用 `refreshProvinceCoverage()`；一页 8 条类别批次会把全省学校重算 8 次。
- **影响**：学校多时是 O(批次数 × 学校数) 的写放大；当前数据量可能可接受，但铺开后是隐患。

### P3-16 前端 `AdminCrawlRunDetail.documents` 与后端字段漂移

- `web/src/api/types.ts:108-119` 缺 `note / shape`；后端 `crawl.ts:66` 已返回。当前没有页面消费，暂不影响运行。

### P3-17 设计文档中的退避 / 自动禁用尚未实现

- 第 1 篇 §7.2 写「失败退避 1h→6h→24h，连续 5 次失败自动禁用并标红」；`crawl-scheduler.ts:7-44` 只有固定间隔检查，schema 没有失败计数字段。
- 建议明确标为 Phase 2，或在 `scoreline_sources` 增加 `consecutive_failures / disabled_reason` 后实现；不要继续让设计文档被当成已实现。

## 4. 修复方案（分层）

### L0：先把口径钉死（文档先行）

1. **维度匹配规则**：定义「精确值 → 显式别名 → 不猜」；别名必须满足长度 ≥ 3 或带业务后缀（`…类 / …考生 / …计划 / …专项`），且**不从纯标题推断 `track`**，除非标题明确出现科类词（如「理工类」）。
2. **覆盖状态语义**：
   - `failed`：最近一次抓取失败且没有任何可复核数据；
   - `no_data`：抓取成功但官方未发布；
   - `not_offered`：人工确认该省 / 校该年不招；
   - 「该省无统一控制线」建议落到 `not_offered` 或新增独立原因字段，不能继续混进 `no_data`。
3. **失败码表**：补充 `no_text_layer`（扫描件 PDF）、`parse`（通用解析失败）、`entry_redirect` 等；所有解析器返回 `failure.code`。
4. **来源追溯**：`sourceUrl` 必须是实际公告页，`publishedAt` 必须来自页面或文件名，不允许回填专题页。

### L1：解析层（解析 / 选链）

1. **`inferFrom()` 改为严格匹配**（`server/src/score-lines/normalize.ts`）：
   - 先精确匹配 canonical 值；
   - 再匹配白名单别名；别名按长度降序，且必须满足边界条件（前后不是汉字，或命中明确后缀）；
   - 仍认不出返回 `''`，并写 `note`。
   - **建议直接移除 `普通` 这类 2 字泛别名**；`教育` 作为 canonical 值只在标题出现「教育类」等明确后缀时命中。
2. **索引页判定**（`crawl.ts:296-298`）：只在 `result.index === true` 时为 `index`；`linkItems >= 3` 不再覆盖 `failure`。如果解析器确实只想返回链接，由解析器显式设置 `index: true`。
3. **解析失败计数**（`crawl.ts:314`）：`result.failure` 存在时 `stats.failed += 1`；run / source 的 `failed` 统计包含解析失败。
4. **所有解析器返回 `failure`**：`pdf.ts` / `xlsx.ts` / `json.ts` 补 `failure: { code, detail }`；`codedError()` 不再需要中文兜底。
5. **页面级 context**（`crawl.ts`）：把当前页 URL / publishedAt 传进 `parseContent`，`national-line.ts` 用当前页而不是 `source.url`。

### L2：落库层（归一化 / 覆盖 / 导入）

1. **note 合并**：`crawl.ts:206-208` 改为 `note = [normalized.batch.note, ...anomalies].filter(Boolean).join('；')`，不覆盖维度 issue。
2. **覆盖刷新**：
   - `coverage.ts` 的 `lastRun()` 同时取 `status` 和 `message`；
   - 无任何数据且最近一次 run `failed` → `status='failed'`；有 pending → `pending`；否则 `no_data`；
   - `crawl.ts` 在 run 结束时（无论 saved 是否为 0）刷新该省 / 该校覆盖；
   - `last_error` 取 run 的首个失败码，而不是拼接后的 URL 文本。
3. **覆盖写放大**：`refreshProvinceCoverage()` 在 run 结束统一调用一次，不在每条批次保存时调用；单校批次仍可即时刷新。
4. **导入顺序**：先 `normalizeImportBatch` + `normalizeBatchDimensions`，再 `validateImportPayload`；校验增加跨批次唯一键去重，重复键报错而不是静默覆盖。
5. **人工导入维度**：`normalizeBatchDimensions()` 返回 `issues` 并降 `confidence`，与抓取路径一致。
6. **pending 计数**：
   - 无院校查询：`pendingCount > 0` 时 `status='pending'`；
   - `pendingBatchCount()` 支持 `scope` / `region`，国家线（`province=''`）按 `scope='national' + region` 计入。
7. **国家线 category**：统一空值语义；`ambiguity()` 把空串当成「未标注」参与歧义判断（例如同时存在空和 `学硕` 时提示补选），导入模板示例改为空或明确说明「国家线不区分学硕 / 专硕」。

### L3：查询 / 展示层

1. 覆盖页状态 chip 真正显示 `failed / not_offered`；失败原因按码翻译。
2. `ScoreLines.vue` 的 `emptyMainText` 在 `coverage.status === 'pending'` 时显示待复核；国家线 pending 也要能触发。
3. `crawlFailureHint()` 不再只匹配行首：让后端把 `failure_code` 单独存一列或放在 `last_error` 首位，避免前端猜。

### L4：调度 / 运维

1. **种子覆盖策略**：插入时写默认值；已存在的行只更新 `url / parser_id` 等由代码定义的字段，`entry_url / verified` 以库内管理员值为准；或在 `scoreline_sources` 增加 `source_of_truth` / `verified_by` 字段。需要产品确认「代码常量 vs 库内值」谁优先。
2. **退避 / 自动禁用**：标为 Phase 2，或在 schema 增加 `consecutive_failures` 后实现；不要继续写在 Phase 1 文档里。
3. **索引页 run 状态**：区分 `success`（有 saved）、`partial`（有 saved + failed）、`index`（只有索引页）、`failed`（无 saved 且有失败）。`CrawlStatus` 需要同步扩展。

## 5. 为什么是这套，不是别的

| 备选方案 | 为什么不选 |
| --- | --- |
| 只改文档，让文档承认现状（如把 `failed` 从文档删掉） | 第 1 篇 AC7 / AC9 与运营需求都要求区分失败原因；删掉状态会把「没数据」和「抓失败」永久混在一起，后续无法补数据 |
| 直接删除标题推断，一律只信解析器返回的维度 | 能消除误标，但会让大量只有标题、没有维度列的公告失去补全能力；v1.82 的目标就是补维度。更合适的是「严格匹配 + 认不出留空」，不是退回零推断 |
| 重写整个解析器框架 | 今天的问题集中在归一化和判定，不在解析器架构；重写风险和验证成本远高于局部修复 |
| 把覆盖刷新放到前端轮询时顺带算 | 状态需要跨请求稳定，且抓取任务结束后才有最终结果；应落在抓取完成点，不是展示层 |
| 给每个省份手动标 `failed` | 无法随抓取结果自动更新；且会把「官方未发布」误标成失败。应由 run 结果驱动，`not_offered` 才用人工确认 |
| 引入独立抓取服务 / 消息队列 | 当前是单进程、SQLite、单实例部署，问题不在这里；引入新基础设施会扩大回滚面 |

## 6. 验证计划

> 本节包含最小验证与完整回归，不单独设「MVP」主线。

### 6.1 纯函数 / fixture（不写库）

1. **维度**：
   - 浙江标题 → `category=''`、`track` 取表格列值，不为 `教育`；
   - `普通高校` 不命中 `普通类`；`教育考试院` 不命中 `教育`；
   - `文史类 / 文史`、`学术学位 / 学硕` 仍能归一到 canonical。
2. **索引 / 失败**：
   - 有表格但解析失败 + 3 条导航链接 → `parseStatus='failed'`、`error` 保留 `unsupported_table`；
   - `yz-topic` 专题 / 文章页 → `index:true`；
   - PDF / Excel / JSON 失败 → 有 `failure.code`。
3. **note**：维度认不出 + 置信度偏低 → 两条 note 都在。
4. **导入**：`学硕` / `学术学位` 两条 → 校验阶段报重复键；dryRun 条数与实际写入一致。
5. **查询**：只有 pending 主线 → `status='pending'`；国家线 pending 计入。

### 6.2 临时 `DATA_DIR` 端到端

- 本地 fixture HTTP 模拟「引导页 → 列表 → 公告」：
  - 全部失败 → 覆盖页 `failed` + 失败码 + 下一步；
  - 部分成功 → `partial`，失败数不为 0；
  - 索引页 run → 不误判 `failed`。
- 导入别名重复 → 400 或去重提示，不静默覆盖。
- 数据全部写临时目录，不碰 `data/vesta.db`。

### 6.3 只读回归

- 对真实站点只读抓 1 页（浙江 / 研招网），确认 `source_url` 指向公告页、`publishedAt` 非空。
- 老库迁移副本：合法 / 损坏问卷 JSON 都能启动，不出现 `malformed JSON`。

### 6.4 工程门槛

- 改后端：`npm run typecheck`；改前端：`npm run typecheck && npm run build`。
- 全部：`npm run verify` 全绿后提交。
