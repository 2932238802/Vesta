# 删除「简历收集」· 开发文档

> 版本：v1.0（2026-11-14）　状态：**已实施并提交（产品版本 v1.76，commit `ba57bb6`）**
> 一句话：把后台「简历」栏目、`/admin/resumes` 页面、简历图片接口和共享专业清单整体下线；**数据库里的存量简历图片保留不删**，需要时可回滚或单独导出。
> 需求来源：2026-11-14 用户口头提出——删除「简历收集」。
> 目录索引：[README.md](./README.md)。

## 一、需求与边界

| 项 | 结论 |
| --- | --- |
| 删除范围 | 侧栏「简历」组、`/admin/resumes` 页面、4 个管理端接口、前端 4 个 client 方法、共享专业清单、上传 helper |
| 保留 | `resume_images` 表及其中已上传的图片；历史提交与 `docs/archive/` 里的旧文档 |
| 不做 | 不 `DROP TABLE`、不删除数据库文件、不清理 `data/backups/`、不改 `update.sh` |
| 公开页 | 无影响；简历收集本来就没有学生端入口 |
| 报告 / 问卷 / 咨询 | 无影响；没有代码引用简历模块 |

**删除后的直接结果**：后台少一个栏目；收藏 `/admin/resumes` 的链接会落到 404；`/api/admin/resumes` 带令牌返回 404、不带令牌仍先返回 401。已上传图片在数据库里继续存在，但界面不再提供查看 / 下载。

### 3.4 数据表

**保留 `server/src/db/schema.ts` 的 `resume_images` 表定义**，只改注释：

```sql
-- 历史数据：简历收集已于 2026-11 下线，代码不再读写；
-- 存量图片保留在库中，便于回滚或人工导出。确认清理前不要 DROP。
CREATE TABLE IF NOT EXISTS resume_images (
  ...
);
CREATE INDEX IF NOT EXISTS idx_resume_images_major ON resume_images(major, created_at DESC);
```

原因：

- 删除表 = 不可逆的数据丢失，违反「修改或清理数据库前先备份、不要直接重置用户数据」的约束。
- 这与 v1.74 处理 `roster_groups` / `roster_hidden_dates` 的口径一致：功能下线、表保留、不读写。
- 新部署会建一张空表，成本可忽略；保留定义让「回滚旧代码」和「未来人工导出」都有稳定结构。

**不做迁移**：不改 `migrations.ts`，不 `ALTER`，不 `DROP`。

### 3.5 配置（本轮不改）

`deploy/nginx.conf` 的 `client_max_body_size 25m` 当初是因为简历图片 20MB 上传。简历功能删除后，最大的请求体是 `express.json({ limit: '4mb' })` 范围内的 JSON，理论上可以下调到 `5m`。

但本轮**不改**，原因：

1. 属于部署配置，改了要单独验证 Nginx 重载 / 生产网关是否用这份模板；
2. 下调与「删除简历收集」不是同一件事，混在一起会让回滚面变大；
3. 保留 25m 不影响功能，只是放宽了上限。

处理：只更新 `docs/README.md` 的说明，把「为简历上传调大」改成历史原因；是否下调另开小改动，单独确认。

## 六、发布与回滚

### 6.1 发布

- 前端删除页面与路由、后端卸载接口，属于纯代码下线；`bash update.sh` 正常构建、重启即可。
- **上线前备份**：`update.sh` 会 `VACUUM INTO` 备份；如手工部署，先执行
  `node deploy/backup.mjs data/vesta.db data/backups/vesta-YYYYMMDD-HHMMSS.db`。
- `resume_images` 表保留，启动时 `initSchema()` 的 `CREATE TABLE IF NOT EXISTS` 不会动它。

### 6.2 回滚

- `git revert` 本次提交 + `bash update.sh`：页面、路由、接口、导航全部恢复。
- 数据一直在 `resume_images`，回滚后旧页面直接可读，无需恢复备份。
- 如果以后确认永不使用、要回收空间：先备份，再单独确认 `DROP TABLE resume_images`；**不要并入本次提交**。

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | 有人收藏了 `/admin/resumes`，删除后 404 | 产品确认接受；如不接受，加一条 `redirect: { name: 'admin-dashboard' }`（但这等于隐藏删除，不推荐） |
