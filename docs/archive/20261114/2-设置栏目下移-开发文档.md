## 一、需求与边界

| 项 | 结论 |
| --- | --- |
| 目标 | 「设置」是栏目列表的**最后一项**（含它自己的三个子链接） |
| 最终顺序（第 1 篇上线后） | 问卷 → 咨询 → 分数线 → 设置 |
| 只做本项时的顺序（第 1 篇未上线） | 问卷 → 咨询 → 设置 |
| 子链接 | 问卷设置、报告设置、AI 分析规则三项目录不变，仍在「设置」组内 |
| 不改 | 路由路径、`meta.settings`、`SettingsNav.vue`、任何页面内容、任何接口 |

**为什么放最后**：设置是低频维护入口，不该占第二高位；问卷 / 咨询是日常入口，分数线是查询入口，都应排在设置之前。

## 二、现状（代码事实）

`web/src/views/admin/AdminLayout.vue` 的 `<nav>`（L25–L139）里四段 `<section class="nav-group">`：

| 顺序 | 栏目 | 模板行 | 子链接 |
| --- | --- | --- | --- |
| 1 | 问卷 | L26–L52 | 概览、邀请链接、学员名单 |

设置相关但**不需要动**的部分：

- `NavGroup` 类型（L172）与 `groups` 初值（L178–L183）只按 key 存状态，**与顺序无关**。
- `activeGroup`（L185–L204）按 `route.path` 前缀判断，设置页仍返回 `'settings'`。
- `localStorage['vesta.admin.navGroups']` 存的是 `{ survey, settings, consult, resume }`，不是数组，移动位置不会读错。
- `SettingsNav.vue` 由 `route.meta.settings` 控制（L157），与侧栏顺序无关。
- 路由 `/admin/survey`、`/admin/report`、`/admin/skill` 均带 `meta: { settings: true }`（`web/src/router.ts` L56–L58），不动。

## 三、实施

### 3.1 唯一改法：移动模板块

1. 在 `AdminLayout.vue` 里**整段剪下**设置 `<section>`（L54–L80，从 `<section class="nav-group">` 到对应的 `</section>`）。
2. 粘贴到「咨询」`<section>` 之后；如果第 1 篇的「分数线」已加，则粘贴到「分数线」`<section>` 之后。
3. 保证它是 `<nav>` 里最后一个 `<section>`。
4. 不新增、不删除、不改写任何 `RouterLink` / `@click` / `:aria-expanded` / `:class` 绑定。

移动后的结构：

```html
<nav class="nav" aria-label="后台导航">
  <section class="nav-group">…问卷…</section>
  <section class="nav-group">…咨询…</section>
  <section class="nav-group">…分数线（第 1 篇新增，若已做）…</section>
  <section class="nav-group">…设置…</section>
</nav>
```

### 3.2 不要用 CSS `order` 代替移动 DOM

- 桌面端 `.nav` 是 `display: grid`，移动端（`@media (max-width: 900px)`）变成 `display: flex; flex-wrap: wrap`，并且 `.nav-group` / `.nav-links` 设为 `display: contents`（L518–L536）。
- 对 `display: contents` 的容器用 `order` 在不同浏览器里表现不一致；而且 DOM 顺序同时决定 Tab 键顺序和读屏顺序。
- 所以必须**移动模板块**，不写 `order: 99`。

### 3.3 同步文档

`docs/README.md`「主要页面」当前写「后台按四个栏目组织」，顺序是问卷 / 设置 / 咨询 / 简历。本项实施后先改为「问卷 / 咨询 / 设置」；第 1 篇的分数线上线后，最终为「问卷 / 咨询 / 分数线 / 设置」。同时在 `development-history.md` 本轮小节记一句「设置下移，因为它是低频维护入口」。

### 5.2 手工

1. **桌面**：侧栏从上到下依次是 问卷、咨询、分数线（若已做）、设置；设置在最下方。

## 六、风险与回滚

| 风险 | 处理 |
| --- | --- |
| 移动时漏掉 `</section>` 或把相邻块带进去 | 用编辑器整块剪切，移动后跑 `npm run build`；模板缩进不参与判定，结构正确即可 |
| 移动端顺序与桌面不一致 | 已确认 `.nav` 在移动端用 DOM 顺序；手工走查 390px |
| 设置组折叠状态丢失 | key 未变，`restoreLayout()` 仍按 `saved.settings !== false` 读取；走查第 5 条 |
| 与第 1 / 3 篇同文件冲突 | 按 README 建议顺序 `3 → 2 → 1` 实施（本项在分数线之前）；若三项合并，最后做本项；同一文件不要并行改 |

**回滚**：`git revert` 本次提交即可，纯模板移动，无数据 / 路由影响。
