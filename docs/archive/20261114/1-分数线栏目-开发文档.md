## 一、需求口径与边界

### 1.1 已确认

| # | 结论 | 说明 |
| --- | --- | --- |
| 1 | 后台新增一个栏目，名称 **分数线** | 与「问卷 / 咨询 / 设置」同级，位置在「咨询」之后、「设置」之前 |
| 2 | 结构要能容纳**后续多种分数线** | 新增类型不改数据库表；新增年份 / 地区 / 来源只新增数据 |
| 3 | 分数线由管理员**人工录入**，带来源 | 不从网上抓取，不预置任何真实分数线数字 |
| 4 | 仅管理后台内部查询 | 本轮不加公开页、不写进 AI 报告、不改问卷 |

### 1.2 不在本轮范围

- 不做自动抓取 / 官方接口同步 / 定时更新。
- 不做批量导入（Excel / CSV / 粘贴）——列为后续增强，表结构不用改。
- 不把分数线注入报告或咨询稿。报告侧继续只使用博查检索到的原文，并受 `shared/src/doc-skill.ts`「不得虚构分数线」约束。
- 不做学生端展示、不做权限分级（管理端目前只有一套管理员账号）。
- 不做历史版本对比 / 变更留痕（只保留 `createdAt` / `updatedAt`）。

### 1.3 为什么不能直接写进报告

`shared/src/doc-skill.ts` L15、L79 与 `shared/src/ai.ts` L83、L111 都明确要求：不得虚构分数线、院校要求、报名时间。分数线是**会随年份和专业变化的外部事实**，本轮只作为后台查询参考；要进报告必须另做「来源核验 + 年份匹配 + 引用链接」方案，不能因为后台有这张表就直接喂给 AI。

## 三、结构设计（核心）

### 3.1 三层模型

```text
类型（考试 / 业务类别，代码常量）
  └─ 数据集 score_line_sets（一条 = 某年 + 某地区 + 某来源的一批线）
       └─ 条目 score_line_entries（一行 = 一个具体数值：总分 / 单科 / 某专业线）
```

| 层 | 例子 | 为什么单独一层 |
| --- | --- | --- |
| 类型 | 考研、四六级、专升本、教资、考公 | 决定列表页 tab 和录入表单的类型选项；**加类型只加常量** |
| 数据集 | 「2026 考研国家线（A 区）」 | 同一年同一地区的一批线一起维护、一起给来源；避免每条都重复年份 / 来源 |
| 条目 | 总分 273、英语一 38、单科（满分>100）57 | 行数不固定，不同考试差异大；一行一个数值才能排序、校验、换行展示 |

### 3.2 为什么类型放代码、数据放表

- 类型是**受控词表**：写错一个字符串就会出现一个空 tab；放代码里用 `scoreLineCategoryIds` 校验，前后端共用，不会漂移。
- 加类型成本极低：在 `shared/src/score-line.ts` 的数组里加一行（如 `{ id: 'ielts', name: '雅思' }`），下次部署即可用，**不需要建表、不需要迁移**。
- 如果以后运营要自己加类型，再单独加 `score_line_categories` 表即可；`score_line_sets.category_id` 仍是字符串，迁移只是把常量来源换掉，不动 set / entry 表。
- **类型 id 一旦上线就不要改**；改显示名只改 `name`。从注册表移除某个类型不会删数据，只是页面不再展示，把常量加回即可恢复。

### 3.3 扩展场景对照

| 后续变化 | 要改什么 | 不用改什么 |
| --- | --- | --- |
| 新增类型（如 雅思、计算机二级） | `shared/src/score-line.ts` 加一行常量 | 表结构、接口、页面组件 |
| 新增年份 / 地区 / 院校 | 页面「新增分数线」录入 | 表结构、代码 |
| 新增一种数值维度（如「单科满分」） | 条目名称写清楚，或加一个 `note` | 表结构 |
| 批量导入 | 另开方案，复用同一套校验 | 表结构 |
| 接入报告引用 | 另开方案，读 `score_line_sets` + 来源链接 | 表结构 |

**明确不做的「扩展」**：不把分数线做成无限列的宽表（加一种考试就加一批字段），也不做成纯 JSON 大字段（无法校验、无法排序、无法按年份筛）。

### 4.1 字段约定

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `categoryId` | string | 必须在 `scoreLineCategoryIds` 里 | 类型 |
| `title` | string | 必填，1–120 字 | 如「2026 考研国家线（A 区）」 |
| `year` | number | 0 或 2000–2100 | `0` = 未标年份；列表排最后 |
| `region` | string | 可空，≤20 字 | 「A 区」「全国」「浙江」 |
| `sourceName` | string | 必填，1–80 字 | 如「教育部」「浙江省教育考试院」 |
| `sourceUrl` | string | 可空，≤500 字，必须 `http://` / `https://` 开头 | 官方原文链接 |
| `note` | string | 可空，≤500 字 | 口径说明、适用专业等 |
| `entries` | array | 1–100 条 | 至少一条，否则没有可看的内容 |
| `entries[].label` | string | 必填，1–40 字 | 「总分」「英语一」「计算机科学与技术（学硕）」 |
| `entries[].value` | number | 有限数，0–1000 | 分数 |
| `entries[].maxValue` | number \| null | 可空；若填，需 0 < 值 ≤ 1000 | 满分，用于显示 `273 / 500` |
| `entries[].note` | string | 可空，≤100 字 | 「满分 100」「仅限学硕」 |

### 4.2 校验规则（错误文案直接给用户）

| 检查 | 错误文案 |
| --- | --- |
| 类型不在注册表 | `请选择分数线类型` |
| 标题空 / 超长 | `请填写标题` / `标题最多 120 个字` |
| 年份非法 | `年份需在 2000–2100 之间，或留空` |
| 地区超长 | `地区最多 20 个字` |
| 来源空 / 超长 | `请填写来源` / `来源最多 80 个字` |
| 链接协议不对 | `来源链接需以 http:// 或 https:// 开头` |
| 说明超长 | `说明最多 500 个字` |
| 条目为空 / 超量 | `至少填写一条分数线` / `最多 100 条分数线` |
| 条目名空 / 超长 | `第 N 条：名称不能为空` / `第 N 条：名称最多 40 个字` |
| 分数非法 | `第 N 条：分数需在 0–1000 之间` |
| 满分非法 | `第 N 条：满分需大于 0 且不超过 1000` |
| 分数大于满分 | `第 N 条：分数不能大于满分` |
| 条目说明超长 | `第 N 条：备注最多 100 个字` |

`N` 从 1 开始，和页面上的行号一致。

## 五、数据库

### 5.1 表结构

加在 `server/src/db/schema.ts` 的 `initSchema()` 末尾（与现有表的先后顺序无关）：

```sql
CREATE TABLE IF NOT EXISTS score_line_sets (
  id          TEXT PRIMARY KEY,
  category_id TEXT NOT NULL,
  title       TEXT NOT NULL,
  year        INTEGER NOT NULL DEFAULT 0,
  region      TEXT NOT NULL DEFAULT '',
  source_name TEXT NOT NULL DEFAULT '',
  source_url  TEXT NOT NULL DEFAULT '',
  note        TEXT NOT NULL DEFAULT '',
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_score_line_sets_category
  ON score_line_sets(category_id, year DESC, updated_at DESC);

CREATE TABLE IF NOT EXISTS score_line_entries (
  id         TEXT PRIMARY KEY,
  set_id     TEXT NOT NULL,
  label      TEXT NOT NULL,
  value      REAL NOT NULL,
  max_value  REAL,
  note       TEXT NOT NULL DEFAULT '',
  sort_order INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_score_line_entries_set
  ON score_line_entries(set_id, sort_order);
```

### 5.2 迁移策略

- 两张都是**新表**，`CREATE TABLE IF NOT EXISTS` 可重复执行；已有数据库启动时自动补建，不需要 `ALTER TABLE`，也不需要改 `migrations.ts`。
- 不做 `DROP`、不重建、不动任何现有表。
- 不需要回填。**不预置任何分数线数据**——空表比编造数字安全。
- 删除数据集时，路由层在同一个事务里先删 `score_line_entries` 再删 `score_line_sets`（SQLite 未开外键级联，不依赖 `FOREIGN KEY`）。

### 5.3 为什么用两张表而不是一张

一条分数线数据集通常有 5–30 个条目（总分、各科、各专业）；放一张表要么 JSON 大字段（无法按条目校验 / 排序），要么每行重复标题 / 年份 / 来源（更新来源要改十几行）。两张表让「数据集元信息」和「数值行」各自只存一份，编辑时整组替换，事务保证不出现半套数据。

## 六、后端接口

新增 `server/src/routes/admin/score-lines.ts`（目标 ≤300 行），在 `server/src/routes/admin/index.ts` 的 `requireAdmin()` 之后挂载：

```ts
import { scoreLinesRouter } from './score-lines'
```

### 6.1 接口清单

| 方法 | 路径 | 用途 | 成功返回 |
| --- | --- | --- | --- |
| GET | `/api/admin/score-lines?category=&year=` | 列表 + 全部条目 | `{ categories, sets }` |
| POST | `/api/admin/score-lines` | 新增一条数据集 | `201 { set }` |
| PUT | `/api/admin/score-lines/:id` | 整组覆盖更新 | `{ set }` |
| DELETE | `/api/admin/score-lines/:id` | 删除数据集及其条目 | `{ ok: true }` |

本轮**不做**类型 CRUD：类型来自代码常量。以后要运营自助加类型，再单独加 `/score-line-categories` 接口和表。

### 6.2 GET 响应

```json
{
  "categories": [
    { "id": "postgrad", "name": "考研", "count": 2 },
    { "id": "cet", "name": "四六级", "count": 1 }
  ],
  "sets": [
    {
      "id": "sline_m3k2a1b2c3d4",
      "categoryId": "postgrad",
      "title": "2026 考研国家线（A 区）",
      "year": 2026,
      "region": "A 区",
      "sourceName": "教育部",
      "sourceUrl": "https://example.com/official",
      "note": "",
      "entries": [
        { "id": "slineitem_...", "label": "总分", "value": 273, "maxValue": 500, "note": "" },
        { "id": "slineitem_...", "label": "英语一", "value": 38, "maxValue": 100, "note": "" }
      ],
      "createdAt": "2026-11-14T02:00:00.000Z",
      "updatedAt": "2026-11-14T02:00:00.000Z"
    }
  ]
}
```

规则：

- `categories` 永远返回注册表里的全部类型（含 0 条的），按注册表顺序；`count` 是**当前 `year` 过滤后**该类型的条数（不受 `category` 过滤影响，保证 tab 计数稳定）。
- `sets` 按「注册表类型顺序 → 年份倒序（0 最后）→ `updated_at` 倒序」排列。SQL 用
  `ORDER BY CASE WHEN year = 0 THEN 1 ELSE 0 END, year DESC, updated_at DESC`，类型顺序在 Node 里按 `scoreLineCategories` 的下标二次排序（`category_id` 是字符串，不靠字典序）。
- `category` 非法值按「全部」处理；`year` 只接受正整数，非数字 / `0` / 负数都按「全部」处理（与 `/roster` 的宽松口径一致）。
- 条目按 `sort_order ASC` 返回；`maxValue` 为空时省略该字段。
- 查询用两次 SQL（sets 一次、entries 一次按 `set_id IN (...)`），不在循环里查条目。

### 6.3 POST / PUT

请求体就是 `ScoreLineInput`：

```json
{
  "categoryId": "postgrad",
  "title": "2026 考研国家线（A 区）",
  "year": 2026,
  "region": "A 区",
  "sourceName": "教育部",
  "sourceUrl": "https://example.com/official",
  "note": "",
  "entries": [
    { "label": "总分", "value": 273, "maxValue": 500 },
    { "label": "英语一", "value": 38, "maxValue": 100 }
  ]
}
```

实现要点：

- `validateScoreLineInput()` 返回非空数组时 `400 { error: errors[0], errors }`。
- `id` 由服务端 `newId('sline')` 生成；条目 id 由 `newId('slineitem')` 生成，**每次保存整组重建**，不要求前端回传条目 id。
- `created_at` / `updated_at` 用 `server/src/db/core.ts` 的 `now()`（ISO UTC）。
- 写操作包在 `db.exec('BEGIN')` / `COMMIT` / `ROLLBACK` 里；`PUT` 先删旧条目再插新条目。
- `PUT` / `DELETE` 找不到 id 返回 `404 { error: '没有找到这条分数线' }`。
- 成功日志：`log.info('scoreline.saved', { id, categoryId, entries: n, created: true|false })`、`log.info('scoreline.deleted', { id })`；不记录正文，不记录 token。

### 6.4 鉴权与错误

- 四个接口都在 `requireAdmin()` 之后，未带令牌返回 401；不新增免鉴权路径。
- `express.json({ limit: '4mb' })` 已足够（一条分数线远小于 4 MB），不改全局限制。
- 400 只返回校验错误，不返回堆栈；500 由现有错误中间件统一处理并打日志。

| 年份筛选 | 选项来自当前已加载数据里出现过的年份 + 「全部年份」；`0` 显示为「未标年份」 |
| 搜索 | 前端在已加载数据里匹配 `title` / `region` / `sourceName`，不区分大小写；结果为空时给「清空搜索」 |
| 新增 | 打开弹窗；类型默认当前选中的 tab（「全部」时默认第一个类型） |
| 编辑 | 同一弹窗，字段回填，条目按原顺序 |
| 删除 | `confirmAction({ title: '删除这条分数线？', danger: true })`，确认后调 DELETE，再从列表移除 |
| 保存 | 成功关闭弹窗、重新拉列表、顶部短暂提示「已保存」；失败留在弹窗内显示接口返回的真实错误 |
| 加载失败 | 页面显示错误原因 + 「重新加载」，不展示空列表冒充成功 |
| 排序 | 服务端已排好；前端不再重排，避免与 tab 计数口径不一致 |
| 移动端 | tab 行横向滚动；卡片纵向排列；条目表 `overflow-x: auto`，不撑破页面 |

### 7.4 弹窗字段

| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 类型 | `select` | 注册表全部类型 |
| 标题 | `input` | 必填，占满一行 |
| 年份 | `number` | 可空；空提交为 `0` |
| 地区 | `input` | 可空，占半行 |
| 来源 | `input` | 必填，占半行 |
| 来源链接 | `input[type=url]` | 可空 |
| 说明 | `textarea` | 可空，2–3 行 |
| 条目 | 动态行 | 每行：名称 / 分数 / 满分 / 备注 / 删除；底部「＋ 添加一行」 |

条目行初始 1 行；删除到 0 行时自动补 1 行空行（不允许提交 0 条）。不做拖拽排序，顺序就是录入顺序（`sort_order` 按数组下标）。

## 九、发布、数据与回滚

- **建表**：服务启动时 `initSchema()` 自动执行 `CREATE TABLE IF NOT EXISTS`；已有数据库不需要手工操作。
- **备份**：按惯例 `bash update.sh` 会先做 `VACUUM INTO` 备份；本次是纯新增表，风险低，但仍不要跳过备份。
- **数据**：空表上线；管理员从官方来源录入。**不写种子数据**，避免把示例数字当成真实分数线。
- **回滚**：`git revert` 本次提交 + `bash update.sh`。两张新表保留不影响旧代码；已录入的数据不会丢。若确定永不使用，再单独确认后 `DROP TABLE`（不在本轮）。

## 十一、风险与处理

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | 管理员录入错误数字，被当成官方口径 | 来源名称必填、来源链接可点；页面标注「内部查询参考」；不接入报告 |
| 2 | 类型注册表前后端漂移 | 类型与校验都放 `shared/src/score-line.ts`，前后端 import 同一份 |
| 3 | 条目太多把卡片撑长 | 条目表限高 + 纵向滚动（如 `max-height: 360px`）；不做折叠，避免多点一次 |
| 4 | 年份留空排序混乱 | `0` 视为「未标年份」，排序固定放最后，tab 计数不受影响 |
| 5 | 两个人同时编辑同一条 | 后保存覆盖先保存（整组 PUT）；管理端单人使用，暂不做乐观锁 |
| 6 | 文件超 400 行 | 按 7.5 拆三个文件；`check:size` 会拦 |
| 7 | 后续想加类型却不想改代码 | 结构已留好：加 `score_line_categories` 表即可，`set.category_id` 不用迁 |
| 8 | 从注册表删掉某个类型后，旧数据还在但页面看不到 | 常量加回即可恢复，不删数据；确实要清理时另做备份后的人工操作 |
