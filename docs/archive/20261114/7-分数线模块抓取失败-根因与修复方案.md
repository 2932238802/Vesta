# 分数线模块 · 抓取失败根因与修复方案

> 版本：v1.0（2026-11-14）　状态：**已实施并提交（产品版本 v1.80，2026-11-14，commit `94f5ecf`）**
> 实施记录：S1/S2/S3 已落地——引导页跟随与失败码、`html-category@1`（正置 / 转置、每类别一条 batch）、有界发现队列（深度 / 条数 / 列表页取最新年）、来源表新增 `entry_url` / `discover_depth` / `url_include` / `verified`、`crawl_documents` 新增 `note` / `shape`、覆盖页失败码文案。S4 只核验了浙江（`/col/col48/index.html`），其余 30 省标 `verified=0`，失败时提示 `needs_seed`，由运营按 §7.2.1 逐省补栏目 URL。真实验证：浙江 2026 公告页 1 页 → 8 条 `pending`，数字与公告一致。

## 一、现象与证据

### 1.1 报文的来源可以反推

| 报文片段 | 产生位置 | 说明 |
| --- | --- | --- |
| `https://www.zjzs.net/：` | [`crawl.ts:256`](../../../server/src/score-lines/crawl.ts#L256) | `stats.details.push(`${url}：${issues.join('；')}`)`，URL 前缀来自抓取地址 |
| `浙江省教育考试院官网：` | [`html.ts:56`](../../../server/src/score-lines/parsers/html.ts#L56) | `issues[0] = `${title}：没有识别到分数线表格``，title 取自 `<title>` |
| `没有识别到分数线表格` | 同上 | 只在 `metrics.length === 0` 时产生 |

结论：**取页成功、HTTP 正常返回、解码正常、解析器跑完但 `metrics = 0`**。报文里 `title` 能被正确解成中文，也直接证明不是编码问题。

### 1.2 只读复现（2026-11-14 14:05 前后，WSL，仓库内真实解析器）

| 步骤 | 结果 |
| --- | --- |
| `GET https://www.zjzs.net/`（与 [`crawl-fetch.ts:44-52`](../../../server/src/score-lines/crawl-fetch.ts#L44-L52) 相同 UA / Accept） | `200`，`text/html`，**4 884 B**，133 ms，无重定向 |
| `title` | `浙江省教育考试院官网` |
| `<table>` / `<a href>` / `<img>` / `<script src>` | **0 / 0 / 3 / 7** |
| 真实 `html-table@1` 解析 | `batches = 0`，`issues = ["浙江省教育考试院官网：没有识别到分数线表格"]`，`links = []` |

解析输出与用户报文**逐字一致**，复现成立。

### 1.3 站点结构：首页是「点击进入」引导页

抓到的正文里，跳转不是超链接，而是写在容器上的 `onclick`：

```html
<div class="zjhz-guide-main" onclick="window.open('/col/col27/index.html','_self')" ...>
  <img src="/images/14/ydby.png" />
  ... <p>鼠标点击进入</p>
</div>
```

补充排除项：`/moban/index/index.html` 只有 **359 B**，内容是 `location.href = "https://www.zjzs.net/"` 的跳板。所以**不是前端 SPA 渲染问题**——该站是服务端渲染的传统 CMS（汉网模板），正文与表格都在初始 HTML 里，只是入口不在 `/`。

### 1.4 真实通路的层级（4 跳）

```text
/                         引导页（0 表、0 <a>，只有 onclick）
└→ /col/col27/index.html  门户首页（26 KB、0 表、54 个 <a>，无业务关键词链接）
   └→ /col/col3/index.html   考试招生（含「普通专升本」栏目链接）
      └→ /col/col48/index.html  普通专升本（14 KB、2 表，含分数线公告列表）
         └→ /art/2026/5/7/art_49_12241.html  2026 各类别最低控制分数线通告
```

### 1.5 把真实公告页喂给真实解析器，仍然失败

`/col/col48/index.html` 里最近的分数线公告（`2026年浙江省普通高校专升本招生各类别最低控制分数线通告`）页面有 3 张表，业务表是 **2 行 × 9 列的转置表**：

```text
招考类别 | 文史  法学  教育  艺术  理工  经管  农学  医学
分数线   | 222   198   226   210   182   156   214   220
```

用 `html-table@1` 解析该页：

```text
batches = 0
issues  = ["浙江省教育考试院官网 通知文件 2026年…最低控制分数线通告：没有识别到分数线表格",
           "没有识别到科目分数", "没有识别到科目分数", "没有识别到科目分数"]
```

**即：把入口 URL 换成正确公告页，也依然 0 条。** 这是第二层根因，与入口无关。

### 1.6 本机数据库里没有这次运行

`data/vesta.db`（含 WAL 合入后）实查：

| 表 | 行数 |
| --- | --- |
| `crawl_runs` | 0 |
| `crawl_documents` | 0 |
| `scoreline_batches` / `scoreline_metrics` | 0 / 0 |
| `scoreline_sources`（浙江） | 1 条，`url = https://www.zjzs.net/`，`last_run_at = ''`，`last_status = ''` |

用户确认：这次失败发生在**生产服务器**实例。排障入口（生产的 `DATA_DIR`）：

1. `crawl_runs` 按 `created_at DESC` 取最近一次任务，看 `status` / `saved` / `failed` / `message`；
2. `crawl_documents` 按该 `run_id` 取 `http_status` / `content_type` / `parse_status` / `error`；
3. 快照在 `data/crawl/YYYYMMDD/<checksum>.html`；`update.sh` 只备份数据库，**快照需单独备份/查看**。

说明：本机这份库不能用来反推这次失败（`crawl_runs` 为 0），不要对着没有运行记录的库找日志。

## 二、根因（按环节定位）

| 环节 | 判定 | 证据 | 是否本次失败原因 |
| --- | --- | --- | --- |
| 取页 | ✗ **取到了，但取错页** | 200 / 4 884 B / 133 ms；内容是「点击进入」引导页；源头是 `source.url` 被配置成站点根 | **是（直接原因）** |
| 解码 | ✓ 正常 | `<meta charset="UTF-8">`；`title` 正确解出中文，报文里中文正常 | 否，可排除 |
| 选链 | ✗ **完全空转** | 引导页 `<a href>` = 0；跳转在 `onclick`；即使换成真首页，候选正则与深度也够不到 | **是（直接原因）** |
| 解析 | ✗ **0 表 → 产生报文** | 0 张 `<table>`，`metrics = 0`，与报文逐字一致；真公告页也只有转置表，认不出 | **是（直接原因 + 结构原因）** |
| 落库 | ✓ 按设计执行 | 只写 `crawl_documents(parse_status=failed)` + `crawl_runs(status=failed)` + `source.last_error`，不写 batch；符合 AC7、文档 §4.3 | 否 |

### R1（直接原因 · 配置与发现能力）

T0 源的 URL 直接取「省考试院官网首页」（[`score-line-region.ts:20`](../../../shared/src/score-line-region.ts#L20) → [`sources.ts:184`](../../../server/src/score-lines/sources.ts#L184) → [`sources.ts:188`](../../../server/src/score-lines/sources.ts#L188)），而 `crawl` 只抓这一个 URL（[`crawl.ts:219`](../../../server/src/score-lines/crawl.ts#L219)），选链只从**第一页**取**最多 3 条**、**只下钻 1 层**（[`crawl.ts:248-253`](../../../server/src/score-lines/crawl.ts#L248-L253)）。真实通路要 4 跳，且第一跳是 `onclick` 不是 `<a>`——发现能力在设计上就到不了。

### R2（结构原因 · 口径与解析器错配）

文档 §1.4 定义专升本主线口径是「省份 + **科类** + 批次」，数据模型也用 `scoreline_batches.track` 承载类别；但：

- `html-table@1` 假定「行 = 科目、列 = 分数」（[`table.ts:113`](../../../server/src/score-lines/parsers/table.ts#L113)），表头必须含 `科目|名称|项目|专业`（[`table.ts:49`](../../../server/src/score-lines/parsers/table.ts#L49)）；
- 浙江省控线是「行 = 招考类别/分数线、列 = 8 个类别」的**转置表**；
- 科目词表里没有 `文史/法学/教育/艺术/理工/经管/农学/医学`，也没有把 `分数线` 当别名（[`score-line.ts:286-300`](../../../shared/src/score-line.ts#L286-L300)）；
- 且 [`batchFromMetrics`](../../../server/src/score-lines/parsers/table.ts#L217) 一页只产 1 个批次，8 个类别本应是 8 条 batch（`track` = 类别，`metric.subject_code = 'total'`）。

这不是浙江一个站的问题：**所有「类别 × 分数」的专升本省控线都不在这套解析器的表达范围内。**

### R3（衍生 · 年抛式配置）

源码里没有「栏目页 / 列表页」概念，只有单个 `source.url`。文档 §7.3.1 要求的「进栏目页 → 按年份和标题筛」没有实现，导致：入口要人工贴、明年公告换 URL 就再失败一次，31 省都如此。

## 四、方案（已定稿 v1.0）

> 边界：**通用能力**，一次覆盖 31 省专升本主线与考研主线；不做「只换浙江一个 URL」的止血版（实测换对页仍 0 条，见 1.5）。

### 4.0 目标与不做

- **目标**：站点入口换成「栏目页 + 形状识别」后能自动走到当年公告；产出的每个类别都能落成可查询的批次；失败原因能自解释到「补 URL / 补解析器 / 重试」三选一。
- **不做**：无头浏览器渲染、OCR、逐站 CSS/XPath 选择器、改 `scoreline_batches` 表结构、把「分数线」塞进全局科目词表。

### 4.1 分层总览

| 层 | 现状 | 改成 | 对应问题 |
| --- | --- | --- | --- |
| L1 入口 | `source.url` = 官网首页（引导页） | 入口页 + **引导页跟随**（`onclick` / `meta refresh` / JS 跳转） | P0-1、P0-2 |
| L2 发现 | 1 个 URL、最多 3 条链、只 1 层 | 有界队列：深度 / 条数 / 列表页取最新年 | P1-1、P1-2 |
| L3 解析 | 只认「科目 × 分数」窄表 | 新增 `html-category@1`：类别表（正置 / 转置）识别 | P0-3、P1-3 |
| L4 口径与落库 | 一页 1 批次、`track` 为空 | 每类别 1 条 batch（`track` = 类别，指标 `total`） | P0-4 |
| L5 可观测 | 一句话「没有识别到分数线表格」 | 结构化失败码 + 覆盖页分级文案 | P1-4、P2-4 |

### 4.2 L1 入口：先「进得去」

1. **种子 URL 换位**：`shared/src/score-line-region.ts` 的 `examUrl` 从「官网首页」改为「该省专升本栏目列表页」（浙江为 `/col/col48/index.html`）。官网地址另存，不再当抓取入口。
2. **引导页跟随**（通用，不加选择器）：取到的页面若满足「`<a href>` = 0 且 `<table>` = 0」，则按顺序尝试三类跳转，最多跟 1 跳、必须同域、必须 200：
   - 容器上的 `onclick="window.open('…')"` / `location.href='…'`；
   - `<meta http-equiv="refresh" content="0;url=…">`；
   - `<script>` 里唯一的 `location.href = "…"`。
   命中后把「实际入口」写进 `crawl_documents` 备注，便于排障。这条正是本次 P0-2 的对症药，且对其它省同样有效。
3. **31 省入口清单从「官网」升级为「栏目 URL + 核验状态」**：文档 §7.2.1 的表增加一列「栏目入口是否已核验」，人工核验一次（每省 1-2 分钟），未核验的省标 `needs_seed`，不假装能抓。

### 4.3 L2 发现：从「单页」到「有界队列」

- 取页由 `[source.url]` 改为队列，元素带 `depth`；`depth ≤ discover_depth`（默认 2，够「入口 → 列表 → 公告」）。
- 每页候选链接沿用现有正则，但**从 `source` 读**（`url_include`），默认值仍是 `20\d{2}|分数线|录取|控制线|招生计划|专业目录|专升本|复试`；同域、去重、每页 ≤10 条、每 run ≤30 页。
- **列表页判定**：某页候选链 ≥3 条且多数带年份 → 按列表页处理，只取**最新年份**的前 5 条，避免把十年公告全抓一遍。
- 节奏不变：同域 1 请求/2 秒、单省单任务、失败退避（§7.2 原样遵守）。

### 4.4 L3 解析：新增 `html-category@1`（形状识别，不写选择器）

判型顺序固定：

1. 先用现有 `rowsToMetrics`（科目表）跑一遍，**成功就用**（考研/校线不受影响）；
2. 失败才按「类别表」识别，两条硬条件同时满足才算命中：
   - **类别行**：某行 ≥3 个单元格，其中 ≥2 个是类别词（文史 / 理工 / 经管 / 农学 / 医学 / 教育 / 法学 / 艺术 …），或首列含 `招考类别` / `类别` / `科类` / `专业类别`；
   - **分数行**：紧邻下一行首列含 `分数线` / `控制分数线` / `最低控制分数线`，且其余单元格能 `parseScore` 成数字，数量与类别列对齐。
3. 正置（行 = 类别、列 = 分数）与转置（列 = 类别、行 = 分数）都支持，按上面两条自动判向。
4. **每个类别产出一个 batch**：`scope='provincial'`、`exam='upgrade'`、`year` 取标题年份、`track=类别`、`metric.subject_code='total'`、`full_score` 公告没写就 `NULL`（不猜）、`confidence=0.9`。
5. 三条都不中 → 返回 `unsupported_table`（带 `tables` / `rows` / `cols` 形状），**不返回空数组冒充成功**（§14.2 已要求）。

### 4.5 L4 口径与落库

- 类别落 `track`；`category` 留给「普通类 / 建档立卡 / 退役士兵」（浙江本期公告只有招考类别，`category` 留空，不编）。
- 已核对唯一键 `(scope, exam, year, province, region, school_id, program_id, category, track)`：8 个类别 → 8 条，互不冲突。
- 查询侧 `requires: ['track']`（§6.1 第 5 条）已存在：同省同年多类别时页面提示补选，不混画，**无需改查询逻辑**。
- 复核策略不变：8 条一起 `pending`，复核页可按省/年批量通过。

### 4.6 L5 可观测：让失败自解释

`crawl_documents.error` 加机读前缀，覆盖页据此给中文文案与下一步动作：

| 前缀 | 含义 | 覆盖页提示 |
| --- | --- | --- |
| `network` | 超时 / 非 2xx / 超 10MB | 「站点不可达，稍后重试」 |
| `entry_redirect` | 入口跳到了别的页仍未拿到内容 | 「入口可能是引导页，请补栏目 URL」 |
| `no_table` | 200 但 0 张表 / 0 个链接 | 「疑似前端渲染或入口错，需人工补源」 |
| `unsupported_table` | 有表但形状不认 | 「表格形状未适配，需补解析器」 |
| `decode` | 解码后无可读文本 | 「编码异常，需补 charset」 |

### 4.7 为什么是这套，不是别的

| 备选 | 否掉的理由 |
| --- | --- |
| 上 Puppeteer / Playwright 渲染 | 该站是服务端渲染，初始 HTML 里就有表和正文（1.3 已证）；上浏览器要多带 ~300 MB Chromium、慢一个数量级、更容易被 WAF 盯，且违背文档 §11「不引入」 |
| 每省写 CSS / XPath 选择器 | 31 套选择器，站一改版全废；本次问题本质是**表格形状**（类别 × 分数），不是元素位置 |
| 每省贴「当年公告 URL」 | 年抛：第二年公告 ID 一变就失败，正是 R3 |
| 把「分数线」加进 `subjectDefinitions` 当 `total` 别名 | 会让「单科分数线」也被误判成总分；类别表必须在专用解析器里显式处理 |
| 给 `scoreline_batches` 加 `class` 列 | `track` 字段本来就是给类别/学科门类用的（§5.4、§6.1），改表要动查询、前端和迁移，收益为零 |
| 只把浙江源 URL 换成公告页 | 实测该公告页仍 `batches = 0`（1.5），等于没修 |
| 先做 OCR / 上大模型抽取 | 与根因无关，且引入不确定性和成本；规则能确定的形状不该交给模型 |

## 六、验证计划

1. **fixture 回归（不联网）**：把本次抓到的三个真实页面存进 `parsers/__fixtures__/`，跑 `npm run check:score`：
   - 引导页 → `entry_redirect` / `no_table`，且不产生 batch；
   - 栏目页 → 能选中最新年份的分数线公告链接；
   - 公告页 → **8 条 batch**，`track` 依次为 文史/法学/教育/艺术/理工/经管/农学/医学，`total` 依次 222/198/226/210/182/156/214/220。
2. **形状用例**：转置表、正置表、缺分数行、多一列"备注"、空表 —— 各自断言（§14.2 要求正常/缺列/格式变化三种，这里多加两种）。
3. **本地端到端**：临时 `DATA_DIR` + 本地 fixture HTTP 服务，跑「发现 → 解析 → pending → 复核 → 查询」，断言查询页能按 `track` 取到单类别（§14.3 第 6 条）。
4. **真实站点只读验证（唯一一次外网）**：浙江 `col48` → 2026 公告，产物 8 条 `pending`，人工逐个核对数字与公告一致；抓完把 source 恢复为「已核验」状态。
5. **覆盖页**：手工造 `no_table` / `unsupported_table` 两种情况，确认文案与「下一步」正确，运营能据此判断该补 URL 还是补解析器。
6. **全量门禁**：`npm run verify`（`check:docs` / `check:size` / `check:version` / `check:score` / `check:audit` / `typecheck` / `build`）全绿。
7. **最小验证（本节一环，不单独成主线）**：只做「浙江 1 省 × 1 页 × 1 年」的真实抓取 + 人工核对 8 个数；通过即可判定 S1/S2 有效，S3 的发现能力用 fixture 验证即可，不必为它再抓一轮真实站点。

> 说明：31 省的逐站回归**不在本轮**。本轮只保证「形状通用 + 入口可核验」，其余省份按同一条路径在 S4 核验后逐个打开，未核验的省在覆盖页显示 `needs_seed`，不显示假成功。
