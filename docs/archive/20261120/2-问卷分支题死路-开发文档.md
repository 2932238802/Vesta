## 一、需求（R-018）

- **R-018-1** 任何带 `branches` 的题目，在分支未命中时都不能渲染成 0 个选项；前台必须可答、可提交。
- **R-018-2** 优先恢复真实数据：分支来源题（当前只有「毕业后的第一选择」，id `q6`）可见、必答、单选且没答案时，进入 Q19 自动回到该题补答，补答后再进 Q19 正常渲染对应分支。
- **R-018-3** 来源题答案失效时（选项已删除、答案不是字符串、答案不在当前选项里），清掉失效答案并回到该题重选；只有无法回跳时才用兜底。
- **R-018-4** 兜底内容固定为：题面「你对目标方向的门槛、时间节点了解多少？」，选项 都清楚 / 知道一些 / 只听过 / 完全不了解；选项 id 与现有分支一致（`q16_1`–`q16_4`），保证报告取标签和评分可用。
- **R-018-5** 前端与后端必须用同一套 `resolveQuestion()` 结果：兜底答案提交时不能被判「选项无效」。
- **R-018-6** 后台发布保护：分支来源题存在但被改成非单选时拒绝发布并给出以题目文字指认的提示；新增选项没有专属题面时不阻断发布，但保存后提示运营「部分选项会显示通用题面」。
- **R-018-7** 后台编辑分支来源题时显示依赖提示（用题目文字，不用题号）。
- **R-018-8** 默认问卷的正常分支渲染与评分不变；报告「信息差」标签改为取学员**实际看到的选项文字**（修正旧实现固定取第一个分支文案的缺陷；2026-11-20 G3 后用户确认接受）。
- **R-018-9** 必答题（含回跳后的分支来源题）未作答时，「下一题」必须拦截，不得跳过；兜底与回跳改动不能放宽这条规则。

## 六、风险与对策

- **回跳循环**：只在「来源题可见 + 必答 + 单选 + 答案缺失/失效」时回跳；来源题非单选的数组答案直接用兜底、不回跳。回跳后来源题必答校验会拦住空答案。→ 不会循环。
- **清空答案的风险**：只清「对不上当前选项」的失效值；有效答案不动。清空前不额外弹窗（无效值本来无法继续）。
- **自定义生产问卷没有 `default` 分支**：兜底必须在共享代码里内置，不能依赖问卷 JSON 新增字段。
- **前后端判定不一致**：兜底只写在 `resolveQuestion()` 一处，前端渲染、提交校验、报告取值共用。
- **后台保护不可操作**：来源题缺失时不做硬阻断（后台无法恢复同 id 题目），只提示；非单选是硬阻断（可改回）。
- **拆分引入回归**：拆分 commit 要求行为完全不变，拆分后先跑 `verify` + 关键页面走查，再做功能 commit。
