# 博查检索时效与「岗位方向」块 · 问题与修复方案

> 版本：v1.0（2026-11-12）　状态：**待修复**
> 现象来源：本地报告 `/r/gDJT5DqM9-X9IVfxtrYs2vr6N3M`（答卷「312」，2026-11-12 生成）
> 一句话：**不是博查没有新数据，是我们一直用 `freshness: noLimit` 要「最相关」，拿回一堆 2018—2024 的高校就业网老公告，再拿它们做「门槛统计」。**
> 开发前先读：`docs/agent-rules.md`（文档优先、数字必须由程序算）、`docs/development-history.md` 本轮记录。

---

## 一、现象（用户可见）

报告「数据库里能对上你专业的只有一类岗位」→「后端开发（Java / 服务端）」卡：

- 三条原文日期是 **2024-12-20、2024-10-19、2018-05-24**，全部 `stale: true`；
- 「入场线」写「学历：大专一条，学历未写一条，本科一条；经验：接受应届或经验不限三条」；
- 「薪资」写「三条原文都只写薪资以原文为准，没有给出具体数字」；
- 下面「原文门槛」又重复一遍「3 条原文里，大专 1 条…」；
- 报告的检索记录里 7 条检索词**全部没有城市**：`Java开发 2026 应届 招聘`、`前端开发 2026 应届 招聘`……

AI 自己在方向块结尾也写了「原文全部是 2024 年及更早的公告，只能用来观察要求结构」，**但上面仍然照常给出了「入场线」**——这是自相矛盾的。

---

## 二、实测证据（2026-11-12，3 次真实调用，约 0.09 元）

同一个检索词 `杭州 Java开发 应届 招聘`，只改 `freshness`：

| freshness | 返回条数 | 实际日期 | 看到什么 |
| --- | --- | --- | --- |
| `noLimit`（当前默认） | 8 | 2018-03 ～ 2024-09 | 全是高校就业网老公告：有赞 2018 内推、2022 届春招、2024 春招 |
| `oneYear` | 3 | 2025-12 ～ 2026-05 | 鱼泡直聘「杭州招聘Java 12000-14000元/月」、猎聘「阿里巴巴 AI研发工程师-JAVA」 |
| `oneMonth` | 7 | 2026-10-18 ～ 2026-11-11 | 南开就业网「27届校招-开发工程师(JAVA开发)」、鱼泡/测试之家带薪资岗位 |

结论：**改 `freshness` 就能拿到新的、带薪资的、校招的原文**。老数据不是博查的问题，是请求参数的问题。

> 注意：博查的 `datePublished` 有时是抓取时间不是发布时间（例如标题写 `[2024][杭州]` 的帖子，日期为 2026-10-24）。时效判断不能只信这一个字段。

---

## 三、根因（代码定位）

### R1 检索从来没要过时间范围

- `server/src/ai/bocha.ts:109`：`freshness: options.freshness ?? 'noLimit'`
- 两个调用点都没传：`server/src/ai/doc-generate.ts:125`（`searchWeb(query, { count: 6 })`）、`server/src/ai/generate.ts:316`（`searchWeb(query)`）
- 缓存 key 已包含 `f{freshness}`（`bocha.ts` 的 `cacheKey`），所以改参数不会命中旧缓存，安全。

### R2 检索词没有城市

- `cityOf()`（`server/src/ai/doc-generate.ts:90-105`）只认 `MAJOR_CITIES` 里的**具体城市名**；问卷 Q8 的选择是「新一线（杭州、成都、武汉、西安等）」这种档位，不是具体城市 → 返回空串。
- 结果：检索词变成 `Java开发 2026 应届 招聘`，全国搜，返回北京/外地岗位。报告标题却叫「你能去的几个方向」。

### R3 过期数据仍然进入统计

- `directionFacts()`（`shared/src/doc.ts:686-728`）用该方向的**全部**匹配原文计算，**不看 `stale`**。
- 其中一条 2018 年岗位写的是「经验：2-3 年」，只因为标题里有「应届毕业生求职」，就被 `/应届/` 正则算进「接受应届/经验不限的 3 条」——假阳性。
- 展示只挂 2 条（`shared/src/doc.ts:750-752` 的 `slice(0, 2)`），facts 却按 3 条算，口径不一致。

### R4 薪资占位符被 AI 当成原文事实

- `server/src/ai/doc-generate.ts:585`：`salary: salaryOf(item.snippet) || '薪资以原文为准'`
- 这个字符串进入 `jobSpecs`，AI 于是复述「三条原文都只写薪资以原文为准」；底部 `sources` 还写「用于核对岗位门槛和薪资」，实际没有任何薪资。

### R5 同一句话渲染两遍

- `entry` 字段已经复述了 facts；`web/src/components/ReportBlocks.vue:374-376` 又用 `direction.facts` 渲染一遍「原文门槛 3 条原文里…」。

## 四、影响面

| 位置 | 被污染的内容 |
| --- | --- |
| 方向卡 `entry` / `salary` | 过期样本统计 + 占位符复述 |
| 方向卡 `fit` | 「原文没有写专业限制」——基于过期原文，参考价值低 |
| `sources` 文案 | 「用于核对岗位门槛和薪资」，薪资实际不存在 |
| `gap` 里「原文『缺什么』」 | 引用的是过期原文的结论 |
| `checklist` 检索词 | 也带「新一线」这种档位词，不是可搜的城市 |

---

## 五、修复方案

### P0（先做，改动小、收益最大）

1. **检索加时间窗**
   - `doc-generate.ts` 的 `searchOne()`：`searchWeb(query, { count: 6, freshness: 'oneYear' })`
   - `generate.ts:316`：`searchWeb(query, { freshness: 'oneYear' })`
2. **兜底策略**：主检索（oneYear）可用原文 <3 条时，再用 `oneMonth` 或 `noLimit` 补一次；补来的结果只做「要求结构参考」，**不进入 `directionFacts` 统计**（给 QuerySpec/结果加 `fallback: true` 标记）。
3. **删掉薪资兜底**：`salary: salaryOf(item.snippet)`，空就是空；`ReportBlocks.vue:358` 已有 `v-if="direction.salary"`，会自动隐藏。
4. **过期不进统计**：`directionFacts()` 先 `.filter((job) => !job.stale)`，剩余 <2 条直接返回 `[]`。

### P1

5. **城市落到具体城市**：Q8 选「新一线」时，优先用 Q4 学校所在城市（若在 `MAJOR_CITIES` 里）；否则从 Q8 的括号文案用 `cityInText()` 抓第一个城市；都抓不到时检索词不加城市，但报告里明确写「本次未限定城市」。
6. **修正则假阳性**：`接受应届` 的判定改为「原文同时没有 `\d+-\d+年` / `\d+年以上`」；或直接按字段匹配「经验：应届 / 经验不限」。
7. **日期可信度**：`stale` 判断改为「`datePublished` + 标题里的年份」双证据，两者冲突时按更早的算。

### P2

8. 去掉 `direction.facts` 脚注（`entry` 已说），或只在可用原文 >2 条时显示。
9. `sources` 文案按实际字段生成：没有薪资就不写「用于核对薪资」。

## 六、验收标准

用同一份答卷重新生成报告（或 `POST /api/report/:slug/retry`），逐条核对：

- [ ] `queries` 里至少一条带具体城市；
- [ ] 方向卡展示的原文 `date` 近 12 个月占多数，过期原文有明确标注且不参与统计；
- [ ] 报告里不再出现 `salary === '薪资以原文为准'`（要么有数字，要么整行不显示）；
- [ ] `facts` 的条数与卡片展示的原文条数一致；
- [ ] `npm run verify` 全绿（WSL 里跑：`wsl bash -lc 'cd ~/LosAngelous/Vesta && npm run verify'`）；
- [ ] 交付说明里附一次真实生成的 `queries` 和返回日期。

## 七、风险与回滚

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| oneYear 结果变少（实测 8→3 条） | 可能触发补位检索，调用次数上升 | 缓存兜底；观察一周 `search_cache` 命中 |
| 城市回退到学校城市 | 学生目标城市可能不是学校所在地 | 报告里写明依据，或 P1 先只做「不加城市但要标注」 |
| 过期判断改双证据后出现误判 | 标题年份格式多样 | 先按更早年份算，宁严勿松 |

回滚：`freshness` 改回 `noLimit` 即恢复现状；其余每项都是独立小改动，可单独回退。
