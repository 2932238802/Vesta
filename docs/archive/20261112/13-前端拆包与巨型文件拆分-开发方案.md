> 版本：v1.2（2026-11-12）　状态：**第一批、第二批均已实施（2026-11-12），改动尚未提交**
> 版本对应：v1.0 立项 → v1.1 第一批（路由懒加载 + 后端路由拆分）→ v1.2 第二批（组件与巨型模块拆分）。`docs/development-history.md` 统一引用 **v1.2**。
> 依据：2026-11-12 代码审查结论（性能与可维护性两项），以及 [`15-13号前端拆包方案-Review.md`](./15-13号前端拆包方案-Review.md) 的修订建议。

## 一、要解决的问题

### 1.1 前端没有路由级拆包

`web/src/router.ts` 把 21 个页面全部静态 `import`，包括 5 个体量很大的管理端页面。Vite 因此只产出一个入口 chunk：改造前构建的 `web/dist/assets/index-*.js` 约 383KB、`index-*.css` 约 145KB。学员在手机上打开邀请页 / 问卷页 / 报告页时，必须先把整个管理后台的代码下载并解析完才能渲染。

`jspdf` 已经是动态加载（`ReportView.vue` 的 `await import('jspdf')`），说明按需加载的写法在本仓库可行，只是路由层没做。

### 1.2 巨型单文件

| 文件 | 行数 | 主要问题 |
| --- | --- | --- |
| `server/src/routes/consult.ts` | 2378 | 森林读写、模板、评分、4 组路由全挤在一起 |
| `web/src/components/ReportBlocks.vue` | 2283 | 17 种 block 的模板 + 1000+ 行 scoped 样式 |
| `web/src/views/admin/ConsultPurposes.vue` | 2101 | 画布、侧栏、状态逻辑同一个组件 |
| `web/src/views/admin/ConsultWorkspace.vue` | 1802 | 同上 |

> 注：本表为 v1.0 立项时测量。并入 `14-管理员界面交互优化` 后，实际拆分基线以 4.2 / 4.3 的「改造前」列为准（`ConsultPurposes` / `ConsultWorkspace` / `doc-generate` 与本表有几十行出入，属于 14 号方案的增删与两次测量时点不同）。

影响：每次改动都要整文件读入（Agent 的 token 成本也在这里），review 和合并冲突成本高。

## 二、方案 A：前端路由懒加载（已实施）

`web/src/router.ts`：

- 只有 `Root`（入口页）和 `NotFound` 保持同步加载；
- 其余全部改成 `const X = () => import('./views/...')`，包括 `Invite` / `Quiz` / `ReportView` 和整个后台；
- `Router` 配置与 `beforeEach` 守卫逻辑不变（守卫只读 token、调 `api.devLogin()`，不依赖组件本体）。

`web/vite.config.ts`：

- `build.rollupOptions.output.manualChunks` 把 `vue` / `vue-router` 单独成 `vendor-vue` chunk，避免被重复打进每个路由 chunk。

不做的事：

- 不加 loading 骨架屏、不改页面过渡——懒加载 chunk 由浏览器缓存，正常网络下切换无感；若以后需要，再按路由加 `<Suspense>`。
- 不改 `AdminLayout` 的导航结构。

### 3.3 拆分纪律（硬约束）

- 只移动代码，不改逻辑、不改路由路径、不改请求/响应、不改错误文案、不重新格式化。
- **允许的例外：目录变深导致的相对路径调整。** `server/src/routes/consult/shared.ts` / `forest.ts` 读取 `shared/src/*.json` 的路径从 `../../../` 改为 `../../../../`，`server/src/index.ts` 的 import 改为 `./routes/admin/index`。已确认种子树仍能并入森林；除路径外不改任何逻辑。
- 路由注册顺序不变：`/submissions/export.csv` 在 `/submissions/:id` 之前，`/collections/bundle` 在 `/collections/:id` 之前，roster 的固定路径在参数路径之前。
- 认证边界不变：`/login`、`/dev-login` 必须在 `requireAdmin()` 之前。
- 导出名不变：`adminRouter`、`consultRouter`；`server/src/index.ts` 改为 `./routes/admin/index`，`admin/index.ts` 改为 `../consult/index`。
- 共享辅助函数只放一份，不复制。

### 4.5 验证方式

- `npm run verify` 全绿（check:docs / check:dates / typecheck / build）。
- **db 启动路径**：用现有数据库副本（`vesta.db` + `-wal` + `-shm`）放到临时 `DATA_DIR`，以 `PORT=8798` 连续启动两次：
  - 两次 `/api/health` 均 200，启动日志无迁移报错；`PRAGMA integrity_check` 为 `ok`；
  - `invites` 含 `group_id`，`submissions` 含 `contact_status` / `admin_notes` / `claimed_at` / `wechat_enc` / `slots` / `ai_*`，旧库补列齐全；
  - `surveys` 仍为 1 条，`consult_forest` 为同一份已应用种子的森林（`consult_forest_seed_applied=1`），第二次启动没有重复 seed。
- 报告页：17 种 block 全部覆盖。9 种（`hero` / `assets` / `gap` / `jobmap` / `roadmap` / `checklist` / `scorecard` / `section` / `sources`）用真实报告页面走查；另 6 种（`target` / `radar` / `strengths` / `gaps` / `cognition` / `actions`）通过 `/admin/report/preview` 的完整预览走查；`consistency` / `note` 无现成报告数据，用同构 payload 注入预览页走查。
- 对比方法：同一份数据分别加载拆分前、拆分后的构建，在 1440 与 375 两个宽度截全页图并对比计算样式的哈希。拆分前后每个页面的截图、计算样式、可见文本均**逐字节一致**，控制台无报错。期间发现并修正了一处由样式合并顺序造成的移动端 `LI.job` padding 偏差（`JobMapBlock.vue` 补回 720px 媒体查询里的 `16px 16px`）。
- 咨询页：`/admin/consult` 与 `/admin/consult/purposes` 同样在 1440 / 375 逐字节一致。

**可复现性说明**：截图 / 计算样式 / 文本哈希对比属于人工走查，仓库里没有保留对比脚本或产物，也**不进入** `npm run verify`。路由清单对比可以随时复跑（在本次拆分提交之前，HEAD 仍是指向旧文件的那版）：

```bash
extract() { perl -0777 -ne 'while(/\.(get|post|put|patch|delete)\(\s*["\x27]([^"\x27]+)/g){print uc($1)," ",$2,"\n"}' "$@" | sort; }
git show HEAD:server/src/routes/admin.ts > /tmp/old-admin.ts
git show HEAD:server/src/routes/consult.ts > /tmp/old-consult.ts
extract /tmp/old-admin.ts > /tmp/old-admin.txt
extract server/src/routes/admin/*.ts > /tmp/new-admin.txt
extract /tmp/old-consult.ts > /tmp/old-consult.txt
extract server/src/routes/consult/*.ts > /tmp/new-consult.txt
diff /tmp/old-admin.txt /tmp/new-admin.txt     # 只应剩 < GET /appointments
diff /tmp/old-consult.txt /tmp/new-consult.txt # 应无输出
```

拆分提交之后，把上面两处 `HEAD` 换成 `<拆分提交>^` 即可复跑。

## 六、回滚与风险

纯文件移动 + 懒加载，不涉及数据迁移、不涉及接口变更，服务器 `bash update.sh` 拉取后即生效。

回滚：`git revert <本次拆分的提交>`。**当前状态（2026-11-12 评审时）**：第一批、第二批改动仍在工作区、尚未提交，因此回滚路径暂时不存在；提交后把 commit hash 补到这里和 `docs/development-history.md`。

已知风险：

- **旧 chunk 404**：部署后用户若还开着旧的 `index.html`，它引用的懒加载 chunk 已被新构建删除，切换路由时会加载失败。当前接受这一取舍（发布不频繁，刷新即恢复）；如需兜底，可在 `web/src/main.ts` 监听 `vite:preloadError`，或在 `router.onError` 里判断动态导入失败后提示刷新。
- **弱网加载失败没有 UI 反馈**：手机弱网下懒加载失败，页面会停在原路由，只有控制台报错，用户看不到「加载失败，点击重试」。当前接受；公开页面向非技术学生，后续可加一个轻量错误页或全局重试提示。
- **db 启动迁移**：已按 4.5 做过双启动验证；若上线后仍发现旧库补列异常，回滚到拆分前的 `db.ts` 即可，数据库文件不需要回退。
