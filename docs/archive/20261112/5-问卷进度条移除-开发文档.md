# 问卷进度条移除 · 开发文档

> 版本 v0.1（2026-11-12）　状态：**待杰哥确认**（先文档、后代码）
> 文档性质：需求记录 + 实施方案。**不替代** [规划自测问卷-设计文档](../../规划自测问卷-设计文档.md)；题目、选项、跳题、计分、报告规则仍以那份为准。确认实施时，同一提交内同步改设计文档第 67、300 行。
> 一句话：**问卷页顶部的「百分比 + 细条」进度删掉**——它按「可见题数」算分母，而拖 Q19 英语重要性滑块会改变后续题的可见性，所以拖动时进度会跳。

---

## 一、现象

在问卷页 Q19「你觉得英语对你未来有多重要」（0—10 滑块）上拖动滑块，页面顶部进度条的分组名不变、但**百分比和细条跟着跳**：往 6 分及以上拖，百分比往下掉；拖回 5 分及以下，百分比又跳回去。用户停在同一题，什么都没提交，进度却变了。

## 二、根因（代码证据）

1. Q19 是 0—10 数字题：`shared/src/survey.ts:352-360`（`id: 'q24'`，`range: { min: 0, max: 10, step: 1 }`）。
2. 它后面有 5 道英语题带「q24 ≥ 6 才显示」的条件：
   - Q21 口语听力 `survey.ts:381`
   - Q22 四级丢分 `survey.ts:396-399`
   - Q24 怎么学英语 `survey.ts:434`
   - Q25 每周时间 `survey.ts:451`
   - Q26 背单词 `survey.ts:466`
3. `visibleQuestions()` 每次都按当前答案重算可见题列表（`shared/src/doc.ts:104-108`），`Quiz.vue` 的 `visible` 是 computed（`Quiz.vue:147-149`）。
4. 进度 = `(step + 1) / visible.length`（`Quiz.vue:165-169`）。滑块从 5 拖到 6 的一瞬间，分母 +5（22 → 27 一类的变化），百分比立刻下降；拖回 5，分母 −5，百分比跳升。
5. 所以这不是 CSS 抖动，是**分母随答案变化**。同一个机制在其他「会改变后续题可见性」的题上也会发生（例如 Q20 英语现状影响 Q22 的显示），只是 q24 是滑块、拖动过程中会连续改答案，才被肉眼看到。

## 三、需求

删除问卷页顶部「答到哪儿了」的进度显示。范围严格限定在问卷页：`web/src/views/Quiz.vue` 的 `.progress-wrap` 整块（分组名 + 百分比 + 2px 细条）、`progressPct`、`progressAriaText`、`groupTitle`，以及 `.progress-*` 样式。

## 四、方案

### 4.1 推荐：整块删除（方案 A）

- 模板：删掉 `Quiz.vue:10-25` 的 `.progress-wrap` 及其 `role="progressbar"` / `aria-*`。
- 脚本：删 `progressPct`（165-169）、`groupTitle`（170-174）、`progressAriaText`（175-177）。`groupTitle` 只被进度块使用，无其他引用。
- 样式：删 `.progress-wrap`、`.progress-meta`、`.progress-group`、`.progress-pct`、`.progress-track`、`.progress-done`（584-650 一带），以及 `866` 附近的响应式覆盖；删完确认没有残留引用。
- 保留：`statusText` 的 `sr-only` 播报（切题播报，与进度无关）、「上一题」按钮、底部草稿提示、吸顶/键盘相关逻辑。

### 4.2 备选：只删百分比和细条，保留分组名（方案 B）

- 顶部只留一行分组名（「英语这块」），不显示数字和细条。分组名只在跨组时变，拖动滑块不会跳。
- 代价：仍有一条常驻 sticky 头；收益：学生知道自己在哪一段。
- 与方案 A 的差别只在模板和样式，脚本部分删 `progressPct` / `progressAriaText`，`groupTitle` 保留。

### 4.3 评估过、不采用的替代

| 替代 | 为什么不选 |
| --- | --- |
| 在本题内冻结分母（进入下一题才重算） | 拖动不再跳，但往返改答案、返回上一题再前进时仍会跳；要额外存状态，复杂度换不来彻底稳定 |
| 分母固定为总题数（28） | 分子（第几步）仍随可见题数变化；且要改「进度」的语义与 aria 文案，改动比删除大 |
| 改成「已答题数 / 28」的纯色条，不显示数字 | 这是唯一能让进度稳定的算法，但会把「答到哪」变成「答了多少」，又回到设计文档第 67 行禁止的题数口径；本轮不做，留作以后想恢复进度感时的备选 |
