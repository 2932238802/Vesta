## 一、问题清单

### 1.1 gap 说「还空着的只有一项」，其他模块说「技能 0 分、实习一段都没有」

**现象**：gap 正文写「还空着的只有一项，也是关键的一项：目标岗位」；同一份报告的 hero 写「技能 0 分、实习一段都没有」，scorecard 写「技能 …是空的」「实习实践 …离门槛最远」。

**原因**：`gapLines()`（`shared/src/doc.ts:912-959`）只输出**问卷答案字段**。这个学生 `resumeNow()` 返回空，导致「现在能写进简历的」这一行也被 `if (nowText)` 省略了（`doc.ts:932-933`）。AI 看到的 lines 里确实只剩「目标岗位」是空的，于是照实写；但读者会拿它和 scorecard 对照。

**修复**（推荐 1+3）：
1. `gapLines()` 里补一行程序事实：「简历里现在能写的东西：还没有」——`resumeNow()` 为空时也要输出，不能省略；
2. 或给 gap 的 prompt 加约束：「空着」只能指答案字段，不许扩展成「整体只有一项没准备好」；
3. 生成后做跨模块一致性检查：若 scorecard 里 `skill < 3` 或 `practice < 3`，而 gap 正文出现「只有一项」，判失败重写。

### 1.2 同一块里「专业没有限制」和「专业不在列出的方向里」并存

**现象**：backend 方向卡写「你的专业是计算机科学与技术，原文没有写专业限制」；下面 `relatedJobs` 那条 2018 年岗位写「专业：原文写了专业范围，计算机科学与技术不在列出的方向里」。

**原因**：`jobMatch()`（`shared/src/doc.ts` 约 560-670 行）按**单条原文**判断专业；方向卡按**方向内多条原文**写结论。两条路径不共享结论，也没说明「这是不同原文的写法」。

**修复**：
- 方向卡 `fit` 里若方向内原文对专业说法不一致，写「这几条原文对专业的写法不一致，以具体岗位为准」；
- `relatedJobs` 卡片保留单条结论，但加一句「这条原文写的是另一类岗位」。

### 1.3 「入场线」与结尾「原文全部过期」自相矛盾

**现象**：方向卡给「入场线：学历…经验…」，方向块结尾又写「原文全部是 2024 年及更早的公告，只能观察要求结构」。

**修复**：统计层由 `9-` 的 P0 覆盖（过期原文不进统计）。本文只补文案规则：**一旦有 stale 原文参与，`entry` 必须带「仅看要求结构，不能当投递入口」的前缀**。
