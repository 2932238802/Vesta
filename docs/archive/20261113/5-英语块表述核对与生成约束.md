## 一、一句话确认

**大方向准确，但有两处硬伤、一处待核**：四六级已过、听力是四级丢分项、背单词 App / 刷真题 / 看剧看视频 / 跟课四类做法都属实；但「先听力，再口语」的排序、「口语不追求流利」的目标，答卷里都没有依据；「你写的原因是没人教方法」把 Q24 的多选压成了单因，需要回后台核对原始答卷。

## 二、逐句核对

| # | 报告原句 | 判断 | 依据 / 问题 |
| --- | --- | --- | --- |
| 1 | 补的顺序是先听力，再口语 | ❌ 无依据 | Q22 只说口语「能听懂、也能说几句、但不流利」，Q23 只说四级里听力丢分最多。没有任何一题问「先补哪个」，也没有任何答案说不练口语。排序是模型自己加的。 |
| 2 | 听力用刷真题加跟课的方式验证：同一套题隔一段时间重做，看错的地方是不是同一类 | ⚠️ 半准确 | 「刷真题」「跟课」来自 Q25；「同一套重做、看错处是否同类」是模型追加的验证方法，不是她写的。作为建议可以，但不能读成她现在的做法。 |
| 3 | 口语不追求流利，先做到能把一段话说完、说清，用录音回听来验证 | ❌ 越界 | 「不流利」是 Q22 的现状，不是她的目标。英语师范 + 考研（复试要开口）+ 教师岗，口语是硬需求；报告替学生把目标降了档。录音回听本身可行，但要放在「口语也要练」的框架下。 |
| 4 | 你写的原因是没人教方法 | ⚠️ 待核 | Q24 是多选，只写这一项等于把多因压成单因。若她还选了「记不住 / 没时间 / 坚持不下来」等，这里就漏了。需回后台看原始答卷。 |
| 5 | 方法这一层可以从现有做法里收：背单词 App、刷真题、看剧看视频、跟课都在用 | ✅ 准确 | Q25 四项全选，逐字对得上。 |
| 6 | 缺的是把听力单独拎出来练，而不是混在整体英语里 | ⚠️ 基本成立 | Q25 四项都是通用英语练法，没有一条听力专项，判断站得住；但「缺的是」太绝对，改成「没有一条是专门冲听力的」更稳。 |

**跨模块补充**：gap 段写「对不上的是听力这一层……而英语又是考研里绕不开的一门」。如果目标是考研初试，英语一/二初试不考听力，只有复试考；这句把「听力弱」和「考研」直接挂钩，容易被懂行的老师抓住，建议限定为「复试」或「雅思托福这类要考听力的考试」。

## 三、改写稿（可直接替换报告里的英语块）

> 按咨询师意见改：① 不让人觉得口语不重要；② 暗示需要系统性学习，但不出现「报班 / 报课」；③ 自然带一句大学课堂的普遍局限。三小段，嫌长可把第 3 段并进第 2 段。

**第一段**

听力和口语不是二选一，两样都要补，但练法不一样。听力可以先把单独的一条线拉出来：四级里你明确丢分的是听力，混在整套题里刷，它最容易被阅读和写作的平均分盖过去。验证还是用真题——同一套隔一段时间重做，看错的地方是不是还是同一类；跟课也只盯这一类，别整段泛听过去。

**第二段**

口语也要练，而且不用等「流利」才开始：听完一段，用自己的话复述、录下来回听，和听力共用材料，既练耳朵也练开口。你说学不好是因为没人教方法，这句话要拆开看：方法不是没有，背单词 App、真题、视频、课你都在用；缺的是有人把「听力该怎么单独练、练到什么程度算过」讲清楚——这四样都是通用英语的练法，没有一样是专门冲听力的。

**第三段**

大学课堂也很难补上这一层。现在这套「老师讲、学生记、期末考」的上课方式，最早是第一次工业革命时期为了批量培养人留下来的；知识点更新慢，PPT 和教材一届传一届。英语课讲语法、讲课文，但很少讲怎么单独练听力、怎么判断自己真的听懂了。所以「没人教方法」不怪你，是这条线得自己搭，或者找人把顺序和方法讲一遍。

## 四、改动说明

1. **去掉「先听力，再口语」的排序**。改成「两样都要补，听力先单独成线，口语同步练」——保留听力优先级，又不给「口语可以往后放」的暗示，正面回应「口语怎么会不重要」的反问。
2. **把「口语不追求流利」改成「不用等流利才开始」**。原文是替学生降目标；改后只降启动门槛、不降目标，也避免和 Q22「能听懂、能说几句、但不流利」的现状混为一谈。
3. **把「没人教方法」拆成「方法已有、缺的是听力专线和验证标准」，并补一句大学课堂的普遍局限**（工业革命上课模型、PPT / 教材传代）。这样「没人教方法」和「缺的是把听力单独拎出来练」就接上了：不是缺资源，是缺一条被讲清楚的训练线；同时暗示需要系统学，但没有出现「报班 / 报课」。

## 五、代码现状：英语块是怎么写出来的

### 5.1 链路

1. `buildDocReport()`（`shared/src/doc.ts:1064`）把 `englishSection()`（`doc.ts:1056`）排进 blocks 末尾（`doc.ts:1093`）。它只给结构：`type: 'section'`、`title: '英语这块'`、`paragraphs: []`。
2. `buildModuleSpecs()`（`server/src/ai/doc-prompts.ts:185-196`）把它转成 spec：`key: 'english'`、`kind: 'english'`、`paragraphsRequired: true`、`items: []`，`data: { ...scores.english }`。
3. `computeDocScores().english`（`shared/src/docScore.ts:383-397`）产出 `need / pathNeeds / preparing / skippedDetail / stage / weeklyHours / weakPart / speaking / reasons`；`weeklyHours` 是 Q26 档位的中点（`docScore.ts:84`）。
4. `generateDocContent()`（`server/src/ai/doc-generate.ts:70-142`）把「Skill + 机器约束 + 答卷 + moduleSpecs + jobSpecs + 检索记录」发给模型，模型写 `title` 和 `paragraphs`。
5. 生成后过五道校验（`doc-generate.ts:156-206`）：`contentProblems`（完整性）、`crossModuleIssues`（跨模块）、`repetitionIssues`（去重）、`findTextIssues`（文本规则）、`auditNumbers`（数字）。不过先反馈重写一轮，仍不过整份失败。
6. 渲染时 `applySystemModules()`（`shared/src/doc.ts:1296-1300`）按 `block.type === 'section'` 取 `modules.get('english')`，用 AI 的 `title` 和 `paragraphs` 覆盖。

> 部署端如果后台 `/admin/skill` 启用的是自定义模板，实际喂给模型的 skill 文本可能和仓库默认稿不同；下面的约束结论以仓库默认稿（`shared/src/doc-skill.ts`）为准。

### 5.2 问题

**P0-1｜英语块没有专属写作规则，模型只能自由发挥。**
英语唯一的专属约束是 `shared/src/doc-skill.ts:61` 那一句「英语只在目标相关处出现；不要写英语不重要……需要补时写清补哪一层、怎么验证」，加上 `outputContract()`（`server/src/ai/doc-prompts.ts:291`）的「不要重复每周投入和总时长」。**没有**规定：口语不能降级、顺序 / 优先级断言要有材料、原因要按多选列、可以点一句大学课堂的普遍局限。本例里「先听力，再口语」「口语不追求流利」都出自模型自由发挥，且全部通过校验。

**P0-2｜校验规则和 Skill 不一致，「英语不重要」本身没被拦。**
`findTextIssues`（`server/src/ai/doc-audit.ts:297`）只拦 `没有硬性门槛 | 保持阅读和表达就够了 | 英语不是(重点|主线)`；Skill 明令禁止的「英语不重要」原句**能通过**。也没有对「口语不追求流利」「先听力再口语」这类表述的检查。

**P0-3｜「英语块只写怎么补、怎么验证」没有校验兜底。**
`scores.english.weeklyHours` 仍随 spec data 下发（`doc-prompts.ts:194`），模型完全可以在英语块写「每周 17.5 小时」；`repetitionIssues` 只查时间距离、目标城市、「缺一段经历」，不查英语时长。设计文档 6.2 要求英语块去重，目前只靠 prompt 自觉。

**P1-1｜字段语义缺失，`skippedDetail` 是死字段。**
`need / pathNeeds / preparing / skippedDetail` 只在 `docScore.ts` 里算出来，全仓库没有消费点（`grep` 仅命中定义处），只作为裸布尔进了 moduleSpecs，模型不知道含义。`skippedDetail` 本意是「Q20 < 6 分的人后面 5 题按规则跳过，不是没答」，`docs/development-history.md:298` 提过要补，当前代码没有落地。

**P1-2｜Q24 多选没有「逐条原因」约束。**
模型习惯写成「你写的原因是 X」。Q27「背了忘、忘了背」和 Q24「记不住」还可能同义重复，`crossModuleIssues` 目前只覆盖 gap / scorecard 和 jobmap 字段，没有这一层。

**P1-3｜考研 × 听力的事实风险没有校验。**
`findTextIssues` 不检查考试科目事实；「考研初试不考听力」这种常识性错误只能靠人工看。

**P2-1｜渲染层硬编码。**
`applySystemModules` 对任何 `section` 都取 `modules.get('english')`（`doc.ts:1296-1300`）。目前只有一个 section，扩第二个就会串。

**P2-2｜标题没有 hint。**
`englishSection()` 固定写「英语这块」，但会被 AI 覆盖，spec 里没有 `titleHint`，标题风格每次随机（本例是「英语这一层怎么补」）。

**P2-3｜没有文本回归测试。**
`npm run verify` 只覆盖 check:docs / check:dates / typecheck / build；报告文本质量只能靠人工抽看，改 prompt 后没有对照物。

### 5.3 可优化项

| 优先级 | 改什么 | 位置 | 预期 |

## 六、验证方式

- 只改文档：`npm run check:docs`。
- 若按 5.3 改代码：`npm run verify`；再用后台报告预览（`server/src/routes/admin/settings.ts:204` 的 `/report/preview`）或同一份答卷重跑，重点核对：
  1. 口语表述不再降级；
  2. 顺序 / 优先级断言有材料支撑；
  3. Q24 多选逐条呈现，没有被压成单因；
  4. 英语块不出现「每周 X 小时」；
  5. 「考研 + 听力」不再直接绑定初试。
- 上线前建议用同一份答卷重跑一次，对照改写前后，确认改写稿能通过新增校验。
