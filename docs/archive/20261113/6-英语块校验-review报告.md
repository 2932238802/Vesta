## 二、问题 1：「考研 + 听力」校验会误伤

### 现状

`crossModuleIssues()` 新增的逻辑（`server/src/ai/doc-audit.ts:125-135`）：

```ts
if (!/考研/.test(text) || !/听力/.test(text)) continue
const examBinding =
  /听力[^。；\n]{0,12}考/.test(text) || /考[^。；\n]{0,6}听力/.test(text)
if (!examBinding) continue
if (/复试|雅思|托福|不考|不用考|无需|不需要/.test(text)) continue
issues.push(`${where} 把「考研」和「听力考试」直接写在一起；……`)
```

实际语义是：**同一段里只要「考研」和「听力」在 12 字内共现，就当作「说初试考听力」**。它不要求文本真的出现「考试 / 考听力」这层意思。

### 复现（已实测）

用 `tsx` 直接调用 `crossModuleIssues()`（一次性脚本，未入库；样例即下表）。

| 样例 | 期望 | 实际 |
| --- | --- | --- |
| 「对不上的是听力这一层，而英语又是考研里绕不开的一门」 | 拦（原问题句） | 拦 ✅ |
| 「考研初试不考听力，复试才考」 | 放行 | 放行 ✅ |
| 「考研复试要考听力，所以现在就得练」 | 放行 | 放行 ✅ |
| 「考研和听力是两件要一起抓的事」 | 放行 | **误拦** ❌ |
| 「如果走考研，听力要早点练」 | 放行 | **误拦** ❌ |

原因：`/考[^。；\n]{0,6}听力/` 会把「考研和听力」「考研，听力」里的「研」也算成间隔；`/听力[^。；\n]{0,12}考/` 也能一路匹配到「考研」里的「考」。

### 影响

- 第一次校验失败 → 反馈重写一轮；第二次仍然写成这种句式 → `doc-generate.ts` 抛 `AI 报告前后矛盾：…`，整份报告失败。
- 对学生报告来说这是「假错误」，顾问只看到生成失败，排查成本高。

### 建议修复

把触发条件收紧到真正表达「考试考听力」的句式，而不是单纯共现。例如要求同段同时命中：

- 考试语义：`/初试|复试|考试|科目|要考|加试/`
- 听力被考：`/听力[^。；\n]{0,8}(考|计入|占分)/` 或 `/考[^。；\n]{0,4}听力/`

并且保留现有白名单词（`复试 / 雅思 / 托福 / 不考 …`）做放行。修复后至少补 5 条正反样例：

1. 考研 + 听力但没提考试 → 放行
2. 考研初试考听力 → 拦
3. 考研初试不考听力 → 放行
4. 考研复试考听力 → 放行
5. 雅思托福考听力 → 放行

## 三、问题 2：正则覆盖不全、时长去重偏严

### 2.1 口语 / 顺序表述有逃逸写法

现状正则（`server/src/ai/doc-audit.ts:319`）：

```ts
/口语[^。；\n]{0,8}(不追求|不用管|不重要|往后放)
 | 先[^。；\n]{0,4}听力[^。；\n]{0,6}再[^。；\n]{0,4}口语/
```

已知能绕过的写法：

| 写法 | 是否被拦 | 说明 |
| --- | --- | --- |
| 「口语不追求流利」 | 拦 ✅ | 正则预期句式 |
| 「不追求口语流利」 | **漏拦** ❌ | 「不追求」在「口语」前面，语序倒置 |
| 「口语先放一放」 | **漏拦** ❌ | 「放一放」不在关键词表里 |
| 「听力优先，口语以后再说」 | **漏拦** ❌ | 没有「先…再…」结构 |
| `先听力\n再口语`（跨行） | **漏拦** ❌ | 字符类 `[^。；\n]` 排除了换行 |

影响：模型换一种说法就能通过校验，规则只能兜住最典型的三种原句。

建议：

- 增加反向语序：`(不追求|不用管|不重要|放一放|往后放|以后再说)[^。；\n]{0,6}口语`。
- 匹配前先把段内换行压成空格（或字符类改用 `[^。；]`），避免跨行逃逸。
- 关键词表补「放一放 / 缓一缓 / 以后再说 / 靠后」。

### 2.2 英语块「每周 / 小时」去重偏严

现状（`server/src/ai/doc-audit.ts:181`）：

```ts
if (moduleKey === 'english' && /每周|小时/.test(flat)) {
  issues.push(`${where} 重复了英语的每周投入 / 总时长；……`)
}
```

问题：只要出现「每周」或「小时」就判重复，不看它是不是在复述问卷的每周投入。实测：

| 英语块原文 | 期望 | 实际 |
| --- | --- | --- |
| 「每周练 5 小时」 | 拦（复述投入） | 拦 ✅ |
| 「每周末做一套真题，隔周重做」 | 放行（验证节奏建议） | **误拦** ❌ |
| 「每天 1 小时听力」 | 待定（建议 vs 时长） | 拦（按当前规则） |

影响：AI 为了避开「每周」二字，会写出不自然的排课建议，或者被迫删掉「每周末」这种正常表达；重写一次仍写「每周末」就整份失败。

建议（二选一，先定产品口径）：

1. **严格口径**（英语块完全不写时间）：保留现状，但把提示词/反馈文案写清「不要出现任何时间安排，包括每周末」，让模型知道边界。
2. **只拦复述**：改成匹配「每周 + 数字/档位 + 小时」或直接匹配 `weeklyHours` 的档位值（如 `17.5 小时`），「每周末做一套真题」这类节奏不计入。

无论选哪种，都应补「每周末 / 每天 X 小时 / 每周 X 小时」三条样例固化。
