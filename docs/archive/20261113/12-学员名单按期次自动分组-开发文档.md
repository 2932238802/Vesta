# 学员名单按期次自动分组 · 开发文档

> 版本：v1.0（2026-11-13）　状态：**已实施**（代码在工作区，待提交；产品版本 v1.74）
> 一句话：把「管理分组 + 勾选 + 移到分组…」和「可涂色日期筛选」整块删掉，学员名单按咨询期次自动归组——一期 = 周三 00:00 → 下周二 23:59:59，顶部只留一排期次，点一下只看这一期。
> 决策来源：2026-11-13 与杰哥的交互式讨论，结论见第一节；方案目录索引见 [README.md](./README.md)。

## 一、需求与已拍板口径

**使用者**：在野（杰哥女朋友，咨询师），一周一期带学员。她的反馈是「分组这一步的交互太复杂」。

| # | 已确认结论 | 说明 |
| --- | --- | --- |
| 1 | **一期 = 周三 00:00 → 下周二 23:59:59**（7 天） | 周三、四、五、六、日、一 在同一轮里；周二算这一期的尾巴，不单独成期 |
| 2 | **归期看「邀请链接创建时间」**（`invites.created_at`） | 她哪周发的链接，学员就属于那期；学员晚几天才填不会跳到下一期。与现在日期筛选的口径一致 |
| 3 | **手动分组 + 日期筛选全部去掉** | 不再建组、不勾选归类、不再涂色选日期；顶部只保留「期次」一排 |
| 4 | **期次只显示日期区间** | chip 文案「11/11–11/17」，不引入「第 N 期」概念 |

**不在本次范围**：期次改名/备注、按期的统计报表、给某期未提交学员群发提醒、单期单独设截止时间、把历史自定义分组数据迁成期次。

## 二、现状（改之前的代码事实）

### 2.1 页面由三层控件叠出来

`web/src/views/admin/Submissions.vue` 依次组合：

1. `RosterCategoryTabs`：状态 tab（全部 / 未填写 / 已提交未领取 / 待联系 / 已联系 / 已约时间 / 已完成）。
2. `RosterGroupBar` + `RosterGroupPanel`：自定义分组 chip 行 +「管理分组」面板（新建、改名、删除、恢复、已删除分组）。
3. `RosterDateFilter`：可涂色的邀请日期筛选，另有「管理日期分类」（删除 / 恢复某个日期）。
4. `RosterToolbar`：没勾选时是搜索框；勾选后变成「已选 N 条 + 移到分组… 下拉 + 批量删除」。

### 2.2 她每周实际要走的动作

1. 点「管理分组」→ 输入组名 → 新建分组；
2. 回表格逐行勾选本周学员（勾错要反选，没有「按日期一键选中」）；
3. 工具栏出现「移到分组…」下拉 → 找到组名 → 归类；
4. 想看本期就点对应 chip；旁边还有一套日期筛选与它并行生效。

也就是**分组、勾选、归类是三件事**，而且「分组」和「日期筛选」是两套语义重叠的筛选同时存在。

### 2.3 数据与接口

- 表：`roster_groups`（软删除 `deleted_at`）、`roster_hidden_dates`（隐藏的日期）、`invites.group_id`（一条记录只能在一个组）。
- 接口：`GET /api/admin/roster`（参数 `q` / `category` / `group` / `dates`；返回 `roster` / `counts` / `groups` / `deletedGroups` / `ungrouped` / `dates` / `hiddenDates`）。
- 写接口 7 个：`POST /roster/groups`、`PATCH /roster/groups/:id`、`DELETE /roster/groups/:id`、`POST /roster/groups/:id/restore`、`POST /roster/assign`、`DELETE /roster/dates/:date`、`POST /roster/dates/:date/restore`。
- 相关前端文件：`useRoster.ts`（状态与日期涂色逻辑）、`useRosterActions.ts`（分组/日期动作）、`rosterMeta.ts`（日期标签、行底色）、`web/src/api/admin.ts`、`web/src/api/types.ts`。
- 这套自定义分组是 2026-11-10 深夜按当时需求加的（见 `docs/development-history.md`「答卷与名单：自定义分组」），现在被周更周期推翻。

### 2.4 一个顺带要修的隐患

`server/src/routes/admin/shared.ts` 的 `localDateKey()` 用 `new Date(iso)` 的**服务器本地时区**取年月日。生产 systemd 环境没设 `TZ`（仓库里也搜不到），默认是 UTC，于是「邀请日期」在 00:00–08:00 之间会算成前一天。本期次计算不沿用它，改为**显式固定 Asia/Shanghai（+08:00）**，见第四节。

## 三、目标交互

### 3.1 页面结构

```text
学员名单                                      128 人   [导出答卷 CSV]
[全部 128] [本期 11/11–11/17 · 12] [上期 11/04–11/10 · 9] [10/28–11/03 · 15] … →横向滚动
[全部] [未填写] [已提交未领取] [待联系] [已联系] [已约时间] [已完成]        ← 状态 tab 保留
[搜索姓名、备注、渠道（/ 搜索）]
┌───────────────────────────────────────────────────────────────┐
│ ☐ 学员   阶段   优先级   领取/联系   时间        操作          │
└───────────────────────────────────────────────────────────────┘
```

- 第一行期次 chip，**默认选中「本期」**；「全部」永远排最左。
- 原来的「管理分组」入口、管理面板、日期筛选卡片、可涂色日期条、行底色**全部删除**。
- 表格里的分组标签（`group-tag`）删除；「时间」列仍显示邀请 / 提交 / 到期时间。

### 3.2 行为规则

| 场景 | 表现 |
| --- | --- |
| 进入页面 | 默认「本期」；本期 0 人也保留 chip（她周三打开就能看到新一期） |
| 期次排序 | 全部 → 本期 → 上期 → 更早，倒序；**没有记录的期次不出 chip** |
| 期次很多 | chip 行横向滚动，进入时把「本期」滚进可视区；不再加「展开/收起」按钮 |
| 切期次 | 服务端按 `week` 过滤，状态 tab 的计数跟着这一期重算 |
| 搜索 | 在**当前期次内**搜；搜不到时空状态给「在全部期次里搜」按钮（切到全部、保留关键词） |
| 勾选 | 只服务「批量删除」；选中条不再出现「移到分组…」 |
| 导出 CSV | 跟随当前期次 + 状态 tab（见 5.4） |
| 本周 0 人 | 空状态文案「本期（11/11–11/17）还没有学员」+「去生成邀请链接」 |
| 某状态 0 人 | 空状态「这一期没有待联系的学员」+「看全部状态」 |
| 跨周 | 刷新 / 重新加载时按当前时间重算本期，不要求页面停留时秒级切换 |
| 旧链接 | `?group=`、`?dates=` 参数直接忽略，不报错；`?category=` 继续有效 |

### 3.3 文案约定

- 期次 chip：`本期 11/11–11/17`、`上期 11/04–11/10`、更早的只写 `10/28–11/03`。
- 日期区间格式 `MM/DD–MM/DD`，跨年显示 `12/30–01/05`（年份放在 `title` 属性里，不占 chip 宽度）。
- 不再出现「未分组」「分组管理」「移到分组」「日期分类」这些词。

## 四、期次算法

### 4.1 定义

- 一期 7 天：`start`（周三）00:00:00 → `start + 6 天`（周二）23:59:59.999，**固定 Asia/Shanghai (+08:00)**。
- 星期二属于「6 天前那个周三」开的那一期（即这一期的尾巴）。
- 归期字段：`invites.created_at`（ISO UTC 字符串，`server/src/db/core.ts` 的 `now()` 写入）。

### 4.2 计算

放在新文件 `shared/src/cycle.ts`，前后端共用（后端过滤、前端 chip 都调它）：

```ts
const SHANGHAI_OFFSET_MS = 8 * 60 * 60 * 1000
const DAY_MS = 24 * 60 * 60 * 1000

/** 把任意时间归到所在期次的「周三」日期键（YYYY-MM-DD，上海时区）。 */
export function cycleStartKey(value: string | Date): string {
  const date = typeof value === 'string' ? new Date(value) : value
  if (Number.isNaN(date.getTime())) return ''
  // 先平移到上海墙钟，再用 UTC getter 读年月日，避免依赖服务器 TZ。
  const local = new Date(date.getTime() + SHANGHAI_OFFSET_MS)
  const dayIndex = Math.floor(
    Date.UTC(local.getUTCFullYear(), local.getUTCMonth(), local.getUTCDate()) / DAY_MS
  )
  const weekday = new Date(dayIndex * DAY_MS).getUTCDay() // 0=周日 … 6=周六
  const back = (weekday + 4) % 7 // 周三=0、周四=1、周五=2、周六=3、周日=4、周一=5、周二=6
  const start = new Date((dayIndex - back) * DAY_MS)
  const pad = (n: number) => String(n).padStart(2, '0')
  return `${start.getUTCFullYear()}-${pad(start.getUTCMonth() + 1)}-${pad(start.getUTCDate())}`
}
```

配套导出：

- `cycleRange(startKey)` → `{ start, end }`（`end = start + 6 天`，均为 `YYYY-MM-DD`）。
- `cycleLabel(startKey)` → `11/11–11/17`；跨年 `12/30–01/05`。
- `currentCycleKey(now = new Date())` → `cycleStartKey(now)`。

`back` 取值校验：周三 `(3+4)%7=0`、周四 1、周五 2、周六 3、周日 4、周一 5、周二 6。

### 4.3 边界样例（写进 `shared/src/cycle.cases.ts`）

| 时间（上海） | 归到 | 说明 |
| --- | --- | --- |
| 2026-11-11（周三）00:00:00 | 11/11–11/17 | 新一期起点 |
| 2026-11-10（周二）23:59:59 | 11/04–11/10 | 上一期的最后一秒 |
| 2026-11-17（周二）23:59:59 | 11/11–11/17 | 周二归本期尾巴 |
| 2026-11-18（周三）00:00:00 | 11/18–11/24 | 下一期起点 |
| 2026-10-21（周三） | 10/21–10/27 | 跨月 |
| 2026-10-28（周三） | 10/28–11/03 | 跨月 |
| 2026-12-30（周三） | 12/30–01/05 | 跨年 |
| 2026-11-10T16:30:00Z（= 上海 11-11 00:30） | 11/11–11/17 | 时区：UTC 字符串按上海墙钟归期 |
| 邀请 11/12 建、11/20 才提交 | 11/11–11/17 | 归期只看邀请时间，提交晚不跳期 |

用例接入检查：`package.json` 的 `check:dates` 改为同时跑 `shared/src/date.cases.ts` 与 `shared/src/cycle.cases.ts`（保持一个脚本入口，`npm run verify` 自动覆盖）。

## 五、接口与数据

### 5.1 `GET /api/admin/roster`

参数：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `q` | 关键词 | 不变 |
| `category` | 状态 tab key | 不变 |
| `week` | `YYYY-MM-DD`（期次起点）或 `all` | 新增；缺省按 `all`，兼容旧调用 |

返回（删除 `groups` / `deletedGroups` / `ungrouped` / `dates` / `hiddenDates`）：

```json
{
  "roster": [{ "week": "2026-11-11", "...": "其余字段不变" }],
  "counts": { "all": 12, "unsubmitted": 3, "new": 5 },
  "weeks": [
    { "key": "2026-11-11", "start": "2026-11-11", "end": "2026-11-17", "label": "11/11–11/17", "count": 12, "current": true },
    { "key": "2026-11-04", "start": "2026-11-04", "end": "2026-11-10", "label": "11/04–11/10", "count": 9 }
  ],
  "currentWeek": "2026-11-11"
}
```

- `weeks` 由「按 `q` 过滤后的全部记录」聚合，倒序；本期永远在列（哪怕 0 人）。
- `counts` 按「选中期次 + `q`」聚合，语义与现在一致（`unsubmitted` = pending + opened + expired）。
- 每行新增 `week`，并删掉 `groupId` / `groupName`。

### 5.2 删除的写接口

`POST /roster/groups`、`PATCH /roster/groups/:id`、`DELETE /roster/groups/:id`、`POST /roster/groups/:id/restore`、`POST /roster/assign`、`DELETE /roster/dates/:date`、`POST /roster/dates/:date/restore` 全部删除；`web/src/api/admin.ts` 对应方法（`createRosterGroup` / `renameRosterGroup` / `deleteRosterGroup` / `restoreRosterGroup` / `assignRosterGroup` / `hideRosterDate` / `restoreRosterDate`）一并删除。

**数据不动**：`roster_groups`、`roster_hidden_dates`、`invites.group_id` 原样保留，只是不再读写。`schema.ts` 里加一行注释标明「历史数据，界面已不再使用」，不做删除、不做迁移。

### 5.3 没有数据库变更

期次是纯派生值，不建表、不加字段，**上线不需要数据迁移，也不需要备份后改库**（常规备份照做）。

### 5.4 导出 CSV（小改）

现在 `GET /api/admin/submissions/export.csv` 只认 `q`。改为同时接受 `week` 与 `category`，让「导出这一期 / 这个状态」成立；前端 `exportCsv()` 带上当前 `week`、`category`。文件名不变。
