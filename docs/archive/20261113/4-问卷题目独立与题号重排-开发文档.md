## 一、需求

1. 不再由 Q5「毕业后想从事本专业相关的工作吗」决定是否显示——所有人都会看到。
2. 位置占**第 6 题**：Q1–Q5 不变，它成为新 Q6，原来的 Q6 及之后全部顺延一位。
3. 题号整体重排为**连续 Q1–Q28**（用户已确认，不再保留 Q5a 这种带字母的编号）。
4. 仍然**可以跳过**（`required: false`），不阻断提交（用户已确认）。

## 二、现状（改动前的事实）

### 2.1 题目本身

- 定义：`shared/src/survey.ts` 中 `id: 'q5a'`、`code: 'Q5a'`，`type: 'text'`，`required: false`，`hint: '可跳过'`，占位符「例如：跨境电商运营、小学英语老师」。
- 显示条件：`showIf: { question: 'q5', when: ['q5_2', 'q5_3'] }`（`shared/src/survey.ts:96`），即 Q5 选「不想」「还没想清楚」才出现；渲染由 `shared/src/doc.ts` 的 `resolveQuestion()` 处理（`showIf` 不满足返回 `visible: false`），提交校验由 `shared/src/validate.ts:130` 跳过隐藏题。
- 数组位置：第 6 个，夹在 `q5` 和 `q6` 之间。

### 2.2 题号体系

- 共 28 个题项，显示编号是 `Q1–Q27` 外加条件题 `Q5a`；分组表见 `docs/规划自测问卷-设计文档.md` §三。
- **`id` 与 `code` 早已脱钩**，不是一一对应：例如 `id: 'q27'` 是 Q9 理想薪资、`id: 'q28'` 是 Q10 我眼中的自己、`id: 'q9'` 是 Q11 实习实践。改题号只需改 `code`，`id` 是答卷数据的键，不能动。

### 2.3 题号被哪些地方使用

| 用途 | 位置 | 说明 |
|---|---|---|
| 问卷页显示 | `web/src/views/Quiz.vue` | **不显示题号**，只用题干、分组名；顺序由 `visibleQuestions()` 的数组顺序决定 |
| 后台问卷编辑器 | `web/src/views/admin/SurveyEditor.vue` | 显示并允许编辑 `question.code`；默认问卷会看到新编号 |
| 后台答卷详情 | `server/src/routes/admin/submissions.ts:158` | 按**当前** survey 动态拼 `code`，历史答卷会显示新编号 |
| 文档一致性检查 | `scripts/check-docs.mjs:30-40` | 从 `survey.ts` 解析 `code` + `title`，要求设计文档里有 `**Qn 题干` |
| 报告分数来源文案 | `shared/src/docScore.ts`（source 字段）、`shared/src/doc.ts`（assets 块） | 用户可见的「来源」文字，含题号 |
| AI 提示词/审计注释 | `server/src/ai/doc-prompts.ts:290`、`server/src/ai/doc-audit.ts` | 文字里提到「Q8」，不影响报告正文，但应保持一致 |
| 咨询稿导入 | `web/src/composables/useConsultImport.ts:67` | 用 `answer.code` 拼题号前缀；历史导入文本已落库，不回溯 |

### 2.4 问卷持久化与迁移

- 问卷存在 `surveys` 表；`getActiveSurvey()` 读 `settings.active_survey`。
- 启动迁移 `migrate()` 只升级**当前启用**的那一份（`server/src/db/migrations.ts:412-438`）：
  - `customized: false` 的问卷：`surveyShape()` 与 `defaultSurvey` 不同时**整份替换**为默认问卷 → 改 `defaultSurvey` 的 code 会自动生效。
  - `customized: true` 的问卷：只执行 `patchQ17EnglishStage` / `patchQ18Multi` / … 这些零散补丁，**不会整份覆盖** → 需要新增补丁（见 §5.6）。

### 2.5 数据与草稿

- 答卷 `answers` 以 **`id`** 为键（`web/src/views/Quiz.vue:49`、`shared/src/validate.ts`），不是 `code`。改题号对历史答卷零迁移。
- 本机草稿存 `{ surveyId, answers, step, timing }`，`step` 是**可见题数组的下标**（`web/src/views/Quiz.vue:280`）。本次数组顺序不变（`q5a` 本来就在 `q5` 之后、`q6` 之前），所以旧草稿恢复不会错位。

/** Q5a 独立成题：去掉「仅当 Q5 选不想/没想清楚才显示」的条件。 */
function patchQ5aIndependent(questions: Survey['questions']): boolean {
  const q5a = questions.find((q) => q.id === 'q5a')
  if (!q5a || !q5a.showIf) return false
  delete q5a.showIf
  return true
}

## 六、兼容性与数据

| 项 | 结论 |
|---|---|
| 历史答卷 | `answers` 按 `id` 存，**零迁移**；报告重算（如后台触发）仍能取到原答案 |
| 旧答卷里 Q5=「想」的人 | 当时 `q5a` 被隐藏、没答；新报告里 Q6 为空，走既有兜底（`doc.ts` 目标岗位为空时回落专业名；`cityScore` 空值不加分），与旧行为一致 |
| 本机草稿 | 数组顺序不变，`step` 下标仍对应同一题，兼容 |
| 后台答卷详情 | 按当前 survey 动态显示新编号；历史答卷不会存旧 code 快照，显示会是新编号，需要在交付说明里告知运营 |
| 非定制问卷 | 启动迁移自动整份对齐新 `defaultSurvey` |
| 定制问卷 | 只自动去掉显示条件，编号保持运营现状；要统一编号需重新发布 |
| 已生成报告 | 不重新生成，报告里的旧编号文案保持原样（历史快照） |
| 咨询稿导入 | 新导入用新编号，历史导入文本不回改 |

## 九、风险与回滚

- **定制问卷迁移不可逆**：`patchQ5aIndependent` 只删 `showIf`，但删了就回不去；执行前先 `VACUUM INTO` 备份 `data/vesta.db`（SQLite WAL 场景必须用这种方式）。
- **报告 source 文案变化**：用户可见「来源」里的题号会变，属于预期；已生成报告不受影响。
- **运营沟通**：历史答卷在后台显示新编号，旧编号（Q5a、Q11…）会消失，需要提前告知。
