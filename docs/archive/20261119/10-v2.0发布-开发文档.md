## 3. 关键设计

### 3.1 版本规则

- `version` 仍为 `MAJOR.MINOR.PATCH`；`patch` 恒为 0。
- `major` 从 1 起可递增（v2.0 起允许）。
- 产品版本 `v<major>.<minor>` ↔ `version = <major>.<minor>.0`。

### 3.2 `check-version.mjs`

- 校验：`major >= 1`、`patch === 0`。
- 从 `reference/README.md` 的“已完成”行解析全部 `v<major>.<minor>`，取最大版本（按数值比较，不按字符串）。
- 规则：文档最高版本与 `package.json` 相等，或 package 比文档领先 1 个小版本（文档领先一律失败；按 `v<major>.<minor>` 数值比较，`v1.99` 与 `v2.0` 相邻）。
- 错误信息更新，不再写“必须是 1 / 不进位到 v2”。

### 3.3 文档

- `reference/README.md`：
  - “已完成”行追加 `v2.0 知识库导入与编辑体验（在野知识库试点导入、大学常识大纲、所见即所得编辑器、页面文案清理）`；
  - “后续从 **v2.1** 继续递增”；
  - 当前版本 `2.0.0`；
  - 版本表新增 v2.0 行（commit 待发布）。
- `development-history.md`：新增 v2.0 小节。
- 归档版本规范：更新“major 恒为 1”为“v2.0 起允许 major 递增，patch 仍恒为 0”。

### 3.4 后台左下角版本号（AC-015-7）

- `web/vite.config.ts` 在构建时读取根 `package.json` 的 `version`，用 `define: { __APP_VERSION__: JSON.stringify(version) }` 注入；不新增依赖。
- `web/src/env.d.ts` 声明 `declare const __APP_VERSION__: string`。
- `AdminLayout.vue` 在侧栏账号区（左下角）显示 `v{{ appVersion }}`；样式低调（11px、`--ink-3`、不换行），390px 单列布局不溢出。版本号不手写，避免与 `package.json` 漂移。
