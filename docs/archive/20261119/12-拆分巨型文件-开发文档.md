## 3. 关键设计

### 3.1 migrations

- 入口 `server/src/db/migrations.ts` 只保留 `runMigrations()` 编排与导出，≤120 行。
- 拆分建议：
  - `db/migrations/columns.ts`：`ensureInviteColumns` / `ensureSubmissionColumns` / `ensureConsultColumns` / `ensureScoreLineColumns` / `backfillSubmissionReportModes`
  - `db/migrations/survey.ts`：问卷 patch 系列与 `upgradeSurvey`
  - `db/migrations/template.ts`：`upgradeTemplate`
  - `db/migrations/consult-quotes.ts`：`readConsultQuoteSeed` / `seedConsultQuotes`
  - `db/migrations/scoreline.ts`：`migrateScoreLineV1`
  - `db/migrations/seed.ts`：初始 `seed()`
- **执行顺序必须与现在完全一致**；每步仍是幂等。

### 3.2 runs

- 入口 `routes/consult/runs.ts` 或 `runs/index.ts` 只装配 router，≤100 行。
- 按职责拆分：
  - `runs/crud.ts`：列表、创建、详情、outcome、retry
  - `runs/sections.ts`：章节增改删、beats、按章节重新生成
  - `runs/export.ts`：导出
  - `runs/shared.ts`：公共查询/校验/序列化
- 路由注册顺序保持不变，避免 `/:id` 与静态路径冲突。

### 3.3 ReportView

- 页面骨架 ≤200 行；模板区块拆为 `components/report/` 下子组件。
- 样式移到 `reportView.css`（`<style scoped src>` 或等价方式），保持 scoped 作用域与现有视觉。
- 交互、打印、主题变量、数据流不变。

### 3.4 版本显示与规模

- 后台左下角版本号显示规则：`v<major>.<minor 两位>`，即 `2.1.0` 显示为 `v2.01`；由构建注入的版本号格式化，不在源码手写。
