## CR-015 发布 v2.0

- **类型**：版本发布
- **背景**：本轮完成了知识库内容导入、大学常识大纲与所见即所得编辑等能力，用户确认按 v2.0 发布。现有版本规则强制 major 恒为 1，需要同步调整校验脚本与文档，否则 `check:version` 会失败。
- **描述**：
  - 产品版本从 `1.99.0` 升到 `2.0.0`；
  - 版本规则改为：`major` 可递增（当前 2），`patch` 恒为 0，`minor` 递增；
  - 更新 `check-version` 脚本、`reference/README.md`、归档版本规范与 `development-history.md`；
  - 版本表新增 v2.0 行。
- **成功指标**：
  - `package.json` 为 `2.0.0`，`npm run verify` 全绿。
  - `check:version` 能正确比较 `v2.0` 与 `2.0.0`。
  - 文档中不再出现“major 恒为 1、不进位到 v2”的过时规则。
- **验收标准**：
  - `AC-015-1` 根 `package.json` 的 `version` 为 `2.0.0`；`npm run check:version` 退出 0。
  - `AC-015-2` `check-version.mjs` 允许 `major >= 1`、`patch === 0`，并按 `v<major>.<minor>` 解析“已完成”行；构造 `2.1.0` 与 `v2.1` 的临时用例能通过，`2.1.1` / `1.100.1` 被拒绝。
  - `AC-015-3` `reference/README.md`“已完成”行包含 v2.0 条目、当前版本为 `2.0.0`、“后续从 v2.1”；版本表新增 v2.0 行。
  - `AC-015-4` `development-history.md` 新增 v2.0 小节，概述本轮能力（知识库导入、大纲、所见即所得编辑、页面文案清理）。
  - `AC-015-5` 归档版本规范文档更新规则说明，标注 v2.0 起允许 major 递增。
  - `AC-015-6` `npm run verify` 全绿；不改变任何产品功能与数据。
- **范围**：`package.json`、`scripts/check-version.mjs`、`docs/reference/README.md`、`docs/reference/development-history.md`、`docs/archive/20261113/9-版本号同步与工程元数据规范-开发文档.md`、`docs/STATUS.md`。
- **不在范围内**：产品功能改动；数据迁移；rest 知识库内容导入（后续增量）。
- **风险**：版本脚本是 `verify` 的守卫，改错会阻断所有交付；需要正反用例验证。
