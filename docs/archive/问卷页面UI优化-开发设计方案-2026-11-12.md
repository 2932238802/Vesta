## 五、设计计划（frontend-design）

### 5.1 定位

- 用户：18–22 岁大学生，手机为主，耐心低；非技术。
- 场景：学姐发来链接，宿舍/通勤路上填；微信内置浏览器打开。
- 设计要传达：**这是一张认真但不吓人的答题纸**，不是营销页、不是心理测试。
- 设计不要：米黄滤镜的“AI 编辑风”、卡片瀑布、渐变、发光、emoji。

### 5.2 配色（4–6 个命名 hex）

| 令牌 | Hex | 角色 |
| --- | --- | --- |
| `--q-paper` | `#EFF1EC` | 页面底色：冷灰绿纸，去掉 `#f7f4ed` 的暖黄 |
| `--q-surface` | `#FBFCF9` | 选项/输入/浮层表面，比纸略亮 |
| `--q-ink` | `#1B231E` | 正文与题干：松墨黑，不是纯黑 |
| `--q-ink-2` | `#4D5951` | 辅助文字、分组名、说明 |
| `--q-accent` | `#2F5C48` | 主操作、选中、进度已完成段：沿用深绿 |
| `--q-danger` | `#9E3D2F` | 错误与缺失，砖红 |

派生色（单独列出，避免依赖 `color-mix`）：`--q-line: #DDE3DB`；`--q-line-strong: #CBD4CB`；`--q-accent-soft: #E6EDE7`；`--q-tint: #F4F7F2`。这 4 个是派生值，不占主色名额。

对比度目标：正文 ≥4.5:1，辅助 ≥4.5:1，选中白字对 `--q-accent` ≥4.5:1；实施后用 DevTools 复核并在交付里记数值。

### 5.3 字体角色与 type scale

| 角色 | 字体 | 字号 / 行高 | 字重 | 用在哪 |
| --- | --- | --- | --- | --- |
| Display | 无衬线 | 32 / 1.25（手机）· 40 / 1.2（桌面） | 600 | 邀请页主标题 |
| H1 分组 | 无衬线 | 24 / 1.3（手机）· 28 / 1.3（桌面） | 600 | 分组标题 |
| 题干 | 无衬线 | 18 / 1.5（手机）· 20 / 1.5（桌面） | 500 | 当前题 |
| 正文/选项 | 无衬线 | 16 / 1.55 | 400 | 选项、输入、说明 |
| 小字 | 无衬线 | 13 / 1.5 | 400 | 辅助、草稿提示 |
| 微字 | 无衬线 | 12 / 1.4 | 500 | 百分比、题内标签 |
| 报告正文 | 衬线（保留） | 现有 `ReportBlocks` | 400 | 只用于结果页正文，本轮不改 |

字体栈（系统字体，不新增 web font）：

```css
/* 沿用现有 --sans，不新增字体；--serif 也保持现状，只限制使用范围 */
--sans: "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Source Han Sans SC",
  "Microsoft YaHei", system-ui, -apple-system, "Segoe UI", sans-serif;
```

规则：**邀请页和问卷页不再使用 `--serif`**；`--serif` 只在结果页正文保留，本轮不改结果页。数字统一 `font-variant-numeric: tabular-nums`，不用等宽字体。

### 5.4 布局概念

对齐：邀请页文字居中、CTA 居中且宽度 340；问卷页整块左对齐，题干、选项、错误共用一条左基线；桌面只是加宽，不改成两栏。

```text
邀请页 375                          问卷页 375
┌────────────────────────┐          ┌────────────────────────┐
│ 大学四年规划自测         │          │ 学习情况          34%   │
│                        │          │ ──────────┈┈┈┈┈┈┈┈┈  │
│ XX，你好                │          │                        │
│ 你离想去的地方，         │          │ 学习情况                │
│ 还差哪几步              │          │ 你现在的状态更接近哪种？  │
│                        │          │                        │
│ ┌────────────────────┐ │          │ ○ 1 小时以内            │
│ │     开始填写        │ │          │ ● 1–2 小时          ✓  │
│ └────────────────────┘ │          │ ○ 2–4 小时             │
│ 上次填到第 3 组        │          │                        │
│ 答案用于生成这份报告      │          │ ⚠ 这道题还没完成        │
└────────────────────────┘          ├────────────────────────┤
                                    │ [上一题]      [下一题]  │
                                    └────────────────────────┘
```

说明：问卷页线框里的“学习情况”只是示意；实现直接用数据里的 `group.title`，**不在 UI 里拼“第三部分 ·”，也不加中点**。邀请页草稿行沿用现有数据，不新增题数。

### 5.5 原则

1. **一屏只回答一个问题**：当前题是唯一焦点，分组名和百分比只做定位，不抢视线。
2. **进度只说“到哪了”，不说“还剩多少题”**：百分比 + 分组名，避免学生盯剩余题量放弃（设计文档第 67 行的产品决定）。
3. **状态靠位置、边框、底色表达**：阴影只留给底栏和提交遮罩，选项卡不用阴影。
4. **纸感来自留白、字距、细线**，不来自米黄滤镜；页面最多一条 2px 进度线做记忆点。
5. **动效只回应用户动作**：120–250ms，不做逐题 fade-and-slide，尊重 `prefers-reduced-motion`。

### 5.6 对照 skill 的模板感自查

| skill 列出的类别 | 现状是否命中 | 判断 | 理由 |
| --- | --- | --- | --- |
| 1. 暖米底 + 高对比衬线 + 陶土/暖色 accent | **命中前半**：`#f7f4ed` + Songti 标题；accent 是深绿不是陶土 | **替换**：纸色换 `#EFF1EC`，邀请/问卷标题改无衬线；深绿 accent 保留 | 暖米 + 衬线是 AI 设计最常见的组合；深绿是品牌色、不是陶土，且与“冷静诊断”一致 |
| 2. 近黑底 + 单一荧光绿/朱红 | 否 | 保留浅色 | 学生白天填写，浅色更稳 |
| 3. 报纸式细线、零圆角、密集分栏 | 否 | 保留 12–16px 圆角 | 触控需要圆角，但不做“SaaS 卡” |
| 4. SaaS 卡片套件：所有卡同一圆角、同一软阴影、渐变装饰 | **部分命中**：选项卡同圆角；邀请 CTA 有 `0 10px 24px` 阴影 | **部分替换**：选项卡保留（它是选项容器，不是装饰）；CTA 阴影删除；只保留底栏/遮罩一层阴影 | 选项卡承担“可点区域”语义，去掉反而难用；装饰性阴影没有信息 |
| 5. 模板 chrome：全大写加字距 eyebrow、`·` 拼接、等宽小数字、按钮箭头、`#0B0B0B` 假黑 | **命中三项**：`.eyebrow` uppercase + 0.16em、题号 `.q-index` 用 mono、返回按钮 `←` | **全部替换**：取消 uppercase 与大字距；新增的百分比用 tabular sans 而非 mono；删除题号；去掉箭头 | 这三项与问卷主题无关，是“生成页”的通用装饰 |
| 补充：逐题 fade-and-slide 入场 | 命中：`.fade-in` 每题 translateY(6px) | 替换为 120ms 透明度，位移删除 | 非用户触发的重复入场是模板感来源 |

#### 结构

```text
┌──────────────────────────────────────┐
│ 学习情况                        34%   │  sticky，q-paper 94% + blur
│ ─────────────────────────┈┈┈┈┈┈┈┈  │  已完成 2px 实线，剩余 1px 点线
├──────────────────────────────────────┤
│ 学习情况（数据 title）                 │  13px，q-ink-2
│ 你现在的状态更接近哪一种？              │  H1 24/28，无衬线

└──────────────────────────────────────┘
```

#### 进度区（按设计文档第 67 行）

- 只显示三项：**分组名**（`groups.title`）、**百分比**、**细条**。不显示题数或完成数量。
- 百分比 = `Math.round((step + 1) / visible.length * 100)`；跳题导致 `visible.length` 变化时允许百分比跳变，这是真实剩余量，不额外平滑。
- 结构：左侧分组名 13px `--q-ink-2`，右侧百分比 12px tabular-nums `--q-ink-2`；下方 2px 轨道：已完成段 `--q-accent` 实线，剩余段 1px 点线（`repeating-linear-gradient`），不抢题干。
- `role="progressbar"`、`aria-valuemin="0"`、`aria-valuemax="100"`、`aria-valuenow`、`aria-valuetext="<分组名>，完成 <pct>%"`；分组为空时 `aria-valuetext="完成 <pct>%"`。
- sticky 顶部，`background: rgba(239, 241, 236, 0.94)`；手机端不使用 blur，直接不透明 `--q-paper`；桌面才用 blur（见 7.4）。
- 分组名只在分组变化时更新，避免每题重复。

#### 题目与焦点

- 删除题干前的等宽题号 `07`；`.q-head` 不再需要 `min-width` 保留位。
- 一屏只保留当前题；切题后 `scrollTo({ top: 0 })`。
- **切题聚焦题干只对键盘用户生效**：用 `keydown`（Tab/Arrow/Enter/Space）置 `keyboardMode = true`，切题后 `h1[tabindex="-1"].focus({ preventScroll: true })`；触摸/鼠标用户不抢焦点，只滚动到顶。
- 触摸/读屏：`#quiz-status` 是唯一的 `aria-live="polite"` 区域；切题后写入“下一题：<分组名>”，写完清空再写，避免不播报。
- 不重复播报：键盘用户靠标题焦点播报，**不再写 live region**；触摸用户靠 live region，**不聚焦标题**。两者互斥。

#### 选项卡片（单选：radiogroup + roving tabindex）

- 结构：`.options` 设 `role="radiogroup"` + `aria-labelledby` 指向题干；每个选项 `role="radio"`、`aria-checked`，保留 `button` 元素以复用现有样式与点击。
- roving tabindex：无选中时第一个 `tabindex="0"`，其余 `-1`；有选中时选中项 `0`，其余 `-1`。
- 方向键：`ArrowUp/ArrowLeft` 上一项，`ArrowDown/ArrowRight` 下一项，循环；`Home/End` 首尾。**方向键只移动焦点，不选中、不触发 `update`、不启动自动前进**，否则键盘用户无法比较选项。
- `Space`/`Enter` 选中当前项并触发 `update`；键盘模式**不自动跳题**，选中后停留，由用户按「下一题」或末题「提交」；`Tab` 离开选项组，进入底栏。
- 选中态：1px 边框 + `inset 0 0 0 1px var(--q-accent)`（不改变布局）+ `--q-accent-soft` 底 + 20px 指示器内白色勾（内联 SVG，`aria-hidden`）。
- 悬停：`--q-tint` 底 + `--q-line-strong` 边框；选中项悬停保持选中态。
- 焦点：`:focus-visible` 2px `--q-accent` 环 + `outline-offset: 2px`；焦点环不能只在 `:focus`（触屏点击不出环）。
- 长选项：`overflow-wrap: anywhere; word-break: break-word;` 不设固定高度。
- 多选：保留 `button` + `aria-pressed`（不做 roving tabindex）；`Space` 切换；达到上限时 `limit-hint` 就地显示、`aria-live="polite"`，不弹窗。

## 七、微信内置浏览器专节

微信内打开是本问卷的主要入口，iOS 是 WKWebView，安卓是 X5（部分版本已切 XWeb）。以下按“必须处理 / 验收方式 / 已知限制”写。

### 7.1 视口单位：100vh / svh / dvh

- 页面容器写 `min-height: 100vh;`，下一行覆盖 `min-height: 100svh;`；不要用 `100vh` 作为唯一值（iOS 工具栏收放会跳）。
- 提交遮罩用 `height: 100vh; height: 100dvh;`；`dvh` 随键盘变化，遮罩不露底。
- X5 老版本不支持 `svh/dvh` 时回退 `vh`；不写 JS 补丁。具体内核版本待核。

### 7.2 position: fixed

- 底栏 `fixed` 在 iOS 上相对布局视口，键盘弹出后仍在屏幕底部、被键盘盖住；安卓 X5 多数 `adjustResize`，布局视口缩小，底栏会自然上移。
- 因此不能只靠 CSS：必须配合 7.3 的 `visualViewport`。
- 进度头也 `sticky`，但 `top: 0` 在 iOS 键盘弹起时可能被顶出；输入聚焦时允许它随页面滚走，不强制吸顶。

### 7.3 visualViewport：先让位，再抬升

判定条件：

- 仅当 `matchMedia('(pointer: coarse)')` 匹配，且 `document.activeElement` 是 `input` / `textarea`。
- `focusin` 进入、`focusout` 延迟 150ms 退出；避免在输入框之间切换时闪烁。

第一段「让位」（所有手机默认执行）：

1. `focusin` 给 `.quiz` 加 `.kb-focus`。
2. `.kb-focus .foot { position: static; margin-top: 16px; }`，内容底部 padding 降到 24px；底栏不再压住输入框。
3. 输入框 `scroll-margin-bottom: 24px`；`nextTick` + 120ms 后 `scrollIntoView({ block: 'center' })`。

第二段「抬升」（仅当键盘真的占屏）：

1. 监听 `visualViewport` 的 `resize` + `scroll`，防抖 100ms；只处理 `resize` 后高度变化 > 8px 的情况。
2. `kb = Math.max(0, window.innerHeight - visualViewport.height - (visualViewport.offsetTop || 0))`。
3. 若 `kb > 120`：设置 `--kb-offset: ${kb}px`；底栏从 static 切回 `position: fixed`、`bottom: var(--kb-offset)`，去掉 `margin-top`；内容 padding-bottom 同步加 `kb`，并在 `requestAnimationFrame` 后再次 `scrollIntoView({ block: 'center' })`，把输入框放到键盘与底栏之间。
4. 若 `kb > 0.45 * window.innerHeight`：底栏 `visibility: hidden`（键盘占大半屏时按钮没有意义），失焦恢复；不改变 DOM。
5. 若 `kb <= 120` 或 `visualViewport` 不存在：只保留第一段让位，底栏不抬升。

失败表现：没有 `visualViewport` 的老 X5 上，底栏在聚焦时保持“文档流让位”，输入框始终可见；用户需收起键盘才能点下一题。这是可接受降级，不额外写轮询。

### 7.4 backdrop-filter 性能

- 手机（`pointer: coarse`）**一律不用 blur**：底栏/进度头用 96% 不透明 `--q-paper`；桌面才用 `backdrop-filter: blur(10px)`。
- `@supports not (backdrop-filter: blur(1px))` 时同样回退为不透明；不存在“按主观卡顿再决定”的切换。
- 不用 blur 做卡片装饰，只用于两条固定栏。

### 7.5 输入聚焦滚动

- iOS 已用 16px 字号避免自动放大；仍会在聚焦时滚动页面。
- `focusin` 后 120ms 再滚动，避开键盘动画；`block: 'center'`，不用 `nearest`（会被底栏挡）。
- 微信键盘右上角“完成”收起后触发 `focusout`，执行 7.3 的恢复。

### 7.6 微信返回手势与草稿保存

- iOS 边缘右滑返回、安卓返回键，`beforeunload` 都不可靠；草稿不能只依赖它。
- 现有 `watch([answers, step, timing], scheduleSave)` 每 400ms 保存，保留。
- 新增：`pagehide` 与 `visibilitychange`（`hidden`）时 `flushTiming()` + `saveDraft()`；与现有 `beforeunload` 并存，不删除。
