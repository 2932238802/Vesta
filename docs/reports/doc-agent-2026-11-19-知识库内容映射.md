## 3. 建议的导入范围（本期）

- **大学常识（约 9–10 篇）**：01 的 4 个主题、02、03 升学路径、04 的 2 个主题。
- **专业知识汇总（7 个专业，约 12–15 篇）**：护理、法学、会计、汉语言、临床医学、英语、教师岗。
- **金句栏（1 个分类，约 150+ 条）**：从 06 抽取；05 的短句仅人工挑选少量。
- **故事集（1 个分类，2–4 篇）**：06 的学员案例 + 03 的护理案例。
- **有效的提问（1 个分类，约 10–20 条）**：01/05 的问句，人工改写。
- **图片**：14 张复制到 `web/public/knowledge/`，改写 01/03 中的图片路径。

**暂不导入**：05 的流程与话术原文（口语转写、噪音大）、06 的训练方法（无对应模块）。

## 4. 导入方式建议

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A（推荐）一次性导入脚本 | `scripts/import-knowledge-pack.ts`，默认 `--dry-run`，`--write` 才落库；读取一个内容包 JSON（含 5 类数据） | 可控、可预览、可重跑；适合内容迁移 | 需在服务器手动执行一次 |
| B 启动迁移 | 像金句种子一样在 `runMigrations()` 写标记位导入 | `update.sh` 自动完成 | 内容体量大、难以 dry-run；改内容需再写迁移 |
| C 后台手工导入 | 做一个导入入口 | 可视化 | 开发量最大，本期不划算 |

- 建议内容包放在 `server/src/data/consult-knowledge-pack.json`，导入脚本按现有表结构写入：
  `consult_topics`、`knowledge_majors/articles`、`consult_quote_categories/quotes`、`consult_story_categories/stories`、`consult_question_categories/questions`。
- 每条记录使用稳定 ID（`kb_...`），脚本幂等：已存在则跳过，不覆盖人工修改。

## 5. 风险与待确认

- **隐私**：原文含学员案例与真实细节，入库前需脱敏；故事集与金句要逐条检查。
- **质量**：05 是口语转写，直接入库会显著拉低可读性；本期建议只挑短句。
- **图片**：需复制到 `web/public/` 并改路径；否则 Markdown 图片会被 CSP 拦截。
- **版权**：内容来自岑啟艳的沉淀文档，仅内部系统使用；是否入库需用户确认。
- **压缩包**：导入完成并核对后删除 `在野咨询知识库.zip` 与 `:Zone.Identifier`。
