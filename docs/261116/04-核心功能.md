## 1. 邀请链接

**目的**：给每个学员一条一次性、可过期、可追踪的答题入口。

**规则**（`server/src/routes/admin/invites.ts`）：

- 单次请求最多创建 **100** 条；`names` 数组或单个 `name` 都接受。
- 姓名 `trim` 后截断到 40 字；空名与重名会被跳过；全部为空返回 `400 至少填一个姓名`。
- `note` 最多 200 字，`channel` 最多 40 字。
- `expiresAt` 必须是可解析且晚于当前时间的日期，否则 `400 过期时间需要晚于现在`；不传则永不过期。
- 创建时绑定**当前激活问卷** `getActiveSurvey()`，之后问卷升级不影响已发链接。
- 返回 `{ id, name, token, path }`，`path` 形如 `/i/<TOKEN>`。

**边界与失败**：

| 场景 | 行为 |
| --- | --- |
| 删除已提交的邀请 | `409 这个链接已经提交过，不能删除` |
| 轮换已提交的邀请 | `409 已经提交过，不需要换链接` |
| 轮换未提交的邀请 | 生成新 token，状态重置为 `pending`，清空 `opened_at` |
| 打开不存在 token | `404 链接无效，请向发链接的人确认` |
| 打开过期 token | `410 链接已过期，请向发链接的人要一条新的` |
| 首次打开 | 状态 `pending → opened`，写 `opened_at`，记 `invite_open` 事件 |

## 2. 公开问卷

**目的**：让学员在手机上完成 28 题现状自评，并保留中途草稿。

**结构**：`shared/src/survey.ts#defaultSurvey` 定义题库、分组、分支与评分。默认 `reportMode: 'doc'`，即报告为全文 AI 文档，不展示数字总分。

**分支规则**（以 `docs/规划自测问卷-设计文档.md` 为准）：

| 触发 | 效果 |
| --- | --- |
| Q7 的选择 | 决定是否进入 Q19 分支 |
| Q20 的值 < 6 | 触发门槛分支 |
| Q21 的选择 | 决定是否进入 Q23 |
| Q22 的选择 | 决定是否进入 Q24 |

实现上由 `shared/src/doc.ts#visibleQuestions` 与 `resolveQuestion` 计算可见题；前端只渲染可见题，不自行推断规则。

**交互**（`web/src/views/Quiz.vue`）：

- 草稿写 `localStorage`，刷新不丢；提交成功后清除。
- 记录每题停留时长 `timing`，用于后台“平均耗时”和流失分析。
- 单选后自动前进；多选、矩阵、文本需要显式继续。
- 每完成一组上报 `group_complete` 事件，用于漏斗。
- 提交前做前端必填校验，服务端会再次校验。

**字段兼容**：历史答卷的 key 与题号解耦（例如 `q17_cet4_times`）。`server/src/db/migrations.ts` 对 Q18 / Q21 / Q25 多选、Q17 阶段、Q22 顺序、Q25 跳过、Q5a、Q27 薪资、Q28 自评等做过回填。改题时先读迁移，不要假设 key 等于题号。

## 3. 提交与报告

### 3.1 提交

`POST /api/invite/:token/submit`（限流 8 次/分钟）：

1. token 不存在 → `404`；过期 → `410`；已提交 → `409`，并带 `reportSlug` 让前端跳转。
2. `validateAnswers` 校验必填、类型、选项合法性；失败返回 `400`，带 `errors` 与 `missing`。
3. `score` 模式走 `computeScores`；`doc` 模式 `total=0`，`tier` 取 `docPriority` 的 A/B/C，**不把 A/B/C 映射成假分数**。
4. `timing` 按题过滤：只接受有限非负数，单题上限 15 分钟。
5. 事务写 `submissions` 并把邀请置 `submitted`；提交后 `enqueueReport(id)`。
6. 返回 `{ slug }`。

### 3.2 报告轮询

`GET /api/report/:slug`（120 次/分钟）：

| 报告模式 | 未完成时 | 完成时 | 失败时 |
| --- | --- | --- | --- |
| `doc` | `report: null`，`status: pending/running`，前端显示加载 | 结构化 AI 报告 | 可重试失败给“可以点重新生成”；配置/规则失败给“把提示发给发链接的人” |
| `score`（旧） | 可先展示基础版（`preview=1` 或已有上一版） | AI 深度版或基础版 | 展示基础版并提示截图联系 |

前端每 3 秒轮询（`poll=1`），轮询不重复记 `report_view`。

### 3.3 重试与领取

- `POST /api/report/:slug/retry`：仅 `doc` 模式、未 `ready`、AI 已配置；成功返回 `{ ok, status: 'pending' }`，限流 5 次/分钟。
- `POST /api/report/:slug/claim`：微信号 2–80 字；时间段 1–3 个，每个 ≤80 字；`agree` 必须为 `true`；已领取返回 `409`。联系方式用 `CONTACT_KEY` 加密后写 `wechat_enc`。
- 报告页支持保存图片、导出 PDF、复制链接（`web/src/views/ReportView.vue`）。设计文档里的“复制完整结果”按钮并未实现，见 §6 的差异说明。

## 4. 运营概览

`GET /api/admin/overview` 一次返回：

| 区块 | 内容 | 口径 |
| --- | --- | --- |
| `stats` | `invites/opened/submitted/claimed/pending/completion` | 两次聚合查询 |
| `funnel` | 已开始人数 + 每组完成人数 | 读 `event_facts`，不扫原始事件 |
| `daily` | 近 14 天提交数 | 按 `created_at` 日期聚合 |
| `questions` | 每题平均秒数、作答率、流失数、流失率 | 答卷只读一次，内存聚合 |
| `recent` | 最近 8 条提交 | 关联邀请姓名、备注、渠道 |

**边界**：分母为 0 时用 1 兜底，避免除零；`questions` 只统计当前问卷存在的题，历史题不会污染。

## 5. 名单与答卷

- `GET /api/admin/roster`：支持 `q`（姓名/备注搜索）、`category`、`week`；返回 `roster`、`counts`、`weeks`、`currentWeek`。期次由日期推导（`shared/src/cycle.ts`），不是手填字段。
- `POST /api/admin/roster/batch-delete`：按 `inviteIds` 批量删除，单次最多 200 个；**会先删关联答卷再删邀请**，不可撤销。与单个删除邀请（已提交时 409）不同，这里没有“已提交保护”。
- `GET /api/admin/submissions`：支持 `q`、`contactStatus`；返回摘要列表。
- `GET /api/admin/submissions/:id`：返回答卷、分数、报告状态、联系方式（解密后）、后台备注、覆盖项。
- `PATCH /api/admin/submissions/:id`：可改 `contactStatus`、`adminNotes`、`overrides.diagnosis/closing`。
- `POST /api/admin/submissions/:id/report`：重新生成报告；只要答卷存在就重置为 `pending` 并清零尝试次数，AI 未配置时会在生成阶段失败。
- `DELETE /api/admin/submissions/:id`：删除答卷并释放邀请（具体以路由实现为准）。
- `GET /api/admin/submissions/export.csv`：按 `q/week/category` 导出 CSV；前端用 `fetch` 带 Bearer Token 取 blob。

**联系方式**：列表默认不返回明文；详情页解密依赖 `CONTACT_KEY` 未变更。换 key 后旧数据无法解密，这是设计代价。

## 6. 问卷、模板与 AI 规则

| 功能 | 规则 | 失败 |
| --- | --- | --- |
| 保存问卷 `PUT /survey` | `validateSurvey` 全量校验；通过后 `publishSurvey` 生成新版本 | 返回 `400` + 第一条错误 + `errors` 数组 |
| 保存报告模板 `PUT /template` | `validateTemplate`；版本号自动 `+1` | 同上 |
| 新建 Skill 模板 | 名称 ≤40 字；规则 100–60,000 字 | `400` 具体文案 |
| 修改 / 删除 Skill | 默认模板不可改、不可删 | `403 默认设置不能修改/删除` |
| 激活 Skill | id 必须存在 | `404 没有找到这个模板` |
| 预览报告 `POST /report/preview` | 可传 `survey/template/answers/overrides`；不传答案时用 `sampleAnswers` 生成示例 | 模板非法 `400` |

`GET /skill` 同时返回 `reportMode`、当前激活 id、`ai.configured`、`ai.searchConfigured`、`ai.model`，后台据此显示“AI 是否可用”。

**差异登记**：设计文档提到报告页有“复制完整结果”按钮；当前 `ReportView.vue` 提供的是保存图片、导出 PDF、复制链接。验收时以页面为准，是否需要补按钮需产品确认。

## 7. 咨询稿工作台

**目的**：把“和学生打电话时说什么”结构化为可编辑、可复用的咨询稿。

**创建** `POST /api/admin/consult/runs`：

- AI 未配置 → `503 未配置 DEEPSEEK_API_KEY，暂时无法生成咨询稿`。
- `mode: 'purpose'`：必须能从 `consult-purpose-data.json` 找到 `purposeTemplateId`；找不到 → `400`。
- `mode: 'sentence'`（默认）：`chooseConsultForestPath` 选路径；没有可用路径 → `400`；模板不存在 → `404`。
- 成功返回 `202` 与 `run`；生成在后台执行。

**运行状态**：`queued | running | ready | failed`（`shared/src/consult.ts#ConsultRunStatus`）。章节状态同构。

**编辑能力**：

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 读运行 | `GET /runs/:id` | 含章节、节拍、路径、上下文 |
| 改章节 | `PATCH /runs/:id/sections/:seq` | 改标题/目标/正文 |
| 生成节拍 | `POST /runs/:id/sections/:seq/beats` | 按模块补节拍 |
| 重写章节 | `POST /runs/:id/sections/:seq/regenerate` | 单节重生成 |
| 加章节 | `POST /runs/:id/sections` | 手动插入模块 |
| 删章节 | `DELETE /runs/:id/sections/:seq` | 删除并重排 |
| 重试 | `POST /runs/:id/retry` | 失败/中断后重跑 |
| 记结果 | `PATCH /runs/:id/outcome` | `won/lost/liked/abandoned` |
| 导出 | `GET /runs/:id/export/:format` | `docx/html/txt`；未完成返回 `400` |

**边界**：生成任务在内存集合 `activeConsultJobs` 中；进程重启后 `queued/running` 的 run 不会自动恢复，需要手动 `retry`。导出文件名做了 RFC 5987 编码，中文文件名不会乱码。

## 8. 收藏栏

- 列表 `GET /collections`、详情 `GET /collections/:id`、新建 `POST /collections`、修改 `PUT /collections/:id`、删除 `DELETE /collections/:id`。
- 聚合 `GET /collections/bundle` 返回前端一次加载所需的全部条目。
- DOCX 导入 `POST /collections/import-docx`：
  - 请求体是**原始字节**，不是 multipart；上限 20MB；文件名放 `X-File-Name`（可 URL 编码）。
  - `parseDocx` 抽正文；空正文 → `400 这个 Word 文件没有可读取的正文`。
  - 标题优先取文件名，去掉 `.docx`、把 `+_` 变空格、去掉“原文”后缀；为空则取正文前 48 字。
  - 若标题或正文前 2000 字命中“咨询稿/咨询师/来访者/学生/发言人/老师：”等模式，归为 `script`，否则 `other`。
  - 自动打标签与摘要（段数、字数）。

## 9. 分数线

### 9.1 数据口径

四层：主线（国家线/省控线）→ 院校线 → 专业线 → 招生计划。所有数字必须带来源；**抓取默认待复核，复核通过才可被查询**。历史保留 10 年（`SCORELINE_HISTORY_YEARS`）。

### 9.2 抓取

- 来源：31 省专升本 + 研招网国家线/复试线汇总，`seedScorelineSources` 幂等写入。
- 手动触发 `POST /score-lines/crawl`：省份必填；`years` 最多 10 个，范围 2000–2100；限流 5 次/分钟。
- 无来源 → `409` + `code: NO_SOURCE`；新任务 `202`，已有同省任务 `200`。
- 队列 `GET /crawl/queue`；取消排队 `DELETE /crawl/queue/:id`（只能取消未开始的）。
- 运行详情 `GET /crawl/runs/:id`。
- 调度器默认开启；一次只跑一个省；启动 60 秒后首次检查。

### 9.3 导入

`POST /score-lines/import`：

- 接受 `batches`（分数线批次）与 `programs`（招生计划），至少一项。
- 单次最多 200 个批次、每批次最多 100 个指标（共享常量）。
- `dryRun: true` 只校验并返回计数，不落库。
- 归一化后若两条批次维度完全相同（范围/年份/省份/院校/专业/批次/科类），报错并指出第几条与第几条冲突，避免互相覆盖。
- 导入的数据默认 `approved`；抓取的数据默认 `pending`。
- 来源链接必须以 `http://` 或 `https://` 开头。

### 9.4 复核与查询

- 待复核列表 `GET /review`、计数 `GET /review/count`、动作 `POST /review`：`kind: batch|program`，`action: approve|reject`，单次最多 100 个 id，只处理 `pending`。
- 查询 `GET /score-lines/query` 只返回 `approved` 数据；必须给 `exam` + `year`；`programId` 会反推 `schoolId` 并校验归属。
- 院校 `GET /schools`、专业 `GET /programs` 支持关键词与分页。
- 覆盖 `GET /coverage`：状态 `covered/partial/pending/no_data/not_offered/failed`，分页返回并带 `summary`。

### 9.5 覆盖状态如何产生

`refreshCoverage` 的判定（`server/src/score-lines/coverage.ts`）：

| 条件 | 状态 |
| --- | --- |
| 主线 > 0 且（校线或专业线 > 0）且计划数 > 0 | `covered` |
| 有部分数据但未齐 | `partial` |
| 有 `pending` 复核数据 | `pending` |
| 最近一次抓取失败 | `failed` |
| 明确不招生 | `not_offered` |
| 其余 | `no_data` |

## 10. 事件与保留

- 公开页通过 `POST /api/events` 上报白名单事件；`track` 使用 `keepalive`，页面关闭也能发出。
- 原始 `events` 默认保留 180 天；`event_facts` 保存漏斗事实，永久保留。
- 抓取原始文档默认保留 90 天，只删快照与 `crawl_documents` 行，不删结构化分数线。
- 清理时机不同：事件清理在启动时执行，并每 24 小时再跑一次（`server/src/index.ts` 的 `setInterval(pruneEventLogs, ...)`）；抓取快照只在启动时清一次（`pruneCrawlSnapshot`）。

## 11. 功能级验收清单

| 功能 | 最小验收动作 | 通过标准 |
| --- | --- | --- |
| 邀请 | 创建 1 条邀请并打开 | 返回 `path`；打开后状态变 `opened` |
| 问卷 | 完成一份答卷 | 必填拦截生效；刷新不丢草稿 |
| 提交 | 提交后再次提交 | 首次得 `slug`；再次得 `409` 且带 `reportSlug` |
| 报告 | 轮询到终态 | `ready` 有内容；`failed` 有可执行提示 |
| 领取 | 填微信号与时间 | `200`；重复领取 `409` |
| 名单 | 搜索与导出 | 搜索结果与 CSV 行数一致 |
| 设置 | 保存问卷/模板 | 版本号递增；非法输入 `400` |
| 咨询 | 生成一份 `purpose` 稿 | `202` → `ready`；可导出 `docx` |
| 收藏 | 导入一个 DOCX | `201`；正文非空；标签合理 |
| 分数线 | 导入 + 复核 + 查询 | 未复核查不到；复核后可查 |
