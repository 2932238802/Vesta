# 开发环境搭建

## 1. 前置条件

| 依赖 | 要求 | 检查命令（cwd = 仓库根） | 预期 |
| --- | --- | --- | --- |
| Node.js | `>=24.0.0` | `node -v` | 输出 `v24.` 开头；退出码 `0` |
| npm | 随 Node 提供，支持 workspaces | `npm -v` | 输出 `10.` 或更高；退出码 `0` |
| Git | 任意近期版本 | `git rev-parse --short HEAD` | 输出 7 位短哈希；退出码 `0` |
| SQLite | **不需要单独安装** | — | 使用 Node 内置 `node:sqlite` |
| AI / 搜索 | 可选 | — | 不配置也能启动与答题，报告会走失败提示而非伪造内容 |

`node -v` 低于 24 时，`node:sqlite` 不存在，启动会在 `server/src/db/connection.ts` 导入阶段失败。

## 2. 安装

cwd = 仓库根：

```bash
npm install
```

- 预期可 grep 的输出：`added` 或 `up to date`。
- 退出码：`0`。
- 失败指向：先看 npm registry 连通性；若是 `EBADENGINE`，升级 Node 到 24；若是某个 workspace 的 peer 冲突，查看 `server/package.json` / `web/package.json` 的版本约束。

> 本仓库是 npm workspaces：根 `package.json` 只放 `concurrently` 与 `tsx`，真实依赖在 `server/` 与 `web/`。不要在子目录单独 `npm install` 后混用锁文件。

## 3. 环境变量

配置从两个位置加载，后者覆盖前者：`<ROOT>/.env`、`<ROOT>/server/.env`（`server/src/env.ts` 顶部的 `process.loadEnvFile`）。也可以直接用进程环境变量注入。

### 3.1 必填与安全相关

| 变量 | 默认 | 生产要求 | 说明 |
| --- | --- | --- | --- |
| `ADMIN_USER` | 空 | **必填**，否则启动抛错 | 管理员账号 |
| `ADMIN_PASSWORD` | 空 | **必填**，否则启动抛错 | 管理员密码；比较使用定时安全摘要 |
| `AUTH_SECRET` | 开发随机临时值 | **必填**，否则启动抛错 | HMAC Token 与默认联系方式加密密钥；建议 ≥32 位 |
| `CONTACT_KEY` | 回退到 `AUTH_SECRET` | 建议单独设置 | 联系方式加密密钥；更换后旧密文不可解 |
| `DEV_GUEST_LOGIN` | 开发环境开启 | 生产无效 | 仅 `NODE_ENV=development` 且未设为 `false` 时开放 `/api/admin/dev-login` |

### 3.2 服务与数据

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 后端监听端口；`npm run dev` 会额外注入 `8788` |
| `DATA_DIR` | `./data` | SQLite、抓取快照、`deploy-info.json` 的根目录；相对路径基于仓库根 |
| `PUBLIC_BASE_URL` | 空 | 当前代码只读取、未消费；邀请接口返回相对路径 `/i/<token>`，由前端按当前域名拼完整链接 |
| `COMPRESS` | 开启 | 设为 `off` 关闭 gzip，仅在前面已有 Nginx 压缩时使用 |
| `TRUST_PROXY` | `false` | 仅在反向代理后设为 `true`；直接对公网监听时必须关闭，否则限流可被伪造头绕过 |
| `SESSION_TTL` | `2592000`（30 天） | 登录会话有效期，单位秒 |
| `LOG_LEVEL` | 生产 `info` / 开发 `debug` | `debug|info|warn|error` |

### 3.3 保留期

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `EVENT_RETENTION_DAYS` | `180` | 原始 `events` 明细保留天数 |
| `EVENT_OPERATIONAL_RETENTION_DAYS` | `365` | 运营事件保留天数 |

`event_facts` 是漏斗事实表，不受这两个保留期影响。

### 3.4 AI 与搜索

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `AI_API_KEY` | 空 | OpenAI 兼容接口密钥；也接受旧名 `DEEPSEEK_API_KEY` |
| `AI_BASE_URL` | 空 | 接口基地址；代码不写死服务商地址，必须注入 |
| `AI_MODEL` | `deepseek-chat` | 模型名；也接受旧名 `DEEPSEEK_MODEL` |
| `AI_TIMEOUT_MS` | `240000` | 单次请求超时；`.env.example` 示例为 `120000`，以代码默认值为准 |
| `BOCHA_API_KEY` | 空 | 博查搜索密钥；为空时报告不联网 |
| `BOCHA_BASE_URL` | 空 | 博查接口基地址 |

### 3.5 分数线抓取

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SCORELINE_CRAWL` | 开启 | 设为 `off` 关闭定时抓取 |
| `SCORELINE_CRAWL_PROVINCE_MINUTES` | `30` | 单省抓取时间预算（分钟） |
| `SCORELINE_CRAWL_INTERVAL_MINUTES` | `10` | 调度器检查间隔（分钟） |
| `SCORELINE_CRAWL_ALLOW_PRIVATE` | 关闭 | 设为 `1` 允许抓取私网地址；**仅本地 fixture 测试**，生产开启会造成 SSRF |

### 3.6 最小本地 `.env`

以下值全部是占位符，真实值由使用者填写，不要提交：

```dotenv
PORT=8787
DATA_DIR=./data
ADMIN_USER=<USER>
ADMIN_PASSWORD=<已脱敏>
AUTH_SECRET=<已脱敏>
DEV_GUEST_LOGIN=true
```

不配 `AI_API_KEY` 时，答卷仍可提交，报告页会显示“AI 分析还没有配置”的失败提示；这是设计行为，不是故障。

## 4. 启动

### 4.1 开发模式（前后端分离）

cwd = 仓库根：

```bash
npm run dev
```

- 行为：`concurrently` 同时启动 `server` 与 `web`。后端由 `server/dev.mjs` 注入 `NODE_ENV=development`、`PORT=8788`，并以 `tsx watch src/index.ts` 运行；前端 Vite 监听 `5173`，把 `/api` 代理到 `127.0.0.1:8788`（`web/vite.config.ts`）。
- 预期可 grep 的输出：Vite 的 `Local:` 行含 `5173`；后端日志出现监听端口 `8788`。
- 退出码：长驻进程，`Ctrl-C` 后为 `130` 属正常。
- 失败指向：`EADDRINUSE` 表示端口被占；Vite 代理 502 表示后端没起来，先看后端终端。

打开 `http://127.0.0.1:5173/admin`。开发环境未配置管理员账号时，路由守卫会先尝试 `/api/admin/dev-login` 免密登录（`web/src/router.ts` 的 `beforeEach`）。

### 4.2 生产同构本地运行

cwd = 仓库根：

```bash
npm run build
NODE_ENV=production PORT=8082 npm start
```

- 预期：`web/dist` 生成；进程监听 `8082`，访问 `/api/health` 返回 `{"ok":true,...}`。
- 退出码：长驻进程。
- 失败指向：`NODE_ENV=production` 下缺 `ADMIN_USER` / `ADMIN_PASSWORD` / `AUTH_SECRET` 会**启动即抛错**，这是有意的。

`docs/README.md` 记载本机线上实例使用 `8082`（由 systemd drop-in 覆盖端口），这是部署事实，不是代码默认值。

## 5. 首次运行会创建什么

| 路径 | 创建者 | 说明 |
| --- | --- | --- |
| `DATA_DIR/vesta.db` | `server/src/db/connection.ts` | 首次导入即建库，随后 `runMigrations()` 建表/补列 |
| `DATA_DIR/vesta.db-wal`、`-shm` | SQLite WAL | 正常运行时存在 |
| `DATA_DIR/crawl/*` | 抓取器 | 原始 PDF/Excel/HTML 快照，90 天后清理 |
| `DATA_DIR/deploy-info.json` | `update.sh` | 本地开发通常不存在；缺失时 `/api/health` 的 `commit` 为空 |

数据库结构以 `server/src/db/schema.ts` 为准；升级靠 `server/src/db/migrations.ts#runMigrations` 的幂等 `ALTER` / 回填，不靠删库。

## 6. 工程约束（STD 合并）

这些约束来自 `AGENTS.md` 与 `docs/agent-rules.md`，违反会让 `npm run verify` 失败或让后续维护成本陡增。

| 约束 | 具体要求 | 守卫 |
| --- | --- | --- |
| 文档优先 | 先改 `docs/`，再改代码；产品规则变化要更新 `docs/development-history.md` | 人工 + `check:docs` |
| 类型 | 不使用 `any` 逃逸；共享类型放 `shared/src/types.ts` | `typecheck` |
| 文件大小 | 软限 600 行、硬限 800 行；新文件 ≤400 行；Vue 块 400/600 | `check:size` |
| 版本 | 根 `package.json` 版本、README 版本表、开发历史必须同步 | `check:version` |
| 依赖 | 不引入与现有运行时冲突的依赖；Express 保持 4.x | `check:deps` |
| 文案 | 面向学员的错误提示必须可执行，不暴露内部 key / 分数口径 | 人工 + AI 审计 |
| 安全 | 不提交 `.env`、密钥、真实学员资料；日志中对 token / slug 脱敏 | 人工 |
| 数据操作 | 不执行破坏性 SQL、不删 `DATA_DIR`、不跑迁移脚本做“试试看” | 人工 |
| 文档查找 | 不熟的 API 先用 context7 查官方文档；页面走查用 playwright | 人工 |

## 7. 常见问题

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `node:sqlite` 找不到 | Node < 24 | 升级 Node；确认 `node -v` |
| 启动即报“缺少管理员账号” | `NODE_ENV=production` 且未配 `ADMIN_USER` / `ADMIN_PASSWORD` | 在根 `.env` 补齐 |
| 启动即报“必须配置 AUTH_SECRET” | 生产环境未配 | 生成 ≥32 位随机串写入 `.env` |
| 登录后重启又掉线 | 开发环境未配 `AUTH_SECRET`，使用临时密钥 | 配置固定 `AUTH_SECRET` |
| 后台一直跳登录页 | 生产环境不提供免密登录，且未登录 | 用 `ADMIN_USER` / `ADMIN_PASSWORD` 登录 |
| 限流把所有人算成一个 IP | 在反向代理后但 `TRUST_PROXY` 未开 | 代理后设 `true`；直连公网保持 `false` |
| 报告一直 `pending` | 未配置 AI，或队列被前序任务占满 | 看后台日志 `report.*`；确认 `AI_API_KEY` / `AI_BASE_URL` |
| Windows 下 `npm run dev` 报环境变量语法错 | 历史问题 | 已由 `server/dev.mjs` 规避；不要改回 `NODE_ENV=... tsx` 写法 |

## 8. 验证环境是否可用

cwd = 仓库根：

```bash
npm run typecheck
```

- 预期：无输出（或仅 `tsc` 的进度），退出码 `0`。
- 失败指向：类型错误会带 `文件:行:列`；先修类型再跑运行命令。

```bash
npm run check:docs
```

- 预期可 grep 的输出：`文档一致性检查通过。`；退出码 `0`。
- 失败指向：输出会列出“设计文档缺 Qx 的题号/题干”或缺少的关键小节。

完整的交付门槛见 [09-测试与验证.md](./09-测试与验证.md)。当前检出若未执行 `npm install`，`check:deps` 会失败，这是环境未就绪，不是仓库缺陷。
