# 排障手册

> 先看症状表定位，再按“确诊命令 → 原因 → 动作”执行。所有命令默认 cwd = 仓库根；生产环境把 `data/` 换成实际 `DATA_DIR`。

## 1. 一分钟分诊

| 症状 | 先看 | 跳到 |
| --- | --- | --- |
| 进程起不来 / 端口占用 | 启动日志、`EADDRINUSE` | §2 |
| 后台登录失败或一直跳登录 | 401/404、`DEV_GUEST_LOGIN`、会话 | §3 |
| 邀请打不开 / 提交失败 | 404/410/409、限流 | §4 |
| 报告一直转圈 / 失败 | `ai_status`、`ai_error`、队列 | §5 |
| 咨询稿生成失败 | AI 配置、目的树数据、运行状态 | §6 |
| 分数线抓不到 / 覆盖不变 | 失败码、`crawl_runs`、来源开关 | §7 |
| 数据变大 / 磁盘满 / 库锁 | 表行数、快照目录、备份 | §8 |
| 更新脚本失败 | L1–L5 阶段名 | §9 |
| 页面白屏 / 接口 404 | 构建产物、SPA 回退、代理 | §10 |
| 疑似泄露 / 异常登录 | 日志、会话、密钥 | §11 |

## 2. 启动与端口

### 症状：启动即退出，日志有 `server.start_failed`

确诊：

```bash
# cwd = 仓库根；开发模式
npm run dev
```

- 预期：长驻；出现 `server.started`。
- 失败：进程退出，日志含 `server.start_failed` 与 `code`。
- 退出码：`1`（`server.on('error')` 主动退出）。

| `code` / 文案 | 原因 | 动作 |
| --- | --- | --- |
| `EADDRINUSE` | 端口被旧进程占用 | `ss -ltnp \| grep <PORT>` 找到 PID；停旧服务或换 `PORT` |
| `缺少管理员账号…` | 生产环境缺 `ADMIN_USER` / `ADMIN_PASSWORD` | 补 `.env` 后重启 |
| `生产环境必须配置 AUTH_SECRET…` | 生产缺 `AUTH_SECRET` | 生成 ≥32 位随机串 |
| `Cannot find module 'node:sqlite'` | Node < 24 | 升级 Node |
| `Cannot find package 'tsx'` | 未安装依赖 | `npm install`（或 `npm ci`） |

### 症状：本地前端 502 / `/api` 代理失败

- 原因：后端没起在 `8788`，或 Vite 代理目标被改。
- 确诊：`curl -sS http://127.0.0.1:8788/api/health`。
- 动作：先修后端；确认 `web/vite.config.ts` 的代理仍是 `127.0.0.1:8788`。

## 3. 登录与会话

| 症状 | 确诊 | 原因 | 动作 |
| --- | --- | --- | --- |
| 登录返回 401 | 看响应 `error` | 账号密码错、超长、限流 | 核对 `.env`；等 5 分钟或换 IP |
| 开发环境打开 `/admin` 直接进 | 看 `NODE_ENV` | `development` + `DEV_GUEST_LOGIN!==false` 会自动免密 | 想关闭就设 `DEV_GUEST_LOGIN=false` |
| 生产访问 `/api/admin/dev-login` 得 404 | — | 生产不开放免密 | 正常行为，用账号密码登录 |
| 登录后立刻 401 | 看服务是否重启 | 开发未配 `AUTH_SECRET`，临时密钥随重启变化 | 配固定 `AUTH_SECRET` |
| 登出后旧 Token 仍可用 | 查 `admin_sessions` | 会话未删或请求未带 Token | 确认调用了 `/logout`；服务端校验会话 |
| 所有请求共用同一限流桶 | 看反代头 | 在 Nginx 后但 `TRUST_PROXY=false` | 设 `TRUST_PROXY=true` 并重启 |

会话表检查（只读）：

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/<DB_NAME>');console.log(db.prepare('SELECT username,expires_at FROM admin_sessions ORDER BY expires_at DESC LIMIT 5').all())"
```

## 4. 邀请、提交与答卷

| 症状 | HTTP | 原因 | 动作 |
| --- | --- | --- | --- |
| 打开链接提示无效 | 404 | token 不存在、被轮换、库不对 | 后台重新发链接；确认连的是同一 `DATA_DIR` |
| 打开提示过期 | 410 | `expires_at <= now()` | 新建邀请；过期链接不能续期 |
| 提交提示已提交 | 409 | `invite_id` 唯一约束已存在 | 用响应里的 `reportSlug` 跳报告；不要重复提交 |
| 提交提示还有必答题 | 400 | `validateAnswers` 失败 | 看 `missing`；前端草稿可能来自旧问卷版本 |
| 提交 429 | 429 | 8 次/分钟限流 | 等一分钟；确认 `TRUST_PROXY` 正确 |
| 后台名单没有新答卷 | — | 提交事务失败或连错库 | 查 `submit.stored` 日志与 `submissions` 行数 |
| 联系方式解密为空 | — | `CONTACT_KEY` 变更 | 换回旧 key 才能解；否则只能放弃旧密文 |

提交失败时日志有 `submit.invalid`，字段含 `inviteId`、`answerCount`、`error`。成功有 `submit.stored`，字段含 `submissionId`、`reportMode`。

## 5. 报告与 AI

### 5.1 状态机

`submissions.ai_status`：

| 状态 | 含义 | 前端表现 |
| --- | --- | --- |
| `pending` | 已入队或等待重试 | 加载中（`doc` 模式无基础版） |
| `running` | 正在调用 AI | 加载中 |
| `ready` | 有可用报告 | 展示报告 |
| `failed` | 终态失败 | 可重试则显示“重新生成”，否则显示联系发链接的人 |

### 5.2 常见失败

| 症状 / `ai_error` | 可重试 | 原因 | 动作 |
| --- | --- | --- | --- |
| `未配置 AI_API_KEY（或 DEEPSEEK_API_KEY）` | 否 | 缺 key | 配 `AI_API_KEY` + `AI_BASE_URL`，重启 |
| `未配置 AI_BASE_URL（或 DEEPSEEK_BASE_URL）` | 否 | 缺基地址 | 补 `.env` |
| `DeepSeek 请求失败（401/402/403）` | 否 | key 无效、欠费、无权限 | 换 key / 充值；不要反复重试 |
| `DeepSeek 请求失败（400/404/422）` | 否 | 模型名或请求格式不对 | 核对 `AI_MODEL`、接口兼容性 |
| `DeepSeek 请求失败（429/5xx）` | 是 | 限流或上游故障 | 等自动重试；持续失败看上游状态 |
| `AI 返回的内容不是合法 JSON` | 是 | 模型输出漂移 | 自动重试；频繁发生则调整 Skill/提示词 |
| `DeepSeek 没有返回内容` | 是 | 被截断或空响应 | 检查 `max_tokens` 与模型 |
| `doc.audit_failed` / `report.audit_failed` | 是 | 审计发现事实矛盾/缺块 | 看日志里的审计问题；必要时改规则 |
| `分析规则为空` / `分析规则不存在` | 否 | Skill 被删或为空 | 后台重新激活模板 |
| 一直 `pending` 不动 | — | 队列被两个长任务占满，或进程重启丢了未开始任务 | 看 `ai.start` / `ai.retry`；必要时后台“重新生成” |
| 重启后报告仍 `running` | — | 启动恢复只处理未超次数的记录 | 看 `resumeUnfinishedReports` 日志；超次数需人工重试 |

### 5.3 确诊命令

```bash
# cwd = 仓库根；只读查询
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/<DB_NAME>');console.log(db.prepare('SELECT ai_status,COUNT(*) c FROM submissions GROUP BY ai_status').all());console.log(db.prepare(\"SELECT id,ai_status,ai_attempts,ai_error FROM submissions WHERE ai_status!='ready' ORDER BY created_at DESC LIMIT 10\").all())"
```

```bash
# systemd 部署：抓 AI 相关日志
journalctl -u vesta -n 300 --no-pager | grep -E 'ai\.(start|call|failed|retry|ready)|doc\.audit'
```

- 预期：能看到同一 `submissionId` 的 `ai.start` → `ai.call` → `ai.ready`，或 `ai.failed` + 原因。
- 失败指向：若只有 `ai.start` 没有后续，通常是进程在调用中被重启，或请求超时（`AI_TIMEOUT_MS`）。

### 5.4 队列与重试规则

- 并发 2、FIFO、最多 4 次尝试，延迟 5s / 15s / 30s（`server/src/ai/report-queue.ts`、`server/src/ai/generate.ts`）。
- 重试判定（`isRetryableError`）：包含“未配置 / 分析规则为空 / 分析规则不存在 / 没有可用的正文” → 不重试；DeepSeek 400/401/402/403/404/422 → 不重试；其余 → 重试。
- 终态失败仍保留真实 `ai_error` 供后台排查；学员侧只看到映射后的可执行提示。

### 5.5 搜索失败

| 日志 / 现象 | 原因 | 动作 |
| --- | --- | --- |
| `search.skipped` | 未配 Bocha | 正常；报告不联网 |
| `未配置 BOCHA_API_KEY` / `BOCHA_BASE_URL` | 配了 key 缺地址或反之 | 两个一起配 |
| `Bocha 检索失败（4xx/5xx）` | 上游拒绝或故障 | 看状态码；429 等一会；错误不写缓存 |
| `Bocha 返回了无法解析的内容` | 响应结构变化 | 查 `server/src/ai/bocha.ts` 的解析分支 |

搜索最多 4 次、结果缓存 7 天、单飞（同 key 并发只发一次）。搜索失败不应让整份报告硬失败；若出现硬失败，看 `doc-search` 的降级分支。

## 6. 咨询稿

| 症状 | HTTP/日志 | 原因 | 动作 |
| --- | --- | --- | --- |
| 创建即 503 | `未配置 DEEPSEEK_API_KEY…` | AI 未配置 | 配 key 并重启 |
| `GET /purposes` 500 | “咨询树数据还没有生成” | 缺 `consult-purpose-data.json` 或生成失败 | 运行 `node prototype/consult-purpose-tree/generate.mjs`（脚本在 prototype 下） |
| 创建 400 无路径 | — | 逐句树为空或上下文不足 | 检查 `consult-forest-seed.json`；补充上下文 |
| 运行卡在 `queued` | 无 `consult.start` | 进程重启，内存任务丢失 | `POST /runs/:id/retry` |
| 某章节 `failed` | `consult.section.failed` | 单节生成失败 | 单节 `regenerate`，或手动编辑 |
| 导出 400 | — | run 未完成 | 等 `ready` 或补全章节 |
| 导出中文名乱码 | — | 客户端未按 RFC 5987 解析 | 用响应头的 `filename*` |

## 7. 分数线抓取

### 7.1 失败码

`crawl_runs.message` / `scoreline_sources.last_error` 以失败码开头，格式 `code: detail`。覆盖页的 `crawlFailureHint()` 按行首码给下一步。

| 码 | 含义（按解析器与覆盖提示） | 典型动作 |
| --- | --- | --- |
| `network` | 请求失败、超时、DNS/TLS | 检查服务器出网、目标站点可达性、代理 |
| `entry_redirect` | 入口页跳转异常 | 更新来源 `url` / `entry_url` |
| `no_table` | 页面里没找到可解析表格 | 站点改版；补选择器或新解析器 |
| `unsupported_table` | 表格形状不支持 | 用 fixture 复现后扩展解析器 |
| `no_text_layer` | PDF 没有文本层（扫描件） | 当前不支持 OCR；改为人工导入或找 HTML 源 |
| `parse` | 通用解析失败 | 看 `details` 前几条 issue |
| `decode` | 编码/解码失败 | 检查响应头与文件类型 |
| `needs_seed` | 缺院校种子/别名，无法归属 | 先导入院校或补别名 |

### 7.2 状态与覆盖

| 现象 | 原因 | 动作 |
| --- | --- | --- |
| 抓取成功但查询不到 | 数据仍 `pending` | 后台复核通过后才可查 |
| 覆盖一直 `pending` | 有未复核数据 | 复核批次/专业 |
| 覆盖 `failed` | 最近一次抓取失败 | 看 `last_error` 的失败码 |
| 覆盖 `not_offered` | 明确不招生 | 正常；后台是否可手动标记需确认 |
| 调度不再触发 | 队列里有 `running` 残留 | 见 §7.3 |
| 手动抓取 409 `NO_SOURCE` | 该省没有启用来源 | 后台补来源或启用 |
| 手动抓取 429 | 5 次/分钟 | 等一分钟 |

### 7.3 高风险：崩溃留下的 `running` 残留

调度器只在**没有任何 `queued|running`** 时才入队（`scheduleOnce`）。抓取进程如果在 `running` 状态被重启，数据库行不会自动回到 `failed`，自动调度会一直停摆。

确诊（只读）：

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/<DB_NAME>');console.log(db.prepare(\"SELECT id,province,status,started_at FROM crawl_runs WHERE status IN ('queued','running')\").all())"
```

- 预期：正常情况下只应有当前正在跑的一条。
- 若 `started_at` 远早于当前时间且进程已重启，基本可判定为残留。
- 处理需要改数据库状态（属于写操作），必须先备份并人工确认；不要直接删除运行记录。该行为是否应在启动时自动修复，登记为待确认项。

## 8. 数据库、磁盘与锁

| 症状 | 确诊 | 原因 | 动作 |
| --- | --- | --- | --- |
| `SQLITE_BUSY` | 日志堆栈 | 长事务 / 外部进程写库 | 停止外部写入；不要并发跑脚本 |
| 健康检查 `db:false` | `/api/health` | 文件权限、磁盘满、库损坏 | 看 `health.db_failed` 日志；检查权限与 `df -h` |
| 磁盘持续增长 | `du -sh data/*` | 抓取快照、备份、事件 | 快照 90 天自动清；备份保留 14 份；事件 180/365 天 |
| 删除后文件不缩小 | `ls -lh data/vesta.db` | SQLite 不自动回收 | 评估 `VACUUM`（需停写、额外磁盘） |
| 备份失败 | 更新日志“数据备份”阶段 | 磁盘满、路径不存在 | 先清空间；确认 `data/backups` 可写 |

只读统计示例：

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/<DB_NAME>');for(const t of ['invites','submissions','events','consult_runs','crawl_documents']){console.log(t,db.prepare('SELECT COUNT(*) c FROM '+t).get().c)}"
```

## 9. 部署与更新失败

| 阶段 | 典型输出 | 原因 | 动作 |
| --- | --- | --- | --- |
| L1 代码 | 工作区有未提交改动 | 服务器上有本地改动 | `git stash push -u` 后再更新；不要 `reset --hard` 除非确认放弃 |
| L1 代码 | detached HEAD / 分支不是 main | 手工 checkout 过 | `git switch main` |
| L1 代码 | 无法快进 | 本地与远程分叉 | 手工 `git rebase origin/main` 后重跑；脚本不会自动 reset |
| L2 依赖 | `npm ci` 失败 | 锁文件/网络/Node 版本 | 修网络或 Node；不要在服务器改锁文件 |
| L2 依赖 | `npm ls` 报 missing/invalid | 依赖树损坏 | 脚本会自动再 `npm ci`；仍失败看具体包 |
| 数据备份 | 备份失败 | 磁盘/权限 | 清空间；修权限；不会继续构建 |
| L3 构建 | `npm run build` 失败 | 类型/依赖/内存 | 本地先复现；脚本已恢复上一版 dist |
| L3 构建 | 产物时间早于构建开始 | 缓存/时钟问题 | 检查系统时间与构建缓存 |
| L4 进程 | 30 秒内未观察到新进程 | 服务起不来 | 看脚本打印的最近日志；按 §2 排查 |
| L4 进程 | `DEPLOY_MODE=none` | 不自动重启 | 改用 `--mode=systemd/pm2/docker` |
| L5 对外 | health 非 200 / 版本不一致 | 新进程没起来、`deploy-info.json` 未更新、连错端口 | 查 `deploy-info.json`、`PORT`、反代 |
| L5 对外 | 首页不含新指纹 | 静态目录未更新/被缓存 | 查 `web/dist/index.html`；清 CDN 缓存 |

## 10. 前端与页面

| 症状 | 原因 | 动作 |
| --- | --- | --- |
| 刷新 `/admin/...` 404 | 静态托管未做 SPA 回退 | 确认 `server/src/index.ts` 的 fallback 生效；反代不要拦截 |
| 页面白屏 | JS 产物缺失/版本不匹配 | 看 Network 的 `assets/*.js` 是否 404；重新构建 |
| API 请求 404 但后端有路由 | 基地址/代理错 | 看请求 URL 是否带 `/api`；开发看 Vite 代理 |
| API 401 后不跳登录 | `request.ts` 未处理 | 看控制台；确认 Token 是否过期 |
| 报告页一直转圈 | `doc` 模式 AI 未完成 | 看 §5；`pending/running` 是正常中间态 |
| 导出图片/PDF 失败 | 浏览器内存/CORS/字体 | 换浏览器；看控制台；报告特别长时降低分辨率 |

## 11. 安全事件处置

| 事件 | 立即动作 | 后续 |
| --- | --- | --- |
| 怀疑 `AUTH_SECRET` 泄露 | 更换 `AUTH_SECRET` 并重启，所有会话失效 | 查 `admin_sessions` 与登录日志；评估是否被写入 |
| 怀疑 `CONTACT_KEY` 泄露 | 更换 key（旧密文将不可解） | 评估是否需要导出/重加密工具 |
| 发现仓库含真实学员资料 | 停止扩散；由仓库所有者决定取消跟踪与历史清理 | 见 AGENT.md §5 最高优先级项 |
| 异常大量提交/登录 | 看 429 与来源 IP | 调整 `TRUST_PROXY`、限流或前置 WAF |
| 日志出现明文 token/slug | 视为脱敏缺陷 | 检查 `server/src/index.ts` 的 `logPath` 覆盖范围 |

事件响应期间不要执行 `git push`、不要删除日志、不要覆盖数据库；先备份再操作。

## 12. 排障侧待确认

| 项 | 为什么需要确认 | 验证命令 |
| --- | --- | --- |
| 抓取 `running` 残留是否自动修复 | 调度器会永久停摆 | 读 `crawl-scheduler.ts` 与 `crawl.ts` 是否有启动清理 |
| 报告 `running` 超时阈值 | 决定“卡住”判定 | `grep -n "startedAt\|timeout\|STALE" server/src/ai/generate.ts` |
| `not_offered` 的后台入口 | 影响覆盖维护 | `grep -rn "not_offered" server/src web/src` |
| 前端 401 统一跳转 | 影响会话过期体验 | `grep -n "401" web/src/api/request.ts` |
| `deploy-info.json` 缺失时的告警 | L5 会退化校验 | 看 `server/src/deploy-info.ts` |
