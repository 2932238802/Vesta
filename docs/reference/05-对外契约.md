# 对外契约

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 基地址 | 同源；开发时 Vite 把 `/api` 代理到 `127.0.0.1:8788` |
| 请求体 | `application/json`；唯一的例外是 `POST /api/admin/consult/collections/import-docx`，它收原始 `.docx` 字节 |
| 响应体 | JSON；导出接口返回二进制或文本 |
| 鉴权 | 管理接口需 `Authorization: Bearer <TOKEN>`；Token 由登录接口返回 |
| 缓存 | 绝大多数接口调用 `noStore(res)`，响应带禁止缓存头 |
| 错误形状 | `{ "error": "给人看的中文提示", "errors"?: string[], "missing"?: string[], "code"?: string, "reportSlug"?: string }` |
| 时间 | ISO 8601 字符串，服务端统一 `now()` 生成 |
| 占位符 | `<TOKEN>` 为登录返回的 Bearer Token；`<DOMAIN>` 为对外域名 |

### 1.1 限流

内存计数，按来源 IP（或 `TRUST_PROXY=true` 时的转发 IP）。超限返回 `429`。

| 作用域 | 限额 |
| --- | --- |
| 登录 `/api/admin/login` | 10 次 / 5 分钟 |
| 打开邀请 `/api/invite/:token` | 60 次 / 分钟 |
| 提交 `/api/invite/:token/submit` | 8 次 / 分钟 |
| 报告轮询 `/api/report/:slug` | 120 次 / 分钟 |
| 报告重试 `/api/report/:slug/retry` | 5 次 / 分钟 |
| 领取 `/api/report/:slug/claim` | 6 次 / 分钟 |
| 事件 `/api/events` | 60 次 / 分钟 |
| 抓取 `/api/admin/score-lines/crawl` | 5 次 / 分钟 |

### 1.2 登录与登出

| 方法 | 路径 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| POST | `/api/admin/login` | `{username, password}` | `200 {token, user:{username}}` | `401 账号或密码不对`；超长输入同样 401；限流 429 |
| POST | `/api/admin/dev-login` | 无 | `200 {token, user:{username}}` | 非开发环境或 `DEV_GUEST_LOGIN=false` → `404 接口不存在` |
| GET | `/api/admin/me` | Bearer | `200 {user:{username}}` | 缺 Token / 会话失效 → `401` |
| POST | `/api/admin/logout` | Bearer | `200 {ok:true}`，并删除 `admin_sessions` 行 | `401` |

Token 是 HMAC 签名串；服务端同时校验 `admin_sessions`，所以登出、会话过期、数据库换库都会让旧 Token 失效。

## 2. 公开接口

### 2.1 健康检查

`GET /api/health`

```json
{
  "ok": true,
  "time": "2026-11-16T00:00:00.000Z",
  "db": true,
  "uptimeSec": 123,
  "commit": "",
  "appVersion": ""
}
```

- `db`：执行 `SELECT 1` 是否成功；失败时为 `false`，HTTP 仍为 `200`（由调用方判断）。
- `commit` / `appVersion`：读 `data/deploy-info.json`；文件不存在时为空串，**不要**拿 `version` 字段冒充 commit。

### 2.2 邀请

| 方法 | 路径 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| GET | `/api/invite/:token` | 无 | `200 {name, note, survey, submitted, reportSlug}` | `404 链接无效…`；`410 链接已过期…` |
| POST | `/api/invite/:token/submit` | `{answers, timing}` | `200 {slug}` | `400` + `errors/missing`；`404`；`410`；`409 {error, reportSlug}` |
| POST | `/api/events` | `{token, events:[{type,payload}]}` | `200 {ok:true}` | `404 链接无效` |

`answers` 是题目 id → 答案的对象；`timing` 是题目 id → 毫秒数（服务端截断到 15 分钟）。事件类型白名单只有 6 个：`invite_open`、`quiz_start`、`group_complete`、`quiz_exit`、`report_view`、`claim_view`；单次最多 20 条，payload 截断到 2000 字符。

### 2.3 报告

| 方法 | 路径 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| GET | `/api/report/:slug` | 可选 `?poll=1&preview=1` | `200 {status, report, name, error?, retryable?, notice?}` | `404 报告不存在` |
| POST | `/api/report/:slug/retry` | 无 | `200 {ok:true, status:"pending"}` | `404`；`409` 已生成或非 doc；`503 AI 分析还没有配置…` |
| POST | `/api/report/:slug/claim` | `{wechat, slots, agree}` | `200 {ok:true}` | `400` 格式错误；`409 已经提交过了` |

`status` 取值：`pending | running | ready | failed`。`report` 为结构化报告对象或 `null`。`retryable` 仅失败时出现，前端据此决定是否显示“重新生成”。

领取约束：`wechat` 2–80 字；`slots` 1–3 个、每个 ≤80 字；`agree === true`；联系方式加密后存 `wechat_enc`。

`batches[].metrics[]` 结构：`{subjectCode, subjectName, fullScore?, value, isMinimum?, minimumType?, note?}`。`minimumType` 取 `''|'admit'|'retest'|'transfer'|'other'`。单次 ≤200 批次，每批 ≤100 指标。

`query` 的 `requires` 是缺失的筛选维度提示（例如还没给科类/科目），前端据此渲染 “facets/chips”；详见 `shared/src/score-line.ts` 与 `server/src/score-lines/query.ts`。

选学校 + 专业时，`programLine` 与 `minimums` 一并返回。校级录取表只写最低分（`subject_code='total'`、`minimum_type='admit'`）时，最低分既进入 `programLine`（供卡片展示）也进入 `minimums`（趋势图空心标记 / 数据表单独行），不会出现“有最低分但页面显示未收录”。专科院校 `school.level='专科'`，页面据此提示不设专升本院校线。

`facets` 只统计 `review_status='approved'` 的主线；`category` / `track` 互相级联。空维度用 `__unlabeled__`（常量 `DIMENSION_UNLABELED`）表示“未标注”，查询时显式传该值即可筛选未标注批次。

| POST | `/api/admin/consult/runs/:id/retry` | 无 | `{run}` | `404`；状态不允许 |
| PATCH | `/api/admin/consult/runs/:id/outcome` | `{outcome}` | `{ok, run, outcome, outcomeNodeId}` | `400` 非法 outcome；`404` |

`outcome` 取值：`'' | 'won' | 'lost' | 'liked' | 'abandoned'`。`mode` 取值：`sentence`（默认）| `purpose`。章节 `seq` 从 1 开始；`beats` 传入后会反推 `content`。

故事集的字段约束：标题 `trim` 后 1–120 字、正文 `trim` 后 1–20000 字、出处 ≤200 字、分类名 `trim` 后 1–30 字；`categoryId` 必须存在。故事对象含 `pinnedAt`（最近置顶时间，未置顶为空字符串）；置顶时写入当前时间，取消置顶清空。排序为置顶优先，置顶组内按 `pinnedAt` 倒序，其后 `sortOrder`、`createdAt`，最后按 `id` 稳定排序。分类顺序接口要求 `ids` 恰好是现有全部分类的完整排列；删除非空分类返回 `409` 并带 `count`。日志只记录 `id` / `categoryId` / `pinned` / `count`，不记录标题与正文。

有效的提问的字段约束：正文 `trim` 后 1–2000 字、备注 `trim` 后 ≤2000 字（可为空）、分类名 `trim` 后 1–30 字；`categoryId` 必须存在。提问对象含 `note`（唯一备注）与 `pinnedAt`（最近置顶时间，未置顶为空字符串）；置顶时写入当前时间，已置顶编辑保留原时间，取消置顶清空。排序与故事集一致：置顶优先，置顶组内按 `pinnedAt` 倒序，其后 `sortOrder`、`createdAt`，最后按 `id` 稳定排序。分类顺序接口要求 `ids` 恰好是现有全部分类的完整排列；删除非空分类返回 `409 分类下还有提问` 并带 `count`。日志只记录 `id` / `categoryId` / `pinned`，不记录正文与备注。

大学常识的字段约束：标题 `trim` 后 1–120 字、正文 `trim` 后 1–50000 字。对象含 `sortOrder`、`createdAt`、`updatedAt`；列表接口只返回摘要（`id` / `title` / `sortOrder` / `createdAt` / `updatedAt`），正文按篇读取。新话题的 `sortOrder` 为当前最大值 +1（追加末尾）；列表按 `sortOrder`、`createdAt`、`id` 稳定排序。排序接口要求 `ids` 恰好是现有全部话题的完整排列（不重复、无未知 id），单事务重写；未登录 401、参数非法 400、不存在 404。日志只记录 `id` / `count` 与 `reqId`，不记录标题与正文。

### 3.7 专业知识汇总

| 方法 | 路径 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| GET | `/api/admin/knowledge` | 无 | `{majors, articles}`，专业含 `count`，知识点为摘要（不含正文） | — |
| GET | `/api/admin/knowledge/articles/:id` | 无 | `{article}`（含 `body`） | `404 知识点不存在` |
| POST | `/api/admin/knowledge/articles` | `{majorId, title, body}` | `201 {article}` | 专业不存在 / 标题或正文为空或超长 `400` |
| PATCH | `/api/admin/knowledge/articles/:id` | `{majorId?, title?, body?}` | `{article}` | `404`；`400` |
| DELETE | `/api/admin/knowledge/articles/:id` | 无 | `{ok:true}` | `404` |
| POST | `/api/admin/knowledge/majors` | `{name}` | `201 {major}` | 空名 / 超长 `400`；重名 `409 专业名重复` |
| PATCH | `/api/admin/knowledge/majors/:id` | `{name}` | `{major}` | `404`；`400`；重名 `409` |
| PUT | `/api/admin/knowledge/majors/order` | `{ids:[...]}` | `{majors}` | `400 专业顺序不是现有专业的完整排列` |
| DELETE | `/api/admin/knowledge/majors/:id` | 无 | `{ok:true}` | `404`；非空 `409 专业下还有知识点`，响应含 `count` |

字段约束：专业名 `trim` 后 1–30 字且唯一；知识点标题 `trim` 后 1–120 字、正文 `trim` 后 1–50000 字；`majorId` 必须存在。新增知识点排在该专业末尾；编辑时换专业会把 `sort_order` 置为新专业末尾。排序接口要求 `ids` 恰好是现有全部专业的一个排列，单事务写入。日志只记录 `id` / `majorId` / `count`，不记录专业名、标题或正文。

## 4. 前端调用对照

| 前端文件 | 覆盖接口 |
| --- | --- |
| `web/src/api/public.ts` | 健康检查之外的公开接口：邀请、提交、报告、重试、领取、事件 |
| `web/src/api/admin.ts` | 登录、概览、邀请、名单、答卷、设置、分数线、导出 |
| `web/src/api/consult.ts` | 咨询工作台、目的树、金句栏、故事集、有效的提问、大学常识、收藏、运行与章节 |
| `web/src/api/knowledge.ts` | 专业知识汇总：专业与知识点的读写、调序 |
| `web/src/api/request.ts` | 统一 `request` / `query` / `ApiError` / Token 注入 |

新增接口时三处要同步：服务端路由、`web/src/api/*` 的类型与方法、本篇契约表。只改服务端会造成前端类型漂移；只改前端会在运行时 404。

## 5. 契约级边界

| 边界 | 行为 |
| --- | --- |
| 未带 Token 访问管理接口 | `401`，前端清 Token 并跳登录 |
| Token 有效但会话被登出 | `401`，同上 |
| 请求体不是 JSON | Express 解析失败 → `400`，日志带 `reqId` |
| 超大 JSON | 由 body 限制拒绝；DOCX 导入单独 20MB |
| 未知路由 `/api/*` | 落到 SPA 前的 404 JSON 或静态回退，不应返回 HTML 给 API 调用方 |
| CSV 导出 | 需要 Bearer；前端不能用裸 `<a href>`，否则不带鉴权 |
