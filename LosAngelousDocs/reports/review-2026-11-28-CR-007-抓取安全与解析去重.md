## 缺陷清单（按严重度降序）

### [P2] 内网地址判定不完整：IPv4-mapped IPv6 / 0.0.0.0 / [::] / NAT64 可绕过 SSRF 校验

- 位置：`server/src/score-lines/crawl-fetch.ts:13-28`（`isPrivateHostname`）；被 `crawl-fetch.ts:39-40` 与 `:201-208` 使用
- 问题：`isPrivateHostname` 只匹配 `127.`、`10.`、`192.168.`、`169.254.`、`172.16-31`、`localhost`、`::1`、`.local`、`fc/fd/fe80` 前缀。WHATWG URL 会把 `http://[::ffff:127.0.0.1]/` 规范化为 hostname `[::ffff:7f00:1]`（以 `[` 开头，不落入任何前缀/`.local` 分支），因此被判为“公网”；`0.0.0.0`、`[::]`、`[64:ff9b::7f00:1]`（NAT64）同理漏判。
- 触发条件：任一被信任来源站点返回 `302 Location: http://[::ffff:127.0.0.1]:<port>/...`（或 `http://0.0.0.0/`）时，逐跳校验放行，第二次请求会发往本机/内网服务。
- 影响：SSRF 防护被编码变体绕过，可能访问本机或内网服务；属防御纵深缺口，非本 CR 枚举的 6 类地址。
- 证据：独立复现（Node 24）：
  `http://[::ffff:127.0.0.1]/ => host=[::ffff:7f00:1] private=false`；`http://0.0.0.0/ => private=false`；`http://[::]/ => private=false`；对照 `127.0.0.1/`、`[::1]`、`192.168.1.1`、`printer.local` 均为 `private=true`。
- 建议：改用 `node:net` 的 `isIP` + 解析判断：拒绝 `0.0.0.0/8`、`::`、IPv4-mapped（`::ffff:0:0/96`）、`fc00::/7`、`fe80::/10`、`ff00::/8` 及所有 RFC1918/回环/链路本地；或与 DNS rebinding 一并写成明确残留并在 `03-design` 标注。最小修复：在 `isPrivateHostname` 内把 host 去掉方括号后按 `::ffff:` 前缀与 `0.0.0.0` 判定。
- 置信度：高（技术与复现确定）；真实影响中（依赖来源站点可控跳转、seed 为受信站点）。

### [P2] `duplicate_table_metric` issue 在真实抓取链路未落库/未记日志，重复值不可追溯

- 位置：`server/src/score-lines/parsers/html.ts:76-81`（生成 issue）→ `server/src/score-lines/crawl.ts:465-484`（成功路径只取 `batches`，`result.issues` 未使用）
- 问题：解析器把重复指标写入 `result.issues`，但 `processPage` 在 `batches.length > 0` 时只用 `codedError(result)`（仅无批次时读 issues），成功抓取后 issues 被丢弃；`crawl_documents` 只存 `note`/`shape`，不含 issues。
- 触发条件：真实页面出现跨表重复 `subjectCode|isMinimum|minimumType`（如两张表都含「总分」且值不同）。
- 影响：第二次值被丢弃后没有任何 DB 记录或日志可查，运营/排障无法知道“某页有两个不同总分”；与 AC-007-4「记录 `duplicate_table_metric` issue」及 CR 风险「issue 可追溯」不一致。
- 证据：`grep -n issues server/src/score-lines/crawl.ts` 仅命中 `codedError` 与专业批次校验，无成功路径日志；`check:crawl` 5e 断言 `error=''`、DB 仅 1 条，但未断言任何 issue 落点。
- 建议：在 `processPage` 成功解析分支对 `result.issues` 写结构化日志（如 `scoreline.parse_issue`，含 sourceId/url/issue）或追加到 `crawl_documents.note`；并补一条断言“真实抓取后可在日志/记录中检索到 duplicate_table_metric”。
- 置信度：高（代码路径确定）。

### [P3] 缺少非法/缺失 `Location` 与 HTTPS→HTTP 生产拒绝的自动化用例

- 位置：`crawl-fetch.ts:184-200`；`crawl-reliability.cases.ts:476-534`
- 问题：缺失/非法 Location、HTTPS→HTTP 降级仅有实现分支，无用例覆盖；现有夹具全为 HTTP，且测试文件常驻 `SCORELINE_CRAWL_ALLOW_PRIVATE=1`。
- 触发条件 / 影响：若后续重构误删这些分支，回归不会报警；属测试保真缺口，不影响本次行为。
- 建议：新增“无 Location 的 302”“`Location: http://[::1]/` 非法/私网”“生产模式（临时 `SCORELINE_CRAWL_ALLOW_PRIVATE` 未设）下 HTTPS→HTTP 拒绝”用例。
- 置信度：高。

### [P3] 引导页第二跳 401/403 → `blocked` 分支无自动化用例

- 位置：`crawl.ts:445-457`
- 问题：Dev 声称「含引导页第二跳」已映射 blocked，但 `check:crawl` 5d 只测入口直接 403/401，未覆盖“入口 200 引导页 → 第二跳 403”。
- 影响：该分支行为（写入 `blocked:` 且不重试）缺乏回归保护；AC-007-3 主体已由主路径证据满足。
- 建议：补一个“入口返回带 meta refresh 的引导页、目标返回 403”的夹具，断言 document.error/来源 last_error 以 `blocked:` 开头且目标仅请求 1 次。
- 置信度：高。

### [P3] 新增 `finalUrl` 未被调用方使用，`crawl_documents.url` 仍记原始 URL

- 位置：`crawl-fetch.ts:227`（返回 `finalUrl: current`）；`crawl.ts:402/468`（`finalUrl` 本地变量初始化为 `url`，未用 `fetched.finalUrl`；document 写 `url`）
- 问题：CR 范围写「最终 URL 记录/可用」，实际只“可用”未“记录”，对内部跟随的公开跳转，DB 仍记入口 URL。
- 影响：可观测性小缺口，不构成回归（旧 `redirect:'follow'` 行为相同）。
- 建议：在 `processPage` 用 `fetched.finalUrl` 写入 document.note 或独立列；或把 CR 口径改为“可用即可”。
- 置信度：高。

### [P3] blocked 主路径的 `crawl_documents.http_status` 记为 0，401/403 无法从状态列区分

- 位置：`crawl.ts:500-513`（`httpStatus: fetched?.httpStatus ?? 0`；403 时 `fetched` 为 null）
- 问题：403/401 被 `FetchStatusError` 抛出，`fetched` 未赋值，document 状态记为 0；错误文案含 `HTTP 403`，但状态列不可查。
- 影响：排障需读 error 文本；属既有模式延续，非本 CR 引入。
