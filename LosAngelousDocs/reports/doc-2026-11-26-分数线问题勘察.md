## 结论

分数线模块的解析器 fixture 全绿（`npm run check:score`），但**查询 / 复核 / 抓取写入链路存在会造成数据丢失、盲审和调度卡死的问题**。建议先修 3 个数据正确性问题，再修复核可用性与抓取韧性。

## 勘察范围

- 代码：`server/src/score-lines/*`、`server/src/routes/admin/score-lines*.ts`、`shared/src/score-line*.ts`、`web/src/views/admin/ScoreLines.vue` 与 `score-lines/*`。
- 文档：`docs/reference/README.md` 分数线节、`development-history.md` v1.77–v1.89、`AGENT.md` 已知问题。
- 基线：`npm run check:score` 全部通过；`npm run verify` 2026-11-26 EXIT=0。
- 临时库验证（仓库外 `_vesta-backups/_probe`，未碰 `data/`）：
  - 同一批次 checksum 不变、再次以 `pending` 写入 → 状态从 `approved` 变为 `pending`。
  - 两条 `major_code` 为空的招生计划 → 生成同一 id，只剩 1 行，专业名被后一条覆盖。
  - 考研国家线 `region=''` 写入并 approved → 浙江查询 `main=null`、覆盖 `no_data`；补 `region='A区'` 后可查到。

## 问题清单

### P0 数据正确性（优先修）

| # | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| P0-1 | 抓取每次都以 `pending` 覆盖写，即使 checksum 未变，已通过的批次会被打回待复核 | `crawl.ts:265-273`；`batch-store.ts:155-172`；`shared/src/score-line.ts:563-580` 已有 `batchChecksum` 但抓取未使用 | 每次抓取后已审核数据从查询消失，需重新复核；反复抓取会反复丢数据 | 写入前比较 `previous.checksum`：相同且已 approved 时保留 approved；内容变化才置 pending |
| P0-2 | 招生计划唯一键缺 `major_name`，`major_code` 为空时多条计划互相覆盖 | `schema.ts:404-405`；`program-store.ts:115-129` | 同一校同年同培养方式下，只能留下最后一条专业；计划数 / 覆盖率错误 | 唯一键补 `major_name`（或空 code 时用名称生成稳定 key），并做迁移兼容 |
| P0-3 | 人工导入逐条写库，遇到后面的非法院校 / 专业直接返回 400，前面已写入不回滚 | `score-lines-import.ts:137-156` | 用户看到「导入失败」，但库里已有部分数据；重复导入可能再次覆盖 | 先全量校验引用与唯一键，再在一个事务里写；或任何失败回滚整批 |
| P1-1 | 复核页看不到指标、来源、异常备注，也没有批次详情接口，只能看标题和置信度 | `score-lines-import.ts:290-294`（SELECT 不含 metrics/note/source）；`ReviewView.vue:40-64`；无 batch detail 路由 | 复核=盲审；`anomalyIssues` 写入的同比异常根本看不到；容易把错数放行 | 增加 `GET /score-lines/batches/:id`（指标 + 来源 + note + 维度 + 原文快照链接），复核行展开显示 |
| P1-2 | 抓取 `running` / `queued` 残留会永久阻塞调度；启动没有自愈 | `crawl-scheduler.ts:9-12` 有任意 in-flight 就不排；`crawl.ts:480-492` 只有内存 `running`；`index.ts:182-204` 无恢复 | 进程崩溃 / 重启后自动抓取永久停止，只能人工改库 | 启动时把超时的 `running` 标 failed、把遗留 `queued` 重新入队；调度器忽略超时 running |
| P1-3 | 考研国家线允许 `region=''` 导入，但查询 / facets / 覆盖都按 A/B 区等值过滤 | `shared/src/score-line.ts:459-460` 未要求 region；`query.ts:257-259`、`facets.ts:104-107` | 数据存在却查不到，覆盖显示无数据；人工导入最容易踩 | 国家线校验要求 `region` 为 A区/B区；或把空 region 当作通配并在查询/覆盖统一处理 |
| P1-4 | 前端改年份 / 省份不清院校、专业和旧结果；查询没有请求序号 | `ScoreLines.vue:459-467`（watch 只清 category/track）；`ScoreLines.vue:333-354`（无 seq）；`ScoreLineFilters.vue:158-164` | 筛选条件与结果不一致；快速操作时旧响应覆盖新结果 | 变更 exam/year/province 时清 school/program/result；查询加 `querySeq` 丢弃过期响应 |
| P1-5 | 一个页面多张表会合并成同一批次；跨表重复科目可能触发指标唯一键失败，并被误报为 `network` | `parsers/html.ts:36-63`；`parsers/table.ts:81-99` 只在单表内去重；`schema.ts:453-454`；`crawl.ts:389-408` 捕获后记 network | 多类别 / 多年份页面数据混批或整批写失败；失败原因误导 | 按表 / 标题拆批次；跨表去重；`saveBatch` 异常单独记 `parse` / `db` 失败码 |

### P1/P2 安全与运维

| # | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| S-1 | 抓取只校验初始 URL，`redirect: follow` 后不校验最终 URL | `crawl-fetch.ts:35-60`；`assertSafeUrl` 只在入口调用 | 公开站点可 302 到内网，形成 SSRF；DNS 解析也未限制 | `redirect: 'manual'` 逐跳校验，或校验 `response.url` 的 host/IP；解析后拒绝私网地址 |
| O-1 | 抓取原始快照只在启动时清理一次，长期运行不清理 | `index.ts:190`（启动调用）、`index.ts:203` 只给 events 设定时器 | `data/crawl/` 持续增长 | 加每日 / 每周定时 prune，或并入现有 24h 定时器 |
| O-2 | 种子每次启动无条件覆盖 `scoreline_sources.url` 等字段 | `sources.ts:204-213` | 管理员改过的来源地址重启后被重置 | 与 `entry_url/verified` 一样保留库内值，或区分种子字段与人工字段 |
| O-3 | 省市运行时限只在「源之间」检查，单源可跑满 30 页 | `crawl.ts:516-520`；`processSource` 内部无 deadline | 一次抓取可能远超 30 分钟，阻塞其他省 | 把 deadline 传进 `processSource` / `processPage`，每页检查 |
| O-4 | 无瞬时网络重试；下载完成后才检查 10MB；固定 30s 超时 | `crawl-fetch.ts:41-60` | 单次抖动即失败；大文件先占内存 | 瞬时错误退避重试一次；先看 `Content-Length`，流式限长 |
| O-5 | `not_offered` 只在刷新时保留，没有 API / UI 可设置 | `coverage.ts:122-124`；`grep -rn "not_offered" server/src web/src` | 「不招生」只能改库，覆盖看板无法维护 | 增加覆盖率状态设置接口与看板操作 |
