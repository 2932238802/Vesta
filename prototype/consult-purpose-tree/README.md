# 咨询树 · 原型与生成器

这个目录保留为生成器和离线预览。它做两件事：

> 把成交逐字稿拆成“目的动作 + 情绪蝴蝶 + 原文示例组”，按旺季 / 淡季组织成模板，并生成后台「咨询树」读取的数据文件。

后台已经接入只读页面「咨询树」，统一提供模板切换、列表和思维导图。生成器会同时写出 `shared/src/consult-purpose-data.json`，后端只读该文件，不写数据库。

**没有写数据库，没有改现有咨询树，没有改 SKILL，也没有部署。**

## 怎么看

直接用浏览器打开：

```
prototype/consult-purpose-tree/preview.html
```

不需要启动服务，页面里已经嵌入了全部数据。

页面上可以：

- 点任意目的节点，右侧看它的目的概括、分支条件、导演提示和原文示例；
- 点 🦋 蝴蝶节点，看挂在某个目的上的情绪/过渡垫话；
- 切换「显示蝴蝶」和「只看主线」；
- 搜索目的、示例原文、标签；
- 全部展开 / 全部收起。

## 怎么重新生成

修改 `tree-definition.mjs` 后，在项目根目录运行：

```bash
node prototype/consult-purpose-tree/generate.mjs
```

会重新生成：

- `output.json`：解析后的完整结构，方便后续接数据模型；
- `preview.html`：可离线打开的静态预览页；
- `shared/src/consult-purpose-data.json`：后台「咨询目的树」页面读取的正式数据文件。

生成器读取 `zxg/七月咨询稿.docx` 和 `sources.mjs` 里登记的所有逐字稿，通过 `scripts/import-consult-docx.mjs --list` 拿到与导入脚本一致的段号/轮次，再把原文填进示例组。

## 模板与多篇稿子

模板按季节分（旺季 / 淡季），不按单篇稿子分。数据文件的结构是：

```text
meta.activeTemplateId
templates[]: { id, name, season, description, source, stats, tree }
```

当前只有一套：

- `peak` · 旺季骨架 · 定义稿 `zxg/七月咨询稿.docx`

其他同季节的成交稿不新建模板，而是作为“来源”并入同一套骨架：

- `sources.mjs`：每篇稿子一个来源，写清楚文件、季节和“哪几轮 → 哪个目的”的映射；
- 生成器把映射片段挂到对应目的节点的 `examples` 上；
- 同一目的可以积累多篇稿子的说法，学生原话保留；
- 如果某段话做的是现有目的没覆盖的事，先在 `tree-definition.mjs` 补目的节点，再补映射。

9.18 吕新蕊稿是旺季稿，已作为 `918` 来源并入旺季骨架；9.19 的胡余敏、马术菊、黄嘉慧三篇稿子分别作为 `919a` / `919b` / `919c` 并入同一套骨架。淡季稿到了再建 `off` 模板。

### 新增一篇同季节的稿子

1. 在 `sources.mjs` 加来源（id / label / file / season / parser）；
2. 用 `node scripts/import-consult-docx.mjs <docx> --list` 看轮次；如果一份 docx 拼了多段录音，导入脚本会按时间戳回退分段，并逐段识别咨询师；
3. 把有效片段写成 `{ purposeKey, from, to, note }` 映射，设备调试、闲聊、重复确认不要映射；
4. 运行 `node prototype/consult-purpose-tree/generate.mjs`。

### 新增一套模板

1. 写 `tree-definition-<season>.mjs`，导出 `meta`（id / name / season / description）和 `tree`；
2. 在 `templates.mjs` 里 import 并加入 `templates` 数组；
3. 运行生成器。

后台的模板切换会自动出现新模板，不需要改前端。

## 当前拆出来的规模

- 6 个阶段
- 90 个目的动作（其中 26 个可选支线，4 个空缺主题）
- 18 个情绪蝴蝶
- 194 组原文示例，1746 条话轮
- 承接后补齐 5 个收尾分支（价格、家长、犹豫、报名、课后跟进）

七月稿的 438 段咨询师话术，被收敛到 90 个目的节点。9.18 吕新蕊稿映射 29 组片段；9.19 胡余敏、马术菊、黄嘉慧三篇稿子分别映射 16 / 27 / 32 组。所有来源稿的片段都挂到相同目的上，剩余片段是设备调试、闲聊、重复确认，以及暂时没有对应目的的内容（考研动机、竞争对手分析、考研四科、专业能力路径、专业细分岗位、大学生三类人、报班决策等），后续继续补节点和映射。

## 这次特意分开处理的四类内容

七月稿里其实混了四种东西，原型里分开存：

| 类型 | 例子 | 原型里放哪 |
|---|---|---|
| 咨询师话术 | “你是不是担心开学第一周……” | `examples[].turns` |
| 学生回答 | 9.18 稿里的“对”“我觉得……” | `examples[].turns`，role 为 student |
| 阶段/目的标题 | “引出内心最恐惧的” | 节点 `label` / `summary` |
| 导演提示、分支条件 | “一定要等她回答”“如果她说我打算自学” | `notes` / `branchCondition` |

示例永远是原文，AI 不改写。节点标题和概括是人工整理的“目的”，不是系统自拟话术。

## 看的时候重点判断什么

1. **粒度**：90 个目的动作是太细、太粗，还是刚好？比如“社交/社恐”下面拆成“引出恐惧 → 说出渴望 → 给新解释”，是否合适。
2. **命名**：节点标题是否一眼能看懂“这一步要达成什么”，而不是在复述原文。
3. **蝴蝶位置**：情绪垫挂在目的节点上是否自然？哪些其实应该算主线，哪些还漏了。
4. **可选支线**：9 个担忧话题作为“可选支线”挂在“选择她最在意的担忧”下面，是否符合真实咨询的感觉。
5. **空缺**：班委、分班、学生会、入团入党四个只有标题，页面上是否应该这样明确显示“待补充”。
6. **跨稿示例**：9.18 / 9.19 稿的片段挂到七月稿的目的上，是否能看出“同一个目的、不同说法”的价值。

## 两处结构判断

1. **9.18 稿的主线更偏“就业导向”。** 它的路径是就业难 → 以终为始 / 简历差距 → 四条就业赛道 → 竞赛与项目 → 英语差异化 → 课程承接。现在作为旺季树里的可选支线并入：共享“建立信任、摸底、能力标准、英语、承接”等目的，就业主线挂在 `window.job`、`filter.track`、`filter.competition` 下，收尾挂在 `offer.handoff` 的子分支下，不另建一棵树。
2. **七月稿的 9 个担忧是“可选模块”，不是一条直线。** 原型用 `optional: true` 表示：结构上仍是一棵严格树，但路径可以跳过这些支线。这样既保留严格树，又不会把 9 个话题硬串成一条链。

## 文件

- `templates.mjs`：模板注册表（新增模板从这里登记）
- `sources.mjs`：其他成交稿的来源与目的映射（新增稿件从这里接入）
- `tree-definition.mjs`：旺季骨架的人工拆分（要改粒度/命名就改这里）
- `generate.mjs`：解析 docx、填充示例、生成 JSON 和 HTML
- `preview.template.html`：静态预览页模板（生成器用，不直接打开）
- `output.json`：生成结果
- `preview.html`：直接打开看的页面
